ADR-001 · Public name; physical-path proposal superseded

The original decision proposed “Briarwake name and Source/Briarwake paths supersede tentative RPG naming.” That is preserved as historical input in the decision registry, not an instruction or evidence that a rename occurred. Briarwake branding remains correct; ADR-011 supersedes only the physical-path assumption.

ADR-011 · Original game in the existing RPG project

Briarwake is an original 2D pixel-art fantasy MMORPG being developed from the ground up in Unreal Engine 5.8.3. The existing Briarwake Unreal repository is the development starting point. No previous game implementation, port or conversion is required. Earlier game_docs material is optional historical and engineering reference. Each phase introduces or extends Briarwake’s own systems; planned contracts are not runtime evidence.

Briarwake is the public game name; RPG is the verified physical project and runtime module identifier. Open RPG.uproject and use Source/RPG/RPG.Build.cs, Source/RPG.Target.cs and Source/RPGEditor.Target.cs. Keep Content/Game/, existing classes, targets and configured assets intact. Do not create a second project or require a rename.

Verified at Briarwake/main 89231883e1e124cda9db65aa0feaa7febdc8f4cb on 13 October 2026. The descriptor identifies 5.8; installed 5.8.3, builds and gameplay remain unverified. The stable asset key Briarwake and assets/Core/Briarwake.html refer to RPG without renaming any native class or dependency ID. 13 October 2026 read-only project inspection

Earlier local-save, side-view and empty-project examples in historical engineering guidance do not establish current gameplay prerequisites. Preserve engineering practices and the game checkout’s class-creation/Git workflow; use this guide’s own authoritative multiplayer and top-down design.

ADR-002 · Slice B moves to Phase 19

The source schedules Slice B after Phase 18 but requires the cartography route implemented in Phase 19. This guide places the Slice B acceptance checkpoint after Phase 19. It does not silently move or delete Wayfinder content. All roadmap/slice references use the revised checkpoint.

ADR-003 · Minimal services before full systems

Slice B also requires a merchant and contribution board before the full Phase 25 economy and Phase 22/23 region work. Phase 13 introduces only baseline fixed NPC supply/repair/commission services through the existing durable command path. Phase 15 introduces the minimal durable region/project schema and board needed by the Forgekeeper repair outcome. Later phases extend those exact owners/IDs instead of creating second implementations.

ADR-004 · Early combat fixture, later specialization

Phase 09 uses a minimal basic melee/ranged ability fixture. Phase 12 supplies the full discipline/talent data and purchase UI. Do not require a not-yet-created specialization definition merely to prove one server-authorized dummy hit.

ADR-005 · Incomplete input gates stay visible

Neither source archive was accessible. The art and plugin audit pages record brief-reported leads and exact next verification steps, but they do not invent archive paths, line numbers, dimensions or compilation results. The register is provisional and non-exhaustive until those audits and detailed content authoring are complete.

Preserved requirements

All five vocations, six biome families, the 32 phase numbers, 15 worked-scenario requirements and the solo-to-30 contract remain in scope. No requirement is deleted merely because this is a partial delivery. Use the source coverage register to identify the outstanding work.
