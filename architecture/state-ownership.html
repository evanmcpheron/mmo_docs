Definitions are not player state

A definition describes permitted data: a recipe, item, vocation or authored region stage. It may be loaded by many actors and clients. A runtime instance describes what is currently happening. A durable record describes what must survive restart. A projection is a limited copy used by an actor or interface; displaying it does not make that viewer the writer.

Initialization order

  1. Authenticate and resolve the account/character without trusting client-supplied ownership.
  2. Reserve or validate a current lease, verify content/schema compatibility and read durable records.
  3. Create the server body and initialize components/ability owner-avatar references.
  4. Publish public/owner-only snapshots. Bind local view listeners then pull state; accept only newer revisions.
  5. Enable commands only after hydration. On death/travel, cancel old actions, unbind observers and fence or release ownership as appropriate.

Visibility is not authority

A replicated value may be public without being client-editable. A BlueprintCallable method may only submit a request. Each command validates ownership, permissions and current lease on the server and at the durable write boundary. Cosmetic animation and UI events signal or display a completed change; they cannot create it.
