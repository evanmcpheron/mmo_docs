Original game, existing project

Briarwake is an original 2D pixel-art fantasy MMORPG being developed from the ground up in Unreal Engine 5.8.3. The existing Briarwake Unreal repository is the development starting point. No previous game implementation, port or conversion is required. Earlier game_docs material is optional historical and engineering reference. Each phase introduces or extends Briarwake’s own systems; planned contracts are not runtime evidence.

Briarwake is the public game name; RPG is the verified physical project and runtime module identifier. Open RPG.uproject and use Source/RPG/RPG.Build.cs, Source/RPG.Target.cs and Source/RPGEditor.Target.cs. Keep Content/Game/, existing classes, targets and configured assets intact. Do not create a second project or require a rename.

Current source baseline: 13 October 2026 read-only project inspection. Read ADR-011; the historical guide is not a prerequisite.

Open and navigate

  1. Extract the entire ZIP to a normal local folder. Open index.html directly in a desktop browser; keep site/, assets/, systems/, phases/ and sources/ together.
  2. Read the evidence/status panel before beginning Phase 00. Search works from a generated local JavaScript index and does not require a web server.
  3. Open the roadmap, begin Phase 00, and perform authorized implementation in the existing Briarwake game checkout—not inside mmo_docs and not in a second Unreal project.
  4. Capture actual Editor/build/runtime logs and observations on the development machine. Checklists track your local progress only; they do not change the shipped verification record.

Resolve the current blockers

The original documentation edition lacked the art/plugin ZIPs and companion audits and reported repository access failures. Those dated findings remain evidence for that edition, not proof that the current game project is absent. Exact source archives, installed engine, plugins, compiler and Blueprint graphs were not available for this documentation correction either.

The requested target is Unreal Engine 5.8.3. Official mechanism pages in the 5.8 documentation family were consulted, but no installed 5.8.3 source, PaperZD binary, plugin archive or compiler was available.

Physical folders versus Unreal object paths

Content/Game/Maps/L_ThornmereVillage.umap is a planned map file, not an existing map claim. Its Unreal package path is /Game/Game/Maps/L_ThornmereVillage because /Game maps to Content/. Current startup configuration instead references /Game/Game/World/Levels/Test_Level.Test_Level; preserve it while recording the baseline.

New native implementation contracts use Source/RPG/Public/<Domain>/ and matching Private/<Domain>/ locations in the existing RPG module. These proposed folders do not imply that each type already exists. Existing Private/Core/RPGGameMode.h and RPGGameInstance.h stay in place; never move or rename them to match a planned page name.

Completion is a separate gate

The default checks verify the delivered partial package is internally accounted for. python tools/check_feature_coverage.py --require-complete intentionally fails while implementation-detail coverage or required input audits are incomplete. Passing local HTML checks does not pass the game’s phase acceptance tests.
