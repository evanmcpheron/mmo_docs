Implementation scope

  • Extend the same tools/check_runtime_fixtures.py with --suite all, joining evidence/context/diagnostics/metrics from fresh isolated native test runs. Reuse each suite verifier and immutable inputs rather than maintaining a second result calculation. Link exact scenario/source/toolchain/content/rules/owner identities, actual assertions, same-context comparisons, redacted sample and raw measurement outputs in one attributable manifest.
  • Execute two independent complete runs with clean transient worlds, covering accepted/rejected/retried probe actions, seed/context replay, sentinel redaction and the two-logical-recipient burst/drain workload. Add aggregate assertion-failure, missing-report, load-failure and startup-failure controls and a clean recovery. Stale/partial/foreign child artifacts cannot satisfy the aggregate.
  • Rerun the BW-001 native build/client/dedicated-server smoke and package-isolation checks and BW-002 admission/compatibility regressions using their actual implemented documented commands. Add and document the one-command aggregate/reset route in the tracked game repository. Keep fixture controls and data outside normal packaged gameplay and retain evidence in fresh outputs.
  • Review the parent epic against its four exact ACs, BW-001/BW-002 prerequisite completion and applicability, every child ticket and dependent readiness. Explicitly retain the approved local-probe/payload-byte scope and remaining connectivity/gameplay/durability/capacity limitations. Update progress only from applicable executed native evidence and regenerate all current roadmap/inventory views; documentation/schema checks never complete a runtime gate.

Out of scope

  • Implementing or completing BW-004 connectivity, BW-012 multiplayer action, BW-018 durability, BW-095 authoring or BW-097 camera/visual work.
  • Deployment, production operations dashboards or reusing historical Godot results as Unreal evidence.

Dependencies

Hard prerequisites: BW-003-T03, BW-003-T04

Acceptance criteria

  1. AC 1

    The documented aggregate command actually executes all required child suites and links complete matching current evidence. Missing, stale, partial, failed or foreign child reports make it fail distinctly from native build/load/startup failure.

  2. AC 2

    Two independent complete native runs reproduce deterministic probe outcomes and contain actual correlated actions, successful redaction assertions and raw workload/environment-linked timing, entity, recipient-byte and queue measurements.

  3. AC 3

    Aggregate failure controls return nonzero; subsequent clean recovery passes in a fresh output without overwriting any prior evidence. Existing BW-001/BW-002 checks and normal client/server package isolation still pass.

  4. AC 4

    The parent review maps all four BW-003 criteria to actual retained artifacts, verifies hard prerequisites and children and records the approved evidence boundary before any completion/status change. Later game/network/persistence epics retain their independent status.

  1. Both clean aggregates pass using current native execution evidence; all controls fail distinctly and clean recovery passes. No previous artifact is silently reused.
