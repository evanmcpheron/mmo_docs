Complete · Parent epic: BW-003 · Repeatable runtime fixtures and diagnostics

Epic acceptance criteria: BW-003-AC-1, BW-003-AC-2, BW-003-AC-3, BW-003-AC-4

Implementation scope

  • Extend the same tools/check_runtime_fixtures.py with --suite all, joining evidence/context/diagnostics/metrics from fresh isolated native test runs. Reuse each suite verifier and immutable inputs rather than maintaining a second result calculation. Link exact scenario/source/toolchain/content/rules/owner identities, actual assertions, same-context comparisons, redacted sample and raw measurement outputs in one attributable manifest.
  • Execute two independent complete runs with clean transient worlds, covering accepted/rejected/retried probe actions, seed/context replay, sentinel redaction and the two-logical-recipient burst/drain workload. Consume the already-integrated T01 evidence assertion/missing-report/load/startup/timeout controls and recovery at matching inputs. Add aggregate controls only for new cross-suite risks: omitted/failed child, stale/foreign context and partial report acceptance. Reuse existing control implementations for aggregate dispatch; do not duplicate the completed evidence suite or every prerequisite failure-control run.
  • Extend the existing tools/validate.py FULL plan, which already runs T01 evidence and its five failure controls, with --suite all and only the new aggregate recovery/negative cases, preserving its seven prerequisite tests, report checks, Editor/Game/source-Server build/package/smoke checks and package isolation. Reuse unchanged passing evidence within the same exact native input/toolchain scope rather than adding a parallel regression chain. Document python3 tools/validate.py as the final complete validation route and tools/check_runtime_fixtures.py --suite all as the focused fixture route. Add only required suite dispatch/report expectations to the existing wrappers; retain actual fixture controls/data exclusion from normal artifacts and fresh bounded outputs in the existing checkout.
  • Review the parent epic against its four exact ACs, BW-001/BW-002 prerequisite completion and applicability, every child ticket and dependent readiness. Explicitly retain the approved local-probe/payload-byte scope and remaining connectivity/gameplay/durability/capacity limitations. Update progress only from applicable executed native evidence and regenerate all current roadmap/inventory views; documentation/schema checks never complete a runtime gate.

Out of scope

  • Implementing or completing BW-004 connectivity, BW-012 multiplayer action, BW-018 durability, BW-095 authoring or BW-097 camera/visual work.
  • Deployment, production operations dashboards or reusing historical Godot results as Unreal evidence.

Dependencies

Hard prerequisites: BW-003-T03, BW-003-T04

Acceptance criteria

  1. AC 1

    The documented aggregate command actually executes all required child suites and links complete matching current evidence. Missing, stale, partial, failed or foreign child reports make it fail distinctly from native build/load/startup failure.

  2. AC 2

    Two independent complete native runs reproduce deterministic probe outcomes and contain actual correlated actions, successful redaction assertions and raw workload/environment-linked timing, entity, recipient-byte and queue measurements.

  3. AC 3

    New aggregate failure cases return nonzero with attributable child/context evidence; existing T01 stage controls remain covered without duplicate implementations; clean recovery passes in a fresh output without overwriting prior evidence. The default python3 tools/validate.py actually includes the fixture aggregate and preserves all existing BW-001/BW-002 gates and normal Game/Server package isolation. No project copy, cache deletion, omitted test or independent duplicate admission implementation is required.

  4. AC 4

    The parent review maps all four BW-003 criteria to actual retained artifacts, verifies hard prerequisites and children and records the approved evidence boundary before any completion/status change. Later game/network/persistence epics retain their independent status.

Manual verification

Run from the Briarwake implementation repository. The commands, test worlds and fixtures below are deliverables of this ticket and its prerequisites; these are unexecuted test instructions.

Setup

  1. Use the existing GAME_ROOT and DOCS_ROOT=GAME_ROOT/mmo_docs checkouts. Task bases: game origin/main 9804d8a08cc45b712dd3582adac5d901119c30f8; docs origin/main 3f0fa19aead31265032ad48a99fd3c9927aaa4d7. Preserve existing outputs and build directories; no worktree, clone, project copy or cache deletion.
  2. Pinned macOS ARM64 Development, installed UE 5.8.3 CL 58210709, source Server engine commit 396c9f059903aed5fec78ecd3d437a40c6415368 with the approved lock-file patch, Xcode 27.0 build 27A266a and Apple M2 Max. tools/toolchain.lock.json and each run environment own the exact identities.
  3. The four existing Briarwake.RuntimeFixtures automation tests create/destroy transient UWorlds under WITH_EDITOR && WITH_DEV_AUTOMATION_TESTS. No map, asset, reflection, gameplay RPC or interactive editor/MCP change is required. The existing canonical FContentContracts/FContentAdmission/FRuntimeFixtureEvidence/FRuntimeFixtureContext owners remain unchanged.
  4. Build first. Each aggregate dispatches fresh evidence/context/diagnostics/metrics processes and then reuses their existing verifiers. manifest.json binds relative child artifact paths, SHA-256, nonces, exact source/module/input/toolchain identities, actual assertion counts and deterministic outcomes. Native Unicode JSON is decoded from bytes; payload measurements retain their separate UTF-8 policy.

Actions

  1. Run the launch block in two fresh outputs. Inspect manifest.json and run.json, every child native/automation report, the diagnostic shareable-sample.json and metrics recomputed-metrics.json. The second aggregate must reverify the first and require distinct child nonces plus deterministic replay equality; processing durations and volatile run/scenario/action IDs are excluded from equality.
  2. Run --suite all --control omitted-child, failed-child, stale-context, foreign-context and partial-report separately, each with --prior-run artifacts/fixture-first and a fresh output. Reuse a matching existing T01 assertion control with --failed-child PATH if available; otherwise failed-child invokes the existing T01 control once. Inspect the exact failure_category/control_detection and nonzero exit; missing tools cannot satisfy controls.
  3. Run python3 tools/validate.py. FULL runs the original seven-test prerequisite aggregate and its controls, compiler rejection/recovery before the first fixture aggregate, all T01-T04 controls, new aggregate controls using exact matching retained child evidence, and a fresh four-suite aggregate recovery with replay comparison. Game/source-Server build/package/smoke and decoded/loose artifact/control exclusion still run.
  4. Attempt reuse of an existing --output and compare all prior file hashes. Reverify disposable copies with omitted, changed or missing child artifacts and inspect explicit rejection. Review all four parent criteria, every child and hard prerequisite against actual retained artifacts before completion; then regenerate and inspect dashboard, foundations, milestones, epic/ticket pages, dependent readiness, inventory, search and navigation.

Expected results

  1. Both complete aggregates pass only after all four native verifiers pass at matching identities. Native lifecycle/assertions, immutable authored specifications, correlated accepted/rejected/retried actions, seeded replay/reset, sentinel redaction and raw timing/entity/unequal-logical-recipient-byte/FIFO measurements remain attributable.
  2. All aggregate controls return nonzero with their specific rejection and actual source/child/context evidence. Existing T01 stage controls remain independent actual executions; clean recovery succeeds and prior evidence stays unchanged. Default FULL preserves BW-001/BW-002 and normal Game/Server package exclusion.
  3. This is the approved finite local probe with logical recipients and serialized payload bytes. Connected clients, wire traffic, production gameplay, database durability and launch capacity are not certified. Later epics retain independent implementation status.

Reset

  1. Allow each child to destroy/GC its transient world. Existing timeout control terminates/reaps its owned process group. Context reset clears clock/seed/queue/probe and measurement state; no gameplay control handler exists in normal packages.
  2. Keep prior outputs and use new names under GAME_ROOT/artifacts. Never overwrite reports, resave maps/assets, remove caches or modify canonical specifications to reset a run. Documentation evidence is retained separately under DOCS_ROOT/validation/tickets/BW-003-T05.
