Complete · Parent epic: BW-003 · Repeatable runtime fixtures and diagnostics

Epic acceptance criteria: BW-003-AC-4

Implementation scope

  • Instrument the actual T02 finite processing loop and queue: elapsed processing duration per probe tick from a monotonic clock, test-relevant entity count, consumed FIFO depth before/after drain and actual serialized payload bytes per logical recipient. Use two recipients with unequal payloads, a burst/drain workload and empty/no-recipient controls. Do not derive backlog from requested input count or fabricate timing samples.
  • The owner selected the bounded local probe on 2026-10-21. Label every byte value as serialized payload bytes for a logical test recipient; exclude transport headers, retransmission, compression and socket traffic. Record exact encoding/measurement windows, recipient IDs, payload hashes/lengths, raw samples and summary policy. Ticks are probe processing ticks, not a claim to measure a production server simulation. Record workload/seed/context/configuration and actual engine/compiler/platform/CPU/OS/environment identity alongside the observations.
  • Link ServerMetricRecord and its Id/Instant/Count contracts as the production reference, preserving finite/nonnegative values and field meanings where reused. That record requires database latency and economic counters and declares durable-service authority; no database/service exists here. Use explicitly labeled test evidence rather than a partial ServerMetricRecord, fabricated database zeroes or NetworkLoadTestRecord. Reuse BW-001 revision/toolchain metadata and FServerConfiguration only if actually consumed; FContentContracts and FContentRevisions already own BW-002 shape/compatibility checks. Do not invent unused snapshot/disconnect settings.
  • Add a metrics suite with retained raw samples, an independent payload-length/queue/summary verifier and invalid/nonfinite/missing-sample/report-tampering controls. Use TestCheck for measurement assertions. Keep sample/workload bounds explicit and enforce them; no launch capacity or performance pass threshold is inferred.
  • Keep the existing owner-selected logical-recipient/payload measurement boundary. Later BW-013 scheduling and BW-083 connected workload tickets reuse report/measurement facilities where applicable but must measure their real transport independently; no second general metrics framework or fabricated wire-byte equivalence is needed.

Out of scope

  • Connected clients, wire-network measurement, production replication, database/persistence, economy settlement and large-scale load testing.
  • Canonical metric/schema changes, synthetic values for unmeasured systems, benchmark budgets or an MMO capacity certification.

Dependencies

Hard prerequisites: BW-003-T02

Acceptance criteria

  1. AC 1

    One bounded run records real per-tick processing durations, test-relevant entities, per-recipient serialized bytes and observed FIFO depth with reproducible workload/context and actual environment metadata. The burst demonstrably drains and reset clears test-owned state.

  2. AC 2

    Independent recomputation matches serialized bytes for each of two unequal recipients, queue observations and summaries from raw samples. Empty windows/no recipients have explicit semantics and never divide by zero or mislabel an absent measurement as a measured success.

  3. AC 3

    Negative/nonfinite durations or counters, excessive workload bounds, missing samples/metadata and tampered totals are rejected. Every report/sample prominently labels the local probe/payload-byte limitation and makes no wire/database/capacity claim.

  2. Pinned native host: UE 5.8.3 Launcher CL 58210709, patched source engine commit 396c9f059903aed5fec78ecd3d437a40c6415368, Xcode 27.0 build 27A266a, macOS ARM64 Development. FServerConfiguration and FContentRevisions supply only consumed content/rules labels; unrelated scheduling/disconnect settings do not drive this probe. Actions

  1. Run the launch commands. The metrics suite creates a transient UWorld and executes the exact Briarwake.RuntimeFixtures.Metrics test. Inspect run.json, native/fixture-metrics.json, automation/index.json and recomputed-metrics.json; parse the native JSON from bytes because Unreal may use UTF-16 with BOM. The payload text itself is measured as UTF-8 without BOM/terminator/extra newline.
  2. Inspect burst, empty, no-recipients and replay windows. Five t=0 submissions fill the four-entry FIFO and reject the fifth; t=0.5 preserves the backlog, t=1 drains four effects and t=2 observes it empty. Every tick records actual monotonic start/end, duration, entity count, queue before/after drain/after step, kind/fixture offset, exact logical-recipient payload text/length/SHA-1. The second recipient ID includes Unicode and its projection includes the decision, producing unequal byte lengths.
  3. Recompute payload lengths/hashes/content, FIFO transitions, mean/maximum elapsed milliseconds, maximum queue depth and byte sums per logical recipient from raw samples. Empty windows have no samples and null duration statistics; no-recipient windows still time real processing but have empty payload lists/maps. Inspect actual engine/compiler/CPU/OS/configuration plus context/revisions and runner/source identities.
  4. Both explicit controls execute passing native metrics and then corrupt only an in-memory copy. Require nonzero exit, control_verified=true and the specific invalid-number or summary-mismatch detection. Inspect verification_checks for actual missing/nonfinite/negative/incorrect-type/excessive-bound/tampered-output rejection. Finish with a fresh clean metrics run and default native FULL; check package marker/input exclusion and prerequisite regressions.

Expected results

  1. Actual raw observations support both unequal logical recipients, the observed burst/drain queue and summaries. Timing is per finite probe processing step and includes payload serialization/hashing, excluding report capture. Reports state the local-probe/serialized-payload boundary; no wire/database/capacity result is inferred.
  2. Native invalid-workload/recipient controls reject before mutation, reset clears pending work/clock/random/recipients/samples/enabled state, and seeded replay preserves rule outcomes. Explicit verifier controls fail for their intended corruption, unavailable tools never satisfy them, and fresh recovery passes.

Reset

  1. Let each native run destroy and garbage-collect its owned transient UWorld. Probe Reset clears all test-owned state; it does not alter canonical inputs or assets. The wrapper bounds child processes and terminates timed-out owned groups.
  2. Default runs choose fresh output directories and refuse existing outputs. Preserve all earlier reports, logs, packages, user edits and caches. Retain relevant raw reports and compressed logs under DOCS_ROOT/validation/tickets/BW-003-T04 for auditable evidence.
