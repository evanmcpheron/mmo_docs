Epic acceptance criteria: BW-097-AC-4

Implementation scope

  • Extend the probe with --case outlines, using T01 measured buffers and T04 camera. Implement candidate silhouette detection, separately controlled convex-edge highlights and toon material/lighting on T03 character/terrain assets. Adapt depth conventions, normal space, orthographic reconstruction, integer texel sampling and alpha composition explicitly; Roystan’s Unity technique and SMAA choice are references, not untested defaults.
  • Supply near/far and clipping-boundary placements, grazing/sloped terrain, thin geometry, touching/overlapping characters, concave versus convex edges and bright/dark material swatches. Include raw depth/normal, silhouette-only, highlights-only, combined and antialiasing comparison controls plus one-internal-pixel measurement overlays.
  • Select lighting bands, value separation, outline/highlight colors and antialiasing through T03 review. Keep shader/material configuration local to the probe: no canonical gameplay type defines these visual parameters and no renderer change may alter domain authority.

Out of scope

  • Full art production, all character forms, final world lighting/environment presets or unproven engine modifications.

Dependencies

Hard prerequisites: BW-097-T04

Acceptance criteria

  1. AC 1

    Measured silhouettes are one pixel wide at internal resolution across the representative distance/geometry matrix. Convex highlights are independently selected and controlled; ordinary normal discontinuities do not automatically become highlights.

  2. AC 2

    Near/far clipping, grazing surfaces, thin geometry and overlapping actors show no filled surfaces or distracting false edges beyond approved bounds. Captures and motion sequences cover each case and selected antialiasing configuration.

  3. AC 3

    Toon lighting preserves approved gameplay-scale silhouette and palette/value separation on the character and terrain. Rejected candidates and any approved deviation remain linked to the visual baseline and exact settings.

Manual verification

Run from the Briarwake implementation repository. The commands, scenes and fixtures below are deliverables of this ticket and its prerequisites; these are unexecuted test instructions.

Launch command or scene

Working directory: GAME_ROOT (briarwake/). Verify local Titan exports at artifacts/titan-export-work/exports/manifest.json; if absent, use the existing python3 tools/export_titan_reference.py workflow with the owner-provided source assets. Run python3 tools/verify_toolchain.py, then python3 tools/run_rendering_probe.py --case outlines. Add --interactive for controls; --output must name a fresh launcher-owned directory. Open the resulting review.html for still/motion comparisons. res:// paths resolve under GAME_ROOT.

Setup

  1. Pinned Godot 4.7.2 / Forward+ / measured desktop device. The launcher validates exact source export hashes, canonical evidence definitions and bounded settings, creates an isolated project and imports/checks it before graphical execution.
  2. The case supplies 13 geometry/clipping fixtures, imported T03 courtyard/terrain, independent source/toon and outline/highlight controls, 88 still settings and 74 lossless 32-frame sequences at 30Hz. Internal 384x216 plus T04 guard; normal/close zooms; day/warm/cool; no-AA/FXAA.

Actions

  1. Run the full case. Inspect run.json checks/measurements, raw/reconstructed depth, view normals, independent coverage and separate silhouette/highlight masks. Compare near/middle/far, clipping, grazing, thin, convex/concave/flat normal seam, touching/overlap and bright/dark swatches.
  2. Use review.html to select geometry, zoom, light and antialiasing. Enable the one-internal-pixel grid/character bounds. Compare PBR/source with selected diagnostic/combined. Examine disabled/FXAA variants; no SMAA capability is claimed.
  3. Play and step all selected-AA sequences: geometry diagonal paths at both zooms, courtyard stationary/slow-axis/diagonal/actor-only paths at both zooms in all lighting states. Inspect rigid edges for crawl/width pumping, character part separation and concave/flat false highlights. Loop wrap is a restart, not a continuity claim.
  4. In the interactive case, toggle Toon, Silhouettes and Convex highlights independently, select raw buffers/fixtures/path/zoom/light/AA, play/pause/step/capture, then Reset. Record project-owner decisions for current colors/bands/no-AA and any deviation against T03 approved bounds.
  5. Run python3 -m unittest discover -s tools -p 'test_*probe.py' -v. Run --control invalid-settings and confirm rejection before graphical launch. Missing-report and deliberate-failure controls must fail without fabricated pass evidence.

Expected results

  1. Selected no-AA exterior silhouettes measure one cardinal texel. Thin foreground geometry remains visible; measured overlap/clipped-side depth edges require visual acceptance. Convex highlights reject flat normal seams, concavity and ordinary slopes and remain independently controllable.
  2. Every matrix combination and consecutive frame is retained and attributable. Stationary masks are exactly identical. Toon preserves gameplay-scale character/terrain readability subject to explicit project-owner review; automated checks and T03 approval do not approve new visual choices.
  3. Invalid evidence/settings, missing reports, incomplete matrices and explicit failure remain observable failures; no gameplay authority or source asset mutation occurs.

Reset

  1. Reset restores courtyard/day/normal zoom/toon/both edges/no AA/frame zero, then quit normally. No persistent gameplay state is created.
  2. Keep prior runs and failures. Repeat into a fresh output directory. Do not modify canonical definitions, source assets, retained evidence or unrelated files to obtain a pass.
