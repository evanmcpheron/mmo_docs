Objective and scope

Produce attributable runtime evidence from the first experiments.

Scope: Pinned fixture world/time/content context, bounded test control, action-correlated diagnostics and baseline tick/traffic/queue measurements; no claim of launch capacity. Owner-selected 2026-10-21 boundary: a finite native test-only local probe with logical recipients and explicitly labeled serialized payload bytes; no connected-client, wire-traffic, database or production-gameplay certification.

Acceptance criteria

  1. AC 1

    Executed fixtures record scenario revisions, runner, result and assertions separately from unexecuted specifications.

  2. AC 2

    The same seeded fixture context reproduces observable rule outcomes; test-only control cannot be invoked through gameplay commands.

  3. AC 3

    Diagnostics connect rejected commands and committed actions to build/content/owner revisions without exposing secrets.

  4. AC 4

    A test run captures tick duration, relevant entities, bytes per client and queue depth, including its workload and environment.

Verification and blockers

Completion evidence required: Actual fixture run records and a redacted diagnostic/measurement sample.

Recorded evidence: None. Required evidence above describes future verification.

Blockers: None recorded; see hard prerequisites.
