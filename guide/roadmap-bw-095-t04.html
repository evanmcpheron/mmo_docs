Complete · Parent epic: BW-095 · Versioned content authoring and import workflow

Epic acceptance criteria: BW-095-AC-1, BW-095-AC-2

Implementation scope

  • Extend the existing canonical extraction/admission owners for NpcAbilityKit, NpcDefinition, LootTableDefinition, EncounterDefinition and EncounterTriggerDefinition, including their finite NpcAbilityRule/EncounterCondition/loot parameter closure. These top-level families currently lack native admission support. Import/export one bounded linked example through T01; reuse ability readiness, typed operations and economic admission rather than adding an NPC scripting system.
  • Validate exact ability/kit/loot/encounter/trigger references, kit scheduling rules referencing listed abilities, finite conditions, positive activation limits, cooldown/cap bounds, enclosing phase ownership and declared reset policy. Validate loot policy parameters against entry count, nonempty weighted_one_v1 tables, explicit weights/probabilities and item references. Never infer rates from rarity or accept an arbitrary function name as a condition implementation.
  • Stage the complete linked set so forward references work and one invalid member rejects the whole candidate. A server-owned dependency identity alone cannot prove a relationship requiring full records. Preserve server-only loot and scheduling data for T06 projection; a valid catalog does not run AI, rewards, triggers or reset. Use existing native tests for a valid linked set and broken kit ability, loot parameters, phase reference and trigger limit.

Out of scope

  • AI/pathfinding, encounters or loot delivery at runtime, production encounters/maps, new balance values, durable reward/idempotency implementation and connected multiplayer.

Dependencies

Hard prerequisites: BW-095-T01

Acceptance criteria

  1. AC 1

    Representative records from all five named families round-trip through source/export/native admission with stable IDs/revisions and validated complete links, including forward references.

  2. AC 2

    A missing kit/ability/item/trigger reference, invalid loot policy parameter set, foreign phase, nonpositive trigger limit or unsupported finite policy returns an actionable record/field finding; no part of that candidate publishes.

  3. AC 3

    Server-only definitions retain their privacy classification. Valid authored scheduling, effects and loot never bypass runtime readiness or create gameplay execution evidence.
