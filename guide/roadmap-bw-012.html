Phase: 2. First authoritative multiplayer interaction · Completion milestone: Two-client authoritative action

Objective and scope

Demonstrate the smallest integrated movement-and-action loop before a full game journey.

Scope: Two test clients, one controlled target, authoritative direct action and visible rejection; temporary non-economic state is sufficient. Excludes adjacent gameplay families and production certification beyond this epic’s stated acceptance criteria.

Acceptance criteria

  1. AC 1

    Two clients move, select an eligible target and observe the same accepted cast and resulting health change from one authoritative action.

  2. AC 2

    A forged hit, position or private-state request fails without changing authoritative state or revealing hidden data.

  3. AC 3

    A late observer receives current health/cast state and packet loss followed by a baseline leaves neither client permanently stale.

  4. AC 4

    The run records action latency, tick/traffic observations and a clear client failure reason; it claims no persistent economy or complete beginner experience.

Verification and blockers

Completion evidence required: An executed two-client scenario with correlated server/client traces and captured feedback.

Recorded evidence: None. Required evidence above describes future verification.

Blockers: None recorded; see hard prerequisites.
