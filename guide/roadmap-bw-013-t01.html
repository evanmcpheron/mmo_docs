Epic acceptance criteria: BW-013-AC-1, BW-013-AC-2, BW-013-AC-5

Implementation scope

  • Extend BW-007 public/owner projection and native per-connection Actor relevancy/conditions; BW-009 target queries consume the same eligibility/disclosure decision.
  • Add floor/instance/spatial and hidden-state authorization with explicit removal/redaction on loss. Apply to currently implemented state and recipient-scoped public combat/correlation fields; tracking/reveal remains within declared bounds and camera zoom never grants disclosure.
  • Extend the existing native automation/report path with focused behavior and failure cases; retain exact engine/source/content/rules/configuration identities and actual assertions. Reuse FContentContracts and its canonical extractor/reference closure where these contracts cross a boundary; a schema does not require a separate UObject or new wire protocol. Do not duplicate admission, replay or domain rules in UI/transport.
  • Deliver a bounded dedicated-server/two-client scenario using the existing process/evidence utilities, with exact verified executable/map/setup/reset instructions. No project gameplay map currently exists; use a ticket-owned minimal fixture or transient world on the verified /Engine/Maps/Entry bootstrap as appropriate. Keep scenario controls test-only and extend the existing validation entrypoint without a second runner framework.

Out of scope

  • Automatic Iris/Replication Graph adoption, a second visibility registry and new tracking mechanics.

Dependencies

Hard prerequisites: BW-007, BW-009

Acceptance criteria

  1. AC 1

    Unauthorized hidden/cross-floor/out-of-instance entities, identifiers and private fields are absent from initial/update snapshots, targeting/cycling queries and correlation references. UI/selection/camera changes cannot reconstruct excluded state.

  2. AC 2

    Interest entry gives current authorized state and authorization loss removes/redacts it; old ownership cannot keep receiving private updates. Existing public/owner rules remain at one projection boundary.

  3. AC 3

    Tracking/reveal returns only allowed bounded markers, never a hidden player via zoom or an internal action ID. Hidden-source public results use null source and recipient-scoped correlation per canonical PublicCombatResult.
