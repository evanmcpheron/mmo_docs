BW-097-T02 · Establish the orthographic world viewport and readable UI scaling

Not Started · Parent epic: BW-097 · 3D pixel-art renderer and camera feasibility proof

Epic acceptance criteria: BW-097-AC-2

Implementation scope

  • Extend the existing probe with --case viewport: an angled orthographic Camera3D, a fixed low-resolution world SubViewport, nearest presentation and a separate independently scalable HUD/pointer layer. Declare internal resolution, orthographic size/angle, world pixel scale, permitted zooms, integer/fractional output policy, aspect/letterbox behavior and minimum-window behavior in one versioned probe settings owner.
  • Supply a world pixel grid, numbered terrain squares, character-sized marker, HUD text/control samples, aspect/zoom controls, window presets and an output-content-rectangle overlay. Include explicit invalid/minimum-size cases instead of silently selecting a different pixel scale.
  • Preserve the continuous planar/floor coordinate boundary described by WorldPoint: finite Vector2 foot anchors in tile-width units plus zone/instance/floor scope. Use local fixture anchors and visual transforms only; no new runtime WorldPoint class, message fields or gameplay movement is required. Probe display settings have no canonical domain schema.

Out of scope

  • Production HUD, ability targeting/picking, server floor selection, character creation, a reusable settings subsystem or renderer defaults outside the isolated probe.

Dependencies

Hard prerequisites: BW-097-T01

Acceptance criteria

  1. AC 1

    Captures and settings identify the exact resolution, orthographic framing, scale, filter, zoom and minimum/aspect policies. Known world pixels retain the declared dimensions and nearest appearance on every supported window preset.

  2. AC 2

    Resize, odd dimensions, wide/tall aspect ratios, minimum-size transitions and actual high-DPI presentation preserve the declared world framing/content rectangle and readable separately scaled HUD/pointer. An unavailable display case remains unverified.

  3. AC 3

    Window/zoom changes never alter fixture foot anchors or floor identity. Invalid resolution/scale/zoom settings are rejected visibly and cannot produce a passing viewport result.

Manual verification

Run from the Briarwake implementation repository. The commands, scenes and fixtures below are deliverables of this ticket and its prerequisites; these are unexecuted test instructions.

Launch command or scene

Working directory: GAME_ROOT, the briarwake/ repository root; every res:// path uses that project root. The rendering launcher/case below is a deliverable of these tickets, not an existing command.
python3 tools/verify_toolchain.py
python3 tools/run_rendering_probe.py --case viewport

Setup

  1. Use T01 graphics hardware and fixtures. This ticket supplies the pixel grid, HUD/pointer samples, presets, zoom controls and declared minimum-window policy.
  2. Have a high-DPI display available; record logical and physical dimensions plus OS scaling. Test every declared supported preset and zoom, with a real resize in addition to preset selection.

Actions

  1. Run viewport, capture native internal pixels and presented output, and inspect the grid at each permitted zoom. Resize through normal, minimum, odd-size, wide and tall cases.
  2. Repeat at available high-DPI settings; compare HUD text/pointer with the world grid and content-rectangle overlay. Use disposable invalid settings and check the diagnostic. Compare fixture anchors before and after.

Expected results

  1. Recorded dimensions, nearest scaling, framing and letterbox/minimum behavior match the declared policy. UI remains readable independently of world resolution.
  2. Invalid settings fail visibly; anchor coordinates/scopes remain unchanged. Missing physical display coverage is recorded as not run.

Reset

  1. Use the probe Reset control to restore the checked-in case settings, camera, actor path and effect toggles; quit the graphical process normally. No persistent gameplay state is created.
  2. Keep prior captures, failed results and reports intact. Repeat into a fresh launcher-owned artifacts directory; restore only deliberately modified disposable inputs, leaving source assets, canonical registries and existing user files intact.

Completion evidence and blockers

Required evidence: Retain versioned viewport settings, logical/physical dimension matrix, internal and presented captures, resize/high-DPI review, rejected-settings output and unchanged anchor comparisons.

Blockers: None recorded; see dependencies.

Recorded evidence: None. Planning does not establish an executed pass.
