BW-097-T02 · Establish the orthographic world viewport and readable UI scaling

Complete · Parent epic: BW-097 · 3D pixel-art renderer and camera feasibility proof

Epic acceptance criteria: BW-097-AC-2

Implementation scope

  • Extend the existing probe with --case viewport: an angled orthographic Camera3D, a fixed low-resolution world SubViewport, nearest presentation and a separate independently scalable HUD/pointer layer. Declare internal resolution, orthographic size/angle, world pixel scale, permitted zooms, integer/fractional output policy, aspect/letterbox behavior and minimum-window behavior in one versioned probe settings owner.
  • Supply a world pixel grid, numbered terrain squares, character-sized marker, HUD text/control samples, aspect/zoom controls, window presets and an output-content-rectangle overlay. Include explicit invalid/minimum-size cases instead of silently selecting a different pixel scale.
  • Preserve the continuous planar/floor coordinate boundary described by WorldPoint: finite Vector2 foot anchors in tile-width units plus zone/instance/floor scope. Use local fixture anchors and visual transforms only; no new runtime WorldPoint class, message fields or gameplay movement is required. Probe display settings have no canonical domain schema.

Out of scope

  • Production HUD, ability targeting/picking, server floor selection, character creation, a reusable settings subsystem or renderer defaults outside the isolated probe.

Dependencies

Hard prerequisites: BW-097-T01

Acceptance criteria

  1. AC 1

    Captures and settings identify the exact resolution, orthographic framing, scale, filter, zoom and minimum/aspect policies. Known world pixels retain the declared dimensions and nearest appearance on every supported window preset.

  2. AC 2

    Resize, odd dimensions, wide/tall aspect ratios, minimum-size transitions and actual high-DPI presentation preserve the declared world framing/content rectangle and readable separately scaled HUD/pointer. An unavailable display case remains unverified.

  3. AC 3

    Window/zoom changes never alter fixture foot anchors or floor identity. Invalid resolution/scale/zoom settings are rejected visibly and cannot produce a passing viewport result.

Manual verification

Run from the Briarwake implementation repository. The commands, scenes and fixtures below are deliverables of this ticket and its prerequisites; these are unexecuted test instructions.

Launch command or scene

Working directory: GAME_ROOT (briarwake/). Python 3.10+, sibling mmo_docs and the pinned native macOS ARM64 graphical desktop are required.
python3 tools/verify_toolchain.py
python3 tools/run_rendering_probe.py --case viewport
python3 tools/run_rendering_probe.py --case viewport --interactive
python3 -m unittest discover -s tools -p 'test_*.py'

Setup

  1. Use the locked 4.7.2-stable engine/templates with Forward+; actual tested backend is Metal on Apple M2 Max with built-in Retina display scale 2. Other displays/OS scaling remain unverified.
  2. fixtures/rendering/viewport.json is the versioned settings owner: fixed 384x216, keep-height orthographic size 9, pitch -35/yaw -45 degrees, zoom 1/2, nearest integer physical presentation and 640x480 logical minimum. HUD/pointer scales are native display scale times independent UI 1/1.25/1.5.
  3. The launcher creates a fresh owned artifacts/rendering-<UTC>/ directory and disposable scene-only project. Optional --output must name a new directory. No production project settings or game state change.

Actions

  1. Run the unattended case. Inspect run.json settings/actual identity, all 21 TestChecks, canonical automated_evidence, 19-row matrix, 16 native resize observations, unchanged scoped anchors, display_coverage and 40 paired internal/output captures.
  2. In interactive mode wait until controls enable, then change window/aspect presets, zoom and UI scale. Resize the actual native window through odd/wide/tall/minimum transitions. Capture writes manual-NNN-internal.png, manual-NNN-output.png and actual dimensions/anchors in manual-NNN.json. Reset restores the first preset and scales; close normally to finish.
  3. Repeat on each available physical display/OS scaling. Compare logical size (physical divided by display scale), framebuffer dimensions, gold content rectangle, exact checker block widths and readable HUD/pointer. Treat unavailable cases as not run.
  4. Run each negative in fresh output: --case viewport --control invalid-settings; --case viewport --control missing-report; --case viewport --control check-failure; --case viewport --renderer mobile. Use disposable --settings copies for orthographic_size=0, zooms=[1.0,1.5], or a fractional output_policy. Rerun a clean viewport case afterward.

Expected results

  1. Every preset/zoom preserves the fixed world frame and exact integer physical checker blocks. Zoom changes camera size only; UI/pointer scaling is independent. Scoped non-grid foot anchors, floor identity and marker transforms never change.
  2. Below either logical minimum dimension, world output is hidden with an orange diagnostic. At/above minimum it restores without fractional downscaling. Largest UI fits the minimum window above the world. Odd remainders use right/bottom borders.
  3. Invalid settings/unsupported candidates fail before graphical assertions; missing-report has no complete assertion evidence; deliberate check failure retains canonical failed findings. No negative can produce a passing viewport run. Fresh recovery passes independently.
  4. Actual Retina 2x/source checks and Codex diagnostic capture review are retained; manual drag/click, alternate screens/OS scaling, human art approval, motion stability and exports are unverified.

Reset

  1. Use Reset, then close the graphical process normally. Start a new launcher invocation for a new owned output; no gameplay state persists.
  2. Keep all previous failures/captures/reports intact. Restore only deliberately edited disposable settings; preserve canonical inputs, installed binaries and unrelated user files.
