Not Started · Parent epic: BW-002 · Authority boundaries and content admission

Epic acceptance criteria: BW-002-AC-3

Implementation scope

  • Complete the admission activation gate for AbilityRuntimeBinding/ResolvedAbilityDefinition and enabled named behavior using explicit implemented handler capabilities and matching evidence. Reuse the T03 owner; absence of gameplay handlers in the current module means executable gameplay remains disabled. Do not implement combat merely to demonstrate rejection.
  • Validate finite operation tokens/typed parameters, supported talent modifier paths/operation indexes, targeting/policy handlers, presentation/resource references and cleanup bindings before readiness. Binding resolution, data tests and runtime tests are independent gates for the same ability/build/content/rules tuple; authored true flags or expected findings cannot supply execution evidence.
  • Add native fixtures for shipped legacy prose/profile records, missing/null binding where applicable, unknown named effect/token/path/policy, known shape without implemented handler and stale/mismatched evidence. Produce explicit findings for attempted activation while permitting legitimate catalog-only storage. Use only a test-owned capability/evidence fixture to check the successful gate branch; label it as a gate test, not certification of an ability handler.

Out of scope

  • Interpreting intent text, runtime scripting, executing new abilities/talents, certifying all prototype catalog records or fabricating readiness evidence.
  • An extensible plugin registry or new canonical behavior beyond the finite vocabulary without a separately reviewed versioned contract.

Dependencies

Hard prerequisites: BW-002-T03

Acceptance criteria

  1. AC 1

    A definition with only name/prose/profile or a complete binding without implemented support/evidence cannot become enabled; findings name the missing binding, handler, policy or evidence.

  2. AC 2

    Unknown operation tokens/parameters, modifier paths/indexes, policies and stale revision-tuple evidence reject without changing the active package. Changing intent prose never grants capability.

  3. AC 3

    Each readiness gate independently prevents activation when absent; a finite test-owned supported capability with matching actual test evidence passes the gate branch. Normal builds gain no test handler or gameplay control.
