Audit & open gates

Mechanics, governing rules, edge cases and acceptance criteria.

Audit scope

This revision audits the supplied v1 files, the v2 system contracts and the generated data. It checks progression capacity, references, arithmetic, race/faction eligibility, recipe coverage and documentation navigation. It also corrects identified semantic contradictions. It does not claim exhaustive manual certification of every ability interaction, production database testing or measured game balance.

Scope of evidence

330 named ability records have prototype profiles; 329 still carry a bespoke-behavior binding review flag. 882 inherited talent nodes require bespoke binding; 882 added nodes use shared handling contracts. These are content-readiness states, not failed arithmetic tests.

All 257 representative recipe outputs have explicit prototype effect or equipment-budget definitions. They are not a complete launch recipe inventory.

Blocking before a playable release

Current phase: Briarwake is the implementation target, while this repository remains a design/contract reference. The current schema questions are resolved; future art/maps, concrete balance records, handlers, provider/database setup and actual gameplay/integration evidence remain explicitly unimplemented. Fully Defined describes the complete documented contract, never a claim that the game has been written or tested.

The 2.1.0-design contract review settles serialization, ordinary targeting inputs, equipment placement, invitation lifecycle, resource terminology and client disclosure. The remaining design questions are now resolved in the 2.2 documentation pass; future content production and runtime evidence remain listed under decision history. The current repository still contains no game server or executed gameplay fixtures; an open gate cannot be cleared by a schema match or an adopted recommendation alone.

Bespoke content binding. Most inherited named abilities have a numeric primary-effect profile, but some intended secondary effects, summon behavior, talent rewrites and resource hooks are not fully bound. Enabling those entries by reading free-text intent is forbidden. The exact unresolved counts are in the generated report. Broadly repeated handling talents are candidates for pruning if playtests show no meaningful decisions.

Combat and economy balance. No playable server/client, actual rotations, human usability sessions, completed item sets or live economy has been run here. DPS, healing sustainability, faction win rates, skill progression time, repair costs and crafting profitability remain measurements to obtain, not established results.

Full content production. Representative recipe blueprints prove level-band coverage; they are not hundreds of commissioned item icons, finished stat variants, animation sheets or a complete launch drop table. Additional named role-service abilities and UI assets still need authoring.

Operational correctness. Structural JSON and arithmetic tests do not prove database transaction correctness under failures, anti-cheat effectiveness, network capacity or backup restoration. The testing page separates shipped checks from required future integration tests.

Change control

Treat the JSON content version, rules version and database schema version separately. A change to a talent's meaning requires a versioned migration and a safe build refund/revalidation policy. A numeric balance patch must include affected-item/build simulations and clear patch notes. Preserve IDs where meaning remains compatible; do not silently repurpose a deleted ID for an unrelated spell or recipe.
