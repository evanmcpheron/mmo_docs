Complete · Parent epic: BW-095 · Versioned content authoring and import workflow

Epic acceptance criteria: BW-095-AC-1, BW-095-AC-2

Implementation scope

  • Extend FContentAdmission and canonical extraction for TalentNodeDefinition, catalog TalentModifierDefinition and required class/specialization/progression data. Reuse the existing finite modifier/readiness checks; source/import adapters do not resolve free-text effects or issue evidence. Native talent catalog/graph validation is missing: validation/run_checks.py contains documentation allocation examples, not an authoritative runtime validator. Use its established rules as reference, with one native owner for new admission checks.
  • Round-trip one representative complete 36-node character tree and its linked abilities/progression, preserving existing IDs/source_version/binding_status. Validate owner namespace, prerequisite reachability/ranks, exclusive alternatives, required abilities/unlock levels and lower-tier point capacity. Preserve six tiers, thresholds 0/8/18/30/42/52, one choice in each tier-II/tier-VI three-way group, capstone transformation requirement and 92 selectable ranks; use canonical source values rather than new authoring defaults.
  • Preserve level-one zero points; one class and one specialization point per level-up through 60 (59 each, 118 total), separate currencies and specialization spending gated until selection at level ten. Reject impossible prerequisites/progression and inconsistent ability previous_level chains without implementing live allocations, respec or auto-grant. Test a representative legal tree and distinct broken references, cycles, rank/cap, exclusive-choice and unlock cases through the actual native validator. Missing bespoke bindings remain disabled.

Out of scope

  • Production of all 49 trees or inherited ability catalog, exhaustive allocation searches, live talent/build authority, respec UI or combat transformations.

Dependencies

Hard prerequisites: BW-095-T01

Acceptance criteria

  1. AC 1

    The representative talent tree, modifiers and linked progression/ability records round-trip through the same route with stable identity and canonical field semantics; existing finite modifier validation remains the sole owner for its rules.

  2. AC 2

    Unknown/cross-owner prerequisites, cycles, unattainable rank/point thresholds, incompatible exclusive choices and required-ability/previous_level unlock contradictions yield actionable record-level rejection, with no partial admitted selection.

  3. AC 3

    The documented tier/point/unlock requirements remain intact. Static legal-content checks and imported binding_status/readiness fields never enable an unimplemented talent or mark an execution fixture passed.
