In Progress · Parent epic: BW-095 · Versioned content authoring and import workflow

Epic acceptance criteria: BW-095-AC-1, BW-095-AC-2

Implementation scope

  • Own the bounded offline command entry point in the existing Briarwake module beside ContentAdmission. Reuse FContentContracts, FContentRevisions, FContentAdmission::AdmitFile/AdmitText, the existing candidate envelope and server-owned policy; extend tools/extract_content_contracts.py only for required canonical roots and reference closure. Source records remain canonical JSON under version control. Document exact author/import/validate/export/reimport commands, sample paths and supported families; do not introduce a competing gameplay schema or copy native validation into a Python/UI validator.
  • Reuse findings: at game main 1f705e797fae5507fe477deb85529f047f2ddd63, the extracted snapshot contains 98 definitions and admission already supports abilities, targeting/resources/cooldowns and economic item/material/recipe families. Native selection publication, revision compatibility, readiness and complete economic-graph checks exist. BW-002-T06 and BW-003-T05 retain executed prerequisite evidence; they do not establish this missing authoring adapter or production gameplay. Preserve those owners and evidence rather than replaying their historical FULL workflows.
  • Start with a small reviewed, linked ability/item/recipe sample and its explicit dependencies. Preserve stable IDs, tokens, absent-versus-null fields and separate content/rules/database revisions; keep database labels synthetic. Return native code/path/message findings with source file, family, record identity and field mapping; import/export failure returns nonzero. Keep current native input bounds, including 1 MiB files and 256 complete-selection records. Unreal DataTable JSON import/export, Data Assets and factory APIs are available locally but have no Briarwake authoring integration; the existing JSON/native boundary avoids requiring a new asset editor or plugin.

Out of scope

  • A visual editor, DataTable migration, unrestricted scripting, bulk catalog production, gameplay handlers, database deployment or art/resource production (BW-098).
  • Treating an admission test probe, available Unreal API or documentation validation as implemented authoring or runtime capability.

Dependencies

Hard prerequisites: BW-001, BW-002, BW-003

Acceptance criteria

  1. AC 1

    The documented offline entry point imports, validates, exports and reimports representative ability, item and recipe records through the actual native admission owner, preserving exact IDs, canonical values, optional/null distinctions and revision domains. A successful catalog import grants no gameplay readiness.

  2. AC 2

    Malformed/bounded-input violations, duplicate identities, incompatible revisions, missing references, invalid target/resource fields and unsupported families return actionable source/record/field findings and nonzero status; the existing admitted selection remains unchanged.

  3. AC 3

    The same selected canonical definitions are used by import, export and admission. Unsupported schema vocabulary fails visibly; author-provided policy, activation flags or expected findings cannot create server capability or runtime evidence.
