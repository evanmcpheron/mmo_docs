Objective and scope

Make documented state ownership and enabled-content compatibility enforceable boundaries.

Scope: Stable IDs, version domains, command/result contracts, public/private projections and package admission; evolve only the contracts needed by enabled features, without freezing every future message.

Acceptance criteria

  1. AC 1

    The boundary review names an owner and lifecycle for movement, combat, durable assets, builds and client presentation, preserving documented invariants.

  2. AC 2

    Admission accepts a compatible package and rejects unknown references, invalid targeting/resource fields and incompatible versions before enabling its records.

  3. AC 3

    Unbound named behavior cannot be enabled by interpreting free-text intent; unsupported records produce explicit findings.

  4. AC 4

    Compatibility fixtures preserve existing identifiers and serialized values and separate content, rules and database revisions.

  5. AC 5

    Before enabling vendor/crafting/conversion routes, the complete enabled price and conversion graph passes the documented no-unlimited-guaranteed-loop gate; missing required values keep affected routes disabled. Positive and negative fixture graphs demonstrate this admission rule.
