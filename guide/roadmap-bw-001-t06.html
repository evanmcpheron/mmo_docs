BW-001-T06 · Keep server credentials out of distributed client artifacts

Not Started · Parent epic: BW-001 · Reproducible client and headless project

Epic acceptance criteria: BW-001-AC-3

Implementation scope

  • Define explicit client export inclusion/exclusion rules for server-private configuration, environment files, credential directories and server-only fixtures; keep server runtime configuration external to distributed client resources.
  • Add tools/check_client_artifact.py to inspect the full macOS client bundle and its packed resource inventory/content, reporting forbidden paths or sentinel detections without echoing secret values. Document the credential sources excluded by the packaging policy.
  • Provide --self-test --output artifacts/credential-check that creates disposable harmless credential sentinels in representative server-private/config/environment inputs, exports an isolated client with the normal policy, and inspects it. Include an intentionally leaking disposable fixture to prove the inspector detects contamination; never use real credentials.
  • Reuse the T05 exported client launch check after inspection and retain a machine-readable inspection result tied to its artifact hash. Place all fixtures, temporary build inputs and cleanup behavior within this ticket.

Out of scope

  • Identity providers, production credentials, secret vault deployment, runtime authentication or security review of future endpoints.
  • Treating a raw binary string search alone as proof that compressed/packed resources are safe.

Dependencies

Hard prerequisites: BW-001-T05

Acceptance criteria

  1. AC 1

    The normally exported client contains none of the server-private paths or synthetic credential sentinels when both bundle files and packed resources are inspected.

  2. AC 2

    The deliberate leaking fixture produces a failing inspection and nonzero exit with a safe path/category finding, proving the check is active.

  3. AC 3

    The clean inspected client still launches and quits; inspection evidence identifies the artifact hash and excluded credential sources.

  4. AC 4

    Self-test cleanup removes synthetic private inputs and contaminated artifacts from its disposable workspace; no real secret value is collected or printed.

Manual verification

Run from the Briarwake implementation repository. The commands, scenes and fixtures below are deliverables of this ticket and its prerequisites; these are unexecuted test instructions.

Launch command or scene

python3 tools/check_client_artifact.py --self-test --output artifacts/credential-check

Setup

  1. Complete T05. Use a disposable checkout and the pinned toolchain on macOS.
  2. Use only the synthetic private inputs created by the self-test. Do not provide account, service or signing credentials.

Actions

  1. Run the self-test and inspect both the normal-client and deliberately leaking-fixture results.
  2. Launch the clean artifact using the artifact path reported by the tool; close it with Quit.
  3. Inspect the self-test workspace and repository status after cleanup.

Expected results

  1. The normal client passes inspection, while the contaminated fixture fails with an attributable safe diagnostic.
  2. The inspected client remains launchable, and evidence points to that exact artifact hash.
  3. No private sentinel inputs or contaminated outputs remain in distributed output; logs report findings without marker values.

Reset

  1. Close the client. Use the documented cleanup command for the owned self-test output after retaining redacted results; leave source fixtures and normal export policy intact.

Completion evidence and blockers

Required evidence: Client packaging policy, packed-resource inspection results, successful negative-control detection, inspected-artifact hash and client launch result.

Blockers: None recorded; see dependencies.

Recorded evidence: None. Planning does not establish an executed pass.
