BW-001-T06 · Keep server credentials out of distributed client artifacts

Implementation ticket for BW-001.

Complete · Parent epic: BW-001 · Reproducible client and headless project

Epic acceptance criteria: BW-001-AC-3

Implementation scope

  • Define explicit client export inclusion/exclusion rules for server-private configuration, environment files, credential directories and server-only fixtures; keep server runtime configuration external to distributed client resources.
  • Add tools/check_client_artifact.py to inspect the full macOS client bundle and its packed resource inventory/content, reporting forbidden paths or sentinel detections without echoing secret values. Document the credential sources excluded by the packaging policy.
  • Provide --self-test --output artifacts/credential-check that creates disposable harmless credential sentinels in representative server-private/config/environment inputs, exports an isolated client with the normal policy, and inspects it. Include an intentionally leaking disposable fixture to prove the inspector detects contamination; never use real credentials.
  • Reuse the T05 exported client launch check after inspection and retain a machine-readable inspection result tied to its artifact hash. Place all fixtures, temporary build inputs and cleanup behavior within this ticket.

Out of scope

  • Identity providers, production credentials, secret vault deployment, runtime authentication or security review of future endpoints.
  • Treating a raw binary string search alone as proof that compressed/packed resources are safe.

Dependencies

Hard prerequisites: BW-001-T05

Acceptance criteria

  1. AC 1

    The normally exported client contains none of the server-private paths or synthetic credential sentinels when both bundle files and packed resources are inspected.

  2. AC 2

    The deliberate leaking fixture produces a failing inspection and nonzero exit with a safe path/category finding, proving the check is active.

  3. AC 3

    The clean inspected client still launches and quits; inspection evidence identifies the artifact hash and excluded credential sources.

  4. AC 4

    Self-test cleanup removes synthetic private inputs and contaminated artifacts from its disposable workspace; no real secret value is collected or printed.

Manual verification

Run from the Briarwake implementation repository. The commands, scenes and fixtures below are deliverables of this ticket and its prerequisites; these are unexecuted test instructions.

Launch command or scene

Working directory: briarwake repository root.
python3 tools/check_client_artifact.py --self-test --output artifacts/credential-check
python3 -m unittest discover -s tools -p 'test_*.py' -v
python3 tools/run_baseline.py --artifact-dir artifacts/credential-check/build --role client
For an existing unchanged owned result, add --clean to --self-test. To inspect a separate export:
python3 tools/check_client_artifact.py --bundle artifacts/baseline/BriarwakeClient.app --report artifacts/client-inspection.json

Setup

  1. Complete T05. Use native ARM64 Python 3.10+ on macOS with the checksum-pinned Godot 4.7.2 editor and templates in tools/toolchain.lock.json. Optional --engine and --templates select verified installations. See tools/README.md.
  2. Use only self-test-generated harmless private inputs. No account, provider, signing credential, network listener or database is needed. A desktop session is required for the visible launch check.
  3. Choose a new output directory under artifacts/ or use --clean only on unchanged owned self-test output. The self-test writes synthetic inputs solely into the builder's owned temporary snapshot and exports the normal client preset only.

Actions

  1. Run the self-test. Retain result.json, clean-inspection.json, negative-inspection.json, logs/negative-inspection.log, build/manifest.json and build/logs. Compare the inspected bundle SHA-256 with the build manifest client fingerprint.
  2. Review clean-inspection policy.excluded_sources from export_presets.cfg and all bundle/packed-resource inventories. The clean report must have zero findings. The negative report must show safe path/category findings for loose files, PCK path-only/content-only controls, a hidden ZIP member and decoded compressed content. Confirm negative_exit_status is 1.
  3. Execute result.json launch_command with absolute paths from /private/tmp. Observe Briarwake client baseline and Quit, click Quit and retain launcher exit 0. The self-test itself truthfully leaves GUI execution as not run; retain a separate actual launch log/result.
  4. Run a fresh --bundle inspection into a new report after launch and compare its fingerprint to the original clean/build fingerprints. Check result.json cleanup and verify all synthetic_input_paths are absent from the checkout; the negative workspace path must no longer exist.
  5. Run the Python behavioral tests. To retain full baseline regression, run python3 tools/build_baseline.py --output artifacts/credential-baseline-regression then the T05 packaged-server --headless --config fixtures/config/server.valid.json --smoke command.

Expected results

  1. Self-test exit 0 means the normal export passed inspection, all expected negative-control detections were executed with nonzero inspector exit, and temporary cleanup succeeded. Twenty Python tests pass, including failed-export cleanup, redaction and preservation of modified/unowned/symlinked output.
  2. The inspector enumerates hidden packed files and reads all PCK/ZIP member contents using the pinned engine, including decompressed ZIP content. Raw ZIP bytes contain no synthetic prefix in the compressed control. Unreadable/encrypted/nested packs fail inspection. Findings contain location/path/category and inventories contain hashes/lengths, never synthetic values.
  3. The exact clean client visibly launches and exits 0 through Quit from an external working directory. Its bundle fingerprint matches before/after inspection and the build manifest. Server runtime configuration stays external and mandatory.
  4. Synthetic build inputs and contaminated outputs are removed from their disposable workspaces even on failure. No real credential value or credential source is supplied, collected or printed. Successful output retains only the clean client and safe reports/logs/manifests.

Reset

  1. Close the owned test client and retain safe reports/logs/manifests outside self-test output. Run python3 tools/check_client_artifact.py --cleanup --output artifacts/credential-check. This removes only unchanged output with the credential-check ownership marker and exact file/directory inventory.
  2. If ownership/inventory checks reject cleanup, preserve that output and choose a new directory. Keep committed fixtures, export policy, installed tools, existing import cache and user edits. Cleaned contaminated artifacts must not be distributed.

Completion evidence and blockers

Required evidence: Client packaging policy, packed-resource inspection results, successful negative-control detection, inspected-artifact hash and client launch result.

Blockers: None recorded; see dependencies.

Deliberately leaking loose/PCK/deflated-ZIP controls produced safe findings and exit 1, including decoded-only compressed content and a hidden member. Exact inspected client visibly launched from /private/tmp and quit with exit 0; post-launch hash was unchanged.
