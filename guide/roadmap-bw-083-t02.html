Epic acceptance criteria: BW-083-AC-3, BW-083-AC-4

Implementation scope

  • Reuse T01 real workload and native network emulation; reuse equivalent BW-008 correction scenarios/evidence when input/workload scope matches, without assuming single-character proof covers load.
  • Run the representative workload at measured 0/50/100/150/250 ms RTT with declared jitter/reordering/1–5% loss. Record failures and a bounded bottleneck/budget review; distinguish prototype configured rates from achieved behavior. Optional Graph/Iris/custom changes require concrete measured need and a separate scoped decision.
  • Extend the existing native automation/report path with focused behavior and failure cases; retain exact engine/source/content/rules/configuration identities and actual assertions. Reuse FContentContracts and its canonical extractor/reference closure where these contracts cross a boundary; a schema does not require a separate UObject or new wire protocol. Do not duplicate admission, replay or domain rules in UI/transport.
  • Deliver a bounded dedicated-server/two-client scenario using the existing process/evidence utilities, with exact verified executable/map/setup/reset instructions. No project gameplay map currently exists; use a ticket-owned minimal fixture or transient world on the verified /Engine/Maps/Entry bootstrap as appropriate. Keep scenario controls test-only and extend the existing validation entrypoint without a second runner framework.

Out of scope

  • Automatic networking-framework adoption, performance promises, production capacity and unrelated gameplay systems.

Dependencies

Hard prerequisites: BW-012, BW-083-T01

Acceptance criteria

  1. AC 1

    Actual workload impairment runs retain effective settings, RTT, jitter/order/loss, visible rejected inputs/failures and recovery, with compatible engine emulation scenarios. Equivalent valid evidence may be reused; workload-specific gaps are tested.

  2. AC 2

    The reviewed report identifies measured constraints, unresolved budgets and bounded next changes without turning prototype rates or connection counts into achieved capacity. Any claimed improvement has comparable before/after reruns.

Actions
