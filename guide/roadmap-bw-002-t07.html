Implementation scope

  • Join T02-T04/T06 through the same --suite all runner and real FContentAdmission candidate/publication path. Reuse suite verifiers and immutable fixtures; do not calculate substitute admission results in Python. Record exact source/toolchain/canonical fingerprints, boundary-review revision and separate content/rules/database identities.
  • Run compatible, incompatible, unbound and safe/unsafe economic candidates with rejected replacements, stale/partial/foreign reports, assertion failure, build failure, timeout and independent clean recovery. Include actual build and report-discovery controls; a previous report or successful process exit cannot satisfy an unexecuted run. Reuse BW-001 clean snapshot/process/isolation tools where applicable without weakening its baseline tests.
  • Recheck relevant baseline Editor/Game/source-Server builds, startup configuration and packaged headless/client isolation. Verify fixture data/control capabilities are excluded from normal packages and no test command grants production economic authority. Use actual documented BW-001 commands and new verified admission commands; retain current artifact identities and limitations.
  • Review all five parent ACs against child artifacts, applicable BW-001 evidence and current source. Update only justified ticket/epic progress, preserve historical evidence, remove resolved blockers and regenerate readiness, foundation/milestone/dashboard and inventory/search metadata. This integrated suite does not implement BW-003 fixture context/diagnostics/metrics or later networking/persistence epics.

Out of scope

  • Implementing BW-003, connected Steam sessions, production authentication/database deployment, full catalog readiness, capacity testing or other platforms.
  • Completing the epic from documentation/schema checks or from child status alone.

Dependencies

Hard prerequisites: BW-002-T04, BW-002-T06

Acceptance criteria

  1. AC 1

    Two fresh complete native runs execute all required admission suites and link matching boundary review, canonical contract and runtime assertions. Missing/stale/foreign/partial artifacts or any failed suite make the aggregate fail.

  2. AC 2

    Build failure remains not executed, actual assertion failure remains executed/failed and timeout/missing report cannot become success. Clean recovery passes independently without overwriting evidence.

  3. AC 3

    Relevant existing bootstrap builds/configuration/headless smoke/package isolation pass or retain justified applicable evidence. No test-only fixture/capability/control is exposed by normal client/server execution.

  4. AC 4

    An explicit five-criterion parent review maps actual artifacts to BW-002 AC1-AC5, retains precise limitations and updates dependent readiness only when the evidence supports it. Missing canonical decisions, unsafe graph results or unexecuted gates prevent completion.
