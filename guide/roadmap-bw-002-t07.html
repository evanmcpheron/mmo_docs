Complete · Parent epic: BW-002 · Authority boundaries and content admission

Epic acceptance criteria: BW-002-AC-5

Implementation scope

  • Add the no-unlimited-guaranteed-loop analysis to the same admission owner over T06 complete enabled route view. Preserve integer quantities, recipe batch outputs, required inputs and explicit prices; analyze the combined existing-plus-proposed graph, not each recipe or currency edge alone.
  • Enforce crafted output sellback strictly below guaranteed NPC-purchased input cost, accounting for output quantity and the cheapest supported guaranteed conversion path. Reject repeatable guaranteed cycles that generate currency/material value without exhausting required inputs; include salvage/conversion chains and obey their documented binding/access restrictions. Do not reject ordinary player-market arbitrage or assume uncertain rewards are guaranteed.
  • Return actionable findings naming the contributing source route IDs and quantities or a concrete repeatable witness. If supported constraints are insufficient to establish safety, keep those routes disabled and report the unsupported case; do not silently certify it or introduce a permissive heuristic.
  • Add --suite economy-loops: a lossy safe cycle, safe acyclic chain, crafted sellback at/elevated above guaranteed input cost, multi-step profitable conversion, a loop created only by joining prior admitted routes with a new route, explicit free-input profit, multi-input/batch-output cases and a nonrepeatable scarce-input control. Include craft-salvage material loss and no-XP/no-gold constraints from T06.

Out of scope

  • Player-market optimization, numerical production balancing, speculative conversion mechanics, load/capacity measurement and live crafting/vendor services.
  • Approving a route from pairwise price checks alone, rounding floating-point currency into safety, or using a graph pass to bypass later feature/runtime readiness.

Dependencies

Hard prerequisites: BW-002-T06

Acceptance criteria

  1. AC 1

    Positive fixture graphs pass the documented value-loss rules; every guaranteed profit/duplication fixture and equality-at-crafted-sellback fixture fails before route admission with contributing record IDs and a reproducible explanation.

  2. AC 2

    A proposed route that is safe alone but completes a profitable cycle with already admitted routes is rejected. Multi-input recipes, batch quantities and explicit zero costs cannot bypass the gate.

  3. AC 3

    A scarce nonrenewable-input control is not mislabeled an unlimited cycle; unknown completeness/behavior fails closed with an explicit unsupported finding. Reordering the same fixture graph preserves the decision.

Manual verification

Run from the Briarwake implementation repository. The commands, scenes and fixtures below are deliverables of this ticket and its prerequisites; these are unexecuted test instructions.

Launch command or scene

Working directory: GAME_ROOT, the briarwake/ repository root.
python3 tools/verify_toolchain.py
python3 tools/check_content_admission.py --suite economy-loops
python3 -m unittest discover -s tools -p 'test_*.py'

Setup

  1. Use the pinned native macOS Godot 4.7.2 standard editor and Python environment in tools/toolchain.lock.json. The checker executes actual GDScript in an owned temporary Godot project; no database, account, peers or gameplay scene is required.
  2. The 26 canonical vendor/recipe/item/material/salvage cases are in fixtures/content_admission/economy-loops.json. Their expected ContentValidationFixture evidence remains authored/unexecuted. Default --output creates a fresh timestamped artifact directory; inspect its run.json and logs.
  3. Optional editor sanity: open project.godot in Godot. Reload Current Project after branch/source updates if stale parser/UID output persists. F5 starts the existing client shell, which has no economy controls and does not execute these fixtures. Graphical Play was attempted during this ticket and remains unverified; see manual-editor-review.json.

Actions

  1. Run the suite and inspect each actual finding. economic_loop/crafted_sellback messages include JSON steps with source IDs, exact integer executions, canonical inputs/outputs, seed and net_gain.
  2. For every supported rejection, start with seed, consume/produce the listed quantities for each execution count in order, then compare final stock with seed plus net_gain. Python regressions independently perform this replay against canonical records.
  3. Compare proposed-route-safe-alone with cycle-created-by-retained-routes, multi-input/batch profit with safe controls, and nonrenewable-scarce-input-control with replenished material duplication. Every runner case also reverses catalog order and checks the previous candidate is unchanged.
  4. Confirm salvage-no-gold, salvage-no-xp, excluded cores and starter owner/binding cases remain rejected before graph certification. Inspect explicit unsupported access/arithmetic/unknown-source cases. For an intentional failed execution, run python3 tools/check_content_admission.py --suite economy-loops --control assertion-failure; it must exit 1 and report an executed failed assertion.

Expected results

  1. All 26 authored expected decisions match actual Godot assertions. Lossy, acyclic and finite scarce-stock controls pass; guaranteed profit/duplication and crafted equality reject before candidate creation, with exact replay witnesses.
  2. Every supported profit witness replenishes all inputs and gains a nonnegative resource vector with at least one positive quantity. Crafted equality replenishes the seed exactly and is refused by strict-loss policy.
  3. Unknown behavior/completeness and unsupported access, arithmetic or analysis budgets keep routes disabled with explicit findings. Prices and batch arithmetic use integers throughout. Graph certification cannot satisfy ability readiness or publish active server content.

Reset

  1. Let each bounded checker process exit; its owned temporary Godot project and in-memory registries are discarded. Use a new --output path for every run and preserve earlier evidence.
  2. The driver preserves tracked fixtures, canonical snapshots, scenes and bootstrap configuration. No database, account or persistent economy needs reset. A subsequent clean run reproduces the original decisions.

Completion evidence and blockers

Required evidence: Executed positive and negative graph report with exact route/quantity witnesses, combined-graph regression and safe-control evidence.

Blockers: None recorded; see dependencies.
