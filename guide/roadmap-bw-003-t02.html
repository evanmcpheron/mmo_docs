Not Started · Parent epic: BW-003 · Repeatable runtime fixtures and diagnostics

Epic acceptance criteria: BW-003-AC-2

Implementation scope

  • Extend the T01 transient-world/native automation owner with a finite local diagnostic action probe, controlled fixture clock and deterministic random stream. Source/Briarwake has bootstrap smoke ticks and the private FBindingGateProbe readiness test, but no reusable seeded world replay/clock/queue owner. Keep probe state test-owned and non-economic; do not add casts, damage, rewards, movement, NPC AI or production session ownership.
  • Load FixtureWorldContext with exact server_tick, authoritative UTC server_time, owner_epoch, world_configuration_id, random_seed and explicit visible_entities/npc_states/parties arrays. Extend the existing canonical extractor/snapshot with only the needed definitions and their reference closure; FixtureWorldContext and TestCheck are absent from the inspected snapshot. Preserve Id/Count/Version/Instant types, zero-valid nonnegative ticks/epochs, opaque nonempty string seeds and unknown-field rejection. A named transient world/configuration with explicit empty world collections is sufficient. Reuse the T01 canonical reader; do not create a second schema validator or manufacture absent production entities. Keep local probe steps typed and test-owned; use FixtureStep/FixtureAssertion only for their existing variants, and TestCheck for probe-only assertions.
  • Commit finite scenarios for accepted/rejected probe input, bounded queued execution, same-context replay, explicit seed/context change and reset. Reject invalid/nonfinite/out-of-order timing and unsupported controls before mutation. Expose context reset/seed/clock controls only to compiled automation code; exclude them from gameplay RPCs, console/Exec/Blueprint commands and packaged launch options. Add normal client/server negative-launch checks and a documented context suite.

Out of scope

  • Creating the future world, session, ability or combat systems to run a diagnostic experiment.
  • Client-selectable seeds/time/owner epochs, arbitrary property-path mutation, production cheats or a new gameplay command protocol.

Dependencies

Hard prerequisites: BW-003-T01

Acceptance criteria

  1. AC 1

    Two fresh runs of identical context and ordered inputs reproduce accepted/rejected results, committed probe-effect counts and ordering. Wall-clock timings/run IDs may differ and are excluded from rule equality. Changing the declared seed/context is attributable and a reset reproduces the original outcome.

  2. AC 2

    The canonical reader accepts the supported empty-world FixtureWorldContext without changing its field meanings: zero ticks/epochs are valid and seeds remain opaque nonempty strings. Missing/unknown fields, null required collections, negative counters, invalid UTC timestamps, wrong seed types, nonfinite timing, decreasing offsets and unsupported controls fail before mutation. Re-extraction preserves all previously supported canonical definitions and compatibility cases.

  3. AC 3

    Normal client/server artifacts contain no usable test control path. Attempts to set test seeds, reset state or advance time through ordinary gameplay/launch surfaces fail without mutation; absence of a production RPC dispatcher is recorded rather than claimed as a network attack test.

Actions

  1. Run the context suite twice and compare the deterministic outcome section, exact context/source hashes and native assertions. Exercise a declared alternative seed, then a fresh original context; inspect replay equality and reset.
  2. Run --control invalid-context and --control out-of-order-step against disposable inputs; inspect pre-mutation failure and clean recovery. Include zero tick/epoch and nonnumeric opaque seed positive cases, plus null/missing collections and wrong seed types. Check canonical extraction freshness and the existing compatibility suite.
  3. Run --control gameplay-control, which must attempt the implemented test-control spellings against ordinary BW-001 client/server launches as well as the native non-test admission boundary if present. Inspect state/logs and packaged control exclusion. Do not label this a connected-client security test.

Expected results

  1. Same-context probe outcomes reproduce while measurements remain actual observations. Invalid input never partially applies context or queued state.
  2. Only compiled test code can drive the probe controls; normal launches remain isolated and unchanged.

Reset

  1. The runner must stop timed-out child processes and tear down its transient UWorld, fixture clock, seed, queue and test-owned state. Normal client/server launches must remain unaffected.
  2. Retain previous logs/reports; rerun into a new default output directory. Controls modify only disposable inputs. Never overwrite prior evidence or modify canonical sources, user maps or assets to reset a run.

Completion evidence and blockers

Blockers: None recorded; see dependencies.
