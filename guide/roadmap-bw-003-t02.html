Complete · Parent epic: BW-003 · Repeatable runtime fixtures and diagnostics

Epic acceptance criteria: BW-003-AC-2

Implementation scope

  • Extend the T01 transient-world/native automation owner with FRuntimeFixtureContext, a finite local diagnostic action probe with controlled fixture clock, deterministic random stream and bounded pending effects. State remains test-owned and non-economic; no casts, damage, rewards, movement, NPC AI or production session ownership are added.
  • Load FixtureWorldContext with exact server_tick, authoritative UTC server_time, owner_epoch, world_configuration_id, random_seed and explicit visible_entities/npc_states/parties arrays. The existing canonical extractor/snapshot includes FixtureWorldContext and only its required reference closure alongside T01 TestCheck. Preserve Id/Count/Version/Instant meanings, zero-valid nonnegative ticks/epochs, opaque nonempty string seeds and unknown-field rejection. Support the named transient empty-world configuration; reject unsupported populated worlds/configurations explicitly. Reuse FContentContracts rather than a second validator. Keep local probe steps typed and test-owned, use canonical TestCheck for probe assertions and preserve existing FixtureStep/FixtureAssertion variants.
  • Commit finite scenarios for accepted/rejected probe input, bounded queued execution, same-context replay, explicit seed/context change and reset. Reject invalid/nonfinite/out-of-order timing and unsupported controls before mutation. Expose context reset/seed/clock controls only to compiled automation code; exclude them from gameplay RPCs, console/Exec/Blueprint commands and packaged launch options. Add normal client/server negative-launch checks and a documented context suite.
  • Reuse assessment 2026-10-22: extend the verified T01 FRuntimeFixtureEvidence, transient UWorld lifecycle, stage attribution and canonical reader. The local probe adds only deterministic context/queued decision state; it must not recreate MultiplayerSessions, native movement/prediction or a production command dispatcher. See the dated capability review on roadmap-maintenance.html.

Out of scope

  • Creating the future world, session, ability or combat systems to run a diagnostic experiment.
  • Client-selectable seeds/time/owner epochs, arbitrary property-path mutation, production cheats or a new gameplay command protocol.

Dependencies

Hard prerequisites: BW-003-T01

Acceptance criteria

  1. AC 1

    Two fresh runs of identical context and ordered inputs reproduce accepted/rejected results, committed probe-effect counts and ordering. Wall-clock timings/run IDs may differ and are excluded from rule equality. Changing the declared seed/context is attributable and a reset reproduces the original outcome.

  2. AC 2

    The canonical reader accepts the supported empty-world FixtureWorldContext without changing its field meanings: zero ticks/epochs are valid and seeds remain opaque nonempty strings. Missing/unknown fields, null required collections, negative counters, invalid UTC timestamps, wrong seed types, nonfinite timing, decreasing offsets and unsupported controls fail before mutation. Re-extraction preserves all previously supported canonical definitions and compatibility cases.

  3. AC 3

    Normal client/server artifacts contain no usable test control path. Attempts to set test seeds, reset state or advance time through ordinary gameplay/launch surfaces fail without mutation; absence of a production RPC dispatcher is recorded rather than claimed as a network attack test.

Expected results

  1. Two native process runs reproduce deterministic outcomes and reset. Canonical valid inputs preserve meanings; invalid whole contexts/batches never partially mutate probe state. Controls fail for their exact executed reason and fresh recovery passes.
  2. Normal packaged Game/Server artifacts have no usable fixture control code/data. Deferred Engine Exec discards unhandled return values without a diagnostic; executed command inventories and native marker exclusion prove no handler. Ordinary t.MaxFPS is unchanged around the attempts; unknown flags are ignored without a handler. Actual ordinary server state retains three passing smoke ticks. Diagnostics, measurements, gameplay networking and persistence remain independent work.

Reset

  1. Allow each runner to destroy/GC its transient UWorld; owned process groups are stopped on timeout. Test reset clears context, controlled clock, random stream, decisions and pending queue.
  2. Retain prior outputs and rerun into a fresh default output. Controls use copied or uniquely owned inputs only. Never overwrite previous evidence, change canonical sources, remove caches, resave user maps/assets or create a project copy as reset.
