Epic acceptance criteria: BW-003-AC-3

Implementation scope

  • Emit diagnostics at the T02 authoritative probe decision/commit owner and correlate them through the existing T01 evidence writer. Use a single origin for run/scenario/action IDs, sequence/tick/time, build/engine/content/rules revisions and the fixture owner epoch. There is no production command/diagnostic owner to extend yet; keep the new owner within this bounded test path.
  • Include explicit rejected, committed and duplicate/retry observations with no fabricated commit on rejection. Correlate a synthetic non-economic queued action to its one committed effect; reuse FixtureAssertion idempotency with null receipt ID where applicable and TestCheck for diagnostic assertions. Do not issue CommandResponse or SessionOwnershipRecord payloads that pretend the production systems exist; preserve their documented authority boundaries.
  • Use an allowlisted shareable diagnostic projection. Add synthetic secret/private-state sentinels and hostile/oversized text in rejected input; ensure serialized reports, native logs, stdout/stderr and shareable samples do not disclose them. Bound field lengths/record volume and report overflow observably. Add a diagnostics suite and missing-correlation/redaction negative controls; preserve raw private execution details only when safe and required, never log arbitrary input blobs.

Out of scope

  • Production log transport, retention dashboards, authentication/session infrastructure, economic audit trails or private gameplay data modeling.
  • Changing canonical command outcomes, rejection enums or world ownership contracts for a diagnostic probe.

Dependencies

Hard prerequisites: BW-003-T02

Acceptance criteria

  1. AC 1

    An accepted probe action has one attributable commit and matching correlation IDs/revisions; a rejected action reports a reason without mutation; a retried synthetic action has one committed effect. Distinct owner epochs/runs cannot silently join each other.

  2. AC 2

    The shareable sample connects every observation to its actual run, action and build/content/rules/owner context. Missing/foreign correlation fields or a forged commit make verification fail.

  3. AC 3

    Synthetic credentials, hidden identifiers and private input sentinels are absent from all retained/shareable output surfaces. Malformed or oversized text and output overflow produce bounded safe diagnostics; a planted leak is detected by the redaction control.

Actions

  1. Run the diagnostics suite and trace one accepted, rejected and duplicate probe action from input identity through the authoritative decision and effect count to the shareable sample.
  2. Run --control missing-correlation and --control redaction-leak in disposable outputs, then clean again. Inspect failure detection; never use real credentials as sentinels.
  3. Inspect native child logs, wrapper stdout/stderr, JSON reports and shareable sample for all injected secret/private sentinels. Inspect malformed/oversized text and bounded-overflow cases for safe visible failure without unintended mutation.

Expected results

  1. Every rejection/commit/retry is attributable to the correct current probe context and only an actual commit changes probe state.
  2. Safe runs contain no sentinels; deliberately broken correlation/redaction fails and later clean execution recovers.

Reset

  1. The runner must stop timed-out child processes and tear down its transient UWorld, fixture clock, seed, queue and test-owned state. Normal client/server launches must remain unaffected.
  2. Retain previous logs/reports; rerun into a new default output directory. Controls modify only disposable inputs. Never overwrite prior evidence or modify canonical sources, user maps or assets to reset a run.
