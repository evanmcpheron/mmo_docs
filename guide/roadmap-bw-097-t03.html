Epic acceptance criteria: BW-097-AC-7

Implementation scope

  • Use --case reference with a bounded selection from the user-provided Moore RPG Template Unreal library: a modular armored knight, small peasant hut, tree and barrel, preserving source materials and a sampled idle pose. This explicit asset request supersedes the initial original primitive fixtures. Record source/dependency and converted hashes, a local export recipe and provenance without importing production asset volume or porting Unreal gameplay logic.
  • Use DOCS_ROOT/assets/graphics_concept.png as the principal appearance reference and record its hash and annotated crops. Compare character-to-prop detail, relative proportions, palette/value separation, depth/contact cues and lighting at the declared gameplay scale. Link the selected Holland and Roystan material and annotated t3ssel8r clip timestamps; do not infer capability from any reference.
  • Create a versioned review sheet with observable still/motion acceptance bounds, reviewed comparison regions, test settings, reviewer/date, approved deviations and blocking findings. Establish visual and provisional CPU/GPU/memory budgets with the user before accepting downstream comparisons; unresolved acceptance choices are explicit review gates, never fabricated numeric requirements. Subsequent tickets fill their relevant motion/effect results against this baseline.
  • If heading presets are exposed, reuse SpriteDirection exactly as eight case-sensitive strings north, north_east, east, south_east, south, south_west, west and north_west; exercise them as preview presets while retaining continuous actor heading. No complete CharacterPreviewState/appearance catalog or new art gameplay schema is needed.

Out of scope

  • Pixel-perfect reproduction, production character/equipment/environment pipelines (BW-098), final environment art (BW-099), broad concept recreation or automatic visual approval.

Dependencies

Hard prerequisites: BW-097-T02

Acceptance criteria

  1. AC 1

    Annotated side-by-side captures use the concept as principal appearance evidence at the declared gameplay scale and explicitly compare character detail against simpler props, palette, depth and lighting. Supplementary references identify the adopted observation and clip timestamp.

  2. AC 2

    A real review records observable acceptance bounds, prototype measurement budgets, reviewer/date and permitted deviations for later still/motion tests. Any missing approval or blocking finding prevents this ticket and the epic from being accepted.

  3. AC 3

    All fixture assets have source/provenance and stable probe references. Preview presets, if used, retain exact SpriteDirection values; invalid tokens/ordinal substitutes are rejected and actor heading is not restricted to eight directions.

Setup

  1. moores-assets.json selects four local exports and the knight idle animation. export_moores_reference.py uses an isolated copy-on-write Content clone, enabled Python/GLTF/ChaosClothAsset plugins and 512px material baking. The source Unreal project is never saved. Converted GLBs stay ignored under artifacts/moores-export-work/exports; the manifest records recipe, source/dependency and GLB hashes. Missing/changed/incomplete exports fail before graphics; another matching local directory can be supplied with --assets. The concept remains comparison-only in DOCS_ROOT. The current readability revision uses Anim_Idle_Straight, knight display scale 1.8 and focus height 1.3m with frontal fill. Export-only torso/cape materials connect the authored PBR textures directly because the original graphs baked black; runtime albedo observations reject blank transfers.
  2. Automatic verification runs day/warm/cool lighting at zoom x1/x2 and Reset, writing paired internal/output images, projected comparison regions and actual engine/backend/device identity in a new launcher-owned artifacts directory. Human visual approval is separate.
  3. Every automatic reference run also retains comparison-native.png and comparison-pixelated.png at identical physical world-content dimensions. The former renders standard PBR directly at native resolution; the latter enlarges 384×216 with nearest sampling. No custom toon/outline shader is active. Camera, materials, pose and lighting match; the original viewport and exact pixels must be restored after capture.

Actual annotated comparisons and decoded supplementary frame observations support AC1; no engine capability is inferred from external references. Later motion, outlines, contact-depth/water, packaged performance and other hardware remain unverified; numerical proposals are not measured passes.

Reset

  1. Use the probe Reset control to restore the checked-in case settings, camera, actor path and effect toggles; quit the graphical process normally. No persistent gameplay state is created.
  2. Keep prior captures, failed results and reports intact. Repeat into a fresh launcher-owned artifacts directory; restore only deliberately modified disposable inputs, leaving source assets, canonical registries and existing user files intact.
