BW-097-T03 · Add held middle-mouse orbit with isolated input capture

Implementation ticket for BW-097.

Not Started · Parent epic: BW-097 · Orthographic camera and visual-readability proof

Epic acceptance criteria: BW-097-AC-3, BW-097-AC-5

Implementation scope

  • Reuse assessment: Provided by Unreal or a plugin — Enhanced Input mapping contexts, PlayerController input and camera/spring-arm transforms are available. Integrate them into T01/T02 owners rather than rotating the pawn/controller aim or introducing a second camera manager.
  • Map held middle mouse plus horizontal/vertical drag to local camera yaw and bounded pitch in overview, close view and throughout scrolling. Wheel/orbit input is consumed only when the world viewport owns it. Add explicit release, focus-loss, PIE stop, pawn/view-target replacement and widget-capture cleanup so no stuck drag or delayed input resumes unexpectedly.
  • Expose sensitivity, inversion, limits and response/smoothing in the existing Unreal tuning UI. Reuse InputBindingConfiguration/InputBinding semantics where a binding boundary is represented, without inventing an enum of future actions or a gameplay RPC. Supply a small consuming UI panel/control and focus/capture fixtures now; T04 may restyle them and T05 reuses them for picking.
  • MovementState remains owned by the scene route or eventual gameplay owner. Record camera-only versus independent movement/aim observations during stationary/axial/diagonal tests; release ends new orbit input and configured smoothing settles without continuing uncontrolled rotation.

Out of scope

  • Production key-binding/settings UI, controller-platform certification, aim/movement authorization and world-picking rules.

Dependencies

Hard prerequisites: BW-097-T02

Acceptance criteria

  1. AC 1

    Held horizontal drag orbits yaw, vertical drag respects configured pitch limits, and release stops new orbit input in both views and during zoom. Stationary/axial/diagonal routes keep stable framing and unchanged independent position/facing/aim.

  2. AC 2

    Wheel and drag captured by a UI control do not move the world camera. Releasing outside the viewport, losing focus, stopping/restarting PIE or replacing the view target clears capture and pending deltas; returning focus never resumes a stale drag.

  3. AC 3

    Orbit sensitivity/inversion/limits and smoothing are adjustable and persistent through the same Unreal UI controls. Invalid settings use T01 validation and produce no invalid camera transform.

Actions

  1. At overview, close view and intermediate zoom, hold middle mouse and drag horizontally/vertically to both pitch limits, reverse direction, then release. Repeat stationary and on axial/diagonal routes while scrolling.
  2. Repeat wheel/drag over the consuming UI fixture. Press in the viewport then release outside it, alt-tab away while held, replace the fixture view target and stop/restart PIE. Verify no stale drag on return.
  3. Tune sensitivity/inversion/limits/smoothing in Unreal UI, save/reopen and repeat while comparing independent route/facing/aim observations.

Expected results

  1. Yaw/pitch respond only to valid held world input; limits, release and capture cleanup work in every view. Route/facing/aim remain independent and no world-camera action leaks through UI capture.

Reset

  1. Stop only the owned PIE/standalone session. Restore the reference configuration preset through Unreal UI, reset the scene-owned route/lighting/authorization/pointer fixtures and clear pending orbit/zoom/preview input. Reload the reference level and repeat a clean run.
  2. Retain failed and successful captures in bounded task outputs under GAME_ROOT/artifacts with revision/settings identities. Preserve other editor sessions, prior evidence, user assets and build caches; no project copies, worktrees, cache deletion or unrelated asset resaves.

Completion evidence and blockers

Required evidence: Retain input/capture lifecycle regressions, camera and independent route/aim observations, Unreal UI tuning screenshots and rendered orbit/scroll/release recordings. Verify camera-only input emits no gameplay mutation request; this does not certify connected input admission.

Blockers: None recorded; see dependencies.

Recorded evidence: None. Planning does not establish an executed pass.
