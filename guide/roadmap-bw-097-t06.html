Implementation scope

  • Reuse assessment: Implemented and verified — tools/validate.py, native automation/stage attribution, FRuntimeFixtureEvidence/FContentCompatibilityRun and existing package failure/isolation controls. Extend appropriate owners for this feature; retain unexecuted-versus-executed evidence semantics. BW-003 local probe timings/serialized payload bytes are not GPU frame timings or network traffic measurements.
  • Reuse assessment: Provided by Unreal or a plugin — native profiling/capture and packaging facilities. Use Unreal CPU/GPU frame and memory tools with actual rendering on the declared host; verify profiling availability before selecting a capture route. Record warmup/sample durations, workload/actor counts, resolution/backing scale, VSync/frame cap, quality and exact settings identities. Capture CPU/GPU frame-time percentiles and memory separately, including camera/transition/orbit and representative occlusion/effect cost.
  • Integrate only cross-boundary evidence from T01-T05: two independent resets/launches on each declared supported reference configuration, actual built/cooked level and assets, still/motion comparisons and a six-criterion parent review. The existing check_baseline.py package command hard-codes /Engine/Maps/Entry; add the smallest explicit reference-level cook/launch option to the existing tooling while preserving its default and server baseline. Record successful commands and hashes. Do not call the ordinary Entry package proof of the new level.
  • Compare results to T01 recorded reference budgets, retain failed measurements/mitigations and state supported camera/display/quality decisions with reproducible Unreal UI preset paths. Do not move thresholds after observing a failure without a recorded decision and rerun. No new canonical camera/performance schema applies; reuse TestCheck/FixtureRunEvidence only for their actual meanings and keep raw visual/profiling artifacts separate.
  • Add the focused feature regressions to the existing game FAST/FULL routes, including load/build/runtime failure distinctions, settings/configuration identity, rendered versus NullRHI limitations and normal Game/Server fixture-control isolation. Reuse unchanged prerequisite evidence and feature-owned tests rather than creating a parallel aggregate suite. Confirm BW-098 can consume the resulting reference assets/settings/evidence, while 30-player/legal-summon combat, full environments and release workloads remain later certification.

Out of scope

  • Production asset pipeline, 30-player gameplay/server capacity, live replication/privacy certification, Shipping/other platforms, full environment production and release performance/accessibility approval.

    Raw measurements report CPU/GPU frame-time percentiles and memory with sampling/workload/hardware/display/quality settings and compare them against the predeclared budgets. Failures retain mitigations and retested outcomes; supported and unverified configurations are explicit. All camera/visual adjustments needed to reproduce the result are accessible through documented Unreal UI.

  3. AC 3

    Current game default FULL and applicable manual evidence pass without weakening Entry/server/bootstrap/security gates. Normal packages expose no usable reference fixture controls. A parent review maps passing evidence to all six BW-097 criteria and preserves prerequisite/dependent statuses truthfully; no live gameplay or release-capacity claim is inferred.
