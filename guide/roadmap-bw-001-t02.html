Complete · Parent epic: BW-001 · Reproducible client and headless project

Epic acceptance criteria: BW-001-AC-1

Implementation scope

  • Create the project main/bootstrap scene and a separate res://scenes/client/client_shell.tscn using a Control root, a visible Briarwake client baseline label and a Quit button. There is no existing test scene to reuse.
  • Add tools/run_baseline.py --role client, resolving the pinned engine and importing a clean project as needed. Keep role selection before scene instantiation so the server ticket can choose a separate root.
  • Provide macOS editor/F6 and command-line instructions, and ensure the baseline uses the recorded provisional client renderer settings.

Out of scope

  • Character creation, login, network connection, local gameplay player, world content, renderer/camera acceptance or visual polish.
  • Packaged application exports, server startup or configuration validation; these follow in separate tickets.

Dependencies

Hard prerequisites: BW-001-T01

Acceptance criteria

  1. AC 1

    The project has a valid main scene and the client launch command opens a visible macOS window displaying Briarwake client baseline without script/import errors.

  2. AC 2

    Quit and the macOS window close action both end the process cleanly with a zero exit status.

  3. AC 3

    The client shell is isolated in its own scene and does not instantiate gameplay entities or server services.

Manual verification

Run from the Briarwake implementation repository. The commands, scenes and fixtures below are deliverables of this ticket and its prerequisites; these are unexecuted test instructions.

Launch command or scene

Working directory: /Users/le-evanmcpheron/Documents/Godot/briarwake (or the root of a disposable clean copy).
python3 tools/verify_toolchain.py
python3 tools/run_baseline.py --role client
Optional acquired engine: python3 tools/run_baseline.py --role client --engine "/path/to/Godot.app/Contents/MacOS/Godot"

Project main scene: res://scenes/bootstrap.tscn
Independent F6 scene: res://scenes/client/client_shell.tscn

Setup

  1. Complete BW-001-T01 and follow tools/README.md to verify the locked official engine on native macOS ARM64. Use a normal desktop Terminal session with graphics, user-settings and certificate access.
  2. For clean-import evidence, create a new disposable copy of the current project including the uncommitted T02 files, excluding .git, .godot and __pycache__. Do not delete or overwrite an existing cache. Run from that copy, verify .godot is initially absent and retain its absolute path.
  3. No gameplay fixture, credentials, network service, local player or exported application is required. The scene itself contains all UI controls used in this test.

Actions

  1. Run the launcher from the clean copy. Capture the visible baseline window and preserve complete console output. Confirm the first headless editor import finishes without ERROR or SCRIPT ERROR diagnostics, followed by a graphical client using the unchanged provisional Forward Plus settings.
  2. Confirm the label reads Briarwake client baseline and a Quit button is visible. Click Quit; preserve the printed Baseline client exited with status 0. and terminal return.
  3. Run the launcher again. Close the graphical window using its red macOS close control; preserve the same zero exit result and terminal return. Confirm neither test leaves a client process running.
  4. Open scenes/client/client_shell.tscn in the pinned editor and use Run Current Scene (F6, or Fn+F6); confirm the independent shell displays and Quit stops it without errors. Use F5 to check the main bootstrap default client role.
  5. Inspect the isolated client shell scene tree: Control root, CenterContainer, VBoxContainer, Label and Button only, with no gameplay entity or server service. Record tested game HEAD plus uncommitted file hashes when applicable.

Expected results

  1. Clean import and every desktop launch show the label and Quit control without missing-main-scene, script or import errors. Renderer/backend remain the provisional T01 baseline; this does not certify renderer feasibility.
  2. Quit and native red close both end the launcher/client with exit 0. F6 runs the shell independently; F5 defaults to client before loading it.
  3. Unsupported roles and malformed bootstrap arguments fail before shell instantiation. Import diagnostics cause the launcher to exit nonzero without starting a graphical process; a restricted-session failure is not passing graphical evidence.

Reset

  1. Close only the test window/editor and stop any leftover test process you started. No gameplay or fixture state needs resetting.
  2. Remove only the disposable test copy created for this procedure. Preserve the original checkout, .godot cache, canonical toolchain lock, installed engine/templates and all user files.
