Epic acceptance criteria: BW-002-AC-1

Implementation scope

  • Create a versioned responsibility map in the game repository ordinary documentation. For movement/collision, combat/resources/cooldowns, durable assets/currency, applied talent builds and client presentation, name the documented authority, creation/update/teardown lifecycle, command input, safe projection, transfer/reconnect/crash boundary and existing implementation owner or explicit missing owner. Link canonical contracts instead of copying their definitions.
  • Reuse FServerConfiguration for startup settings and module startup/shutdown for existing bootstrap lifecycle. Mark production gameplay/world session, transactional asset/build and presentation owners as missing. Review the unfinished FContentAdmission/FContentContracts drafts as candidate admission owners only; neither they nor MultiplayerSessions establish the missing gameplay services.
  • Preserve one world owner epoch, transactional durable ownership and build revisions, no client-authored outcomes, prediction/presentation without authority, no build-triggered cooldown/resource/debt reset, and independently filtered public/owner/server projections. Record the exact inspected source revision and read-only draft observations separately from executed evidence.

Out of scope

  • Implementing movement, combat, authentication, database transactions, build application, replication, reconnect/transfer or a new general service framework.
  • Redefining schemas, implying a schema needs its own UObject, or promoting a boundary document into tested gameplay authority.

Dependencies

Hard prerequisites: None

Acceptance criteria

  1. AC 1

    Every one of the five AC1 domains has a named authority and lifecycle, trusted/untrusted inputs, projection audience and implementation location or explicit missing owner; no ownership is assigned to a widget or transport callback by accident.

  2. AC 2

    The review traces identity/epoch, durable item/wallet and build invariants to canonical definitions and distinguishes missing future implementations from current native bootstrap and unfinished admission drafts.

  3. AC 3

    Public EntitySnapshot/PublicCombatResult, owner-only ReconnectSnapshot and server-only internal results/checkpoints are distinguished, including hidden-source redaction and authorization-loss removal. No duplicate writable truth is proposed.
