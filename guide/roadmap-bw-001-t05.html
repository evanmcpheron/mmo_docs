Complete · Parent epic: BW-001 · Reproducible client and headless project

Epic acceptance criteria: BW-001-AC-1, BW-001-AC-2

Implementation scope

  • Add versioned macOS Client and macOS Dedicated Server export presets using the T01 engine/templates and recorded CPU architecture. Keep the dedicated role, feature flags/resource stripping and external configuration distinct from client rendering settings.
  • Add tools/build_baseline.py --clean --output artifacts/baseline to import and export both artifacts from the current checkout without relying on cached .godot state, editor-local presets or undeclared files. Cleaning is restricted to the designated build output and disposable import workspace.
  • Embed source build identity and package identifiers at build time; emit an artifact manifest with toolchain lock, source revision/dirty state, target, preset, engine/templates, artifact paths and SHA-256 hashes. Keep rules/content fixture revisions separate and traceable.
  • Extend tools/run_baseline.py with --artifact-dir so it launches each exported artifact from outside the editor/source resource path. The exported headless server accepts an external config and supports the existing bounded smoke command; neither artifact needs a locally installed Godot executable at runtime.
  • Document macOS local launch steps, provisional renderer/backend and the current platform boundary. Future Linux/Windows presets must be added and executed before support is claimed.

Out of scope

  • Linux/Windows build verification, universal binaries, cross-compilation, store packaging, release signing/notarization or deployment.
  • Pixel-identical rendering, byte-identical signed bundles or gameplay/content compatibility claims.

Dependencies

Hard prerequisites: BW-001-T04

Acceptance criteria

  1. AC 1

    A clean checkout with only the documented toolchain and prerequisites produces both macOS artifacts and the manifest using one build command.

  2. AC 2

    The exported client opens the baseline window and quits cleanly from a working directory outside the source tree.

  3. AC 3

    The exported server runs headlessly without a local player, loads the external valid fixture, reports embedded build plus rules/content revisions and passes the bounded bootstrap smoke test.

  4. AC 4

    Repeating from another clean/disposable checkout succeeds without copying import caches or local export settings; each run records its actual artifact hashes and any declared nondeterministic packaging metadata.

Setup

  1. Complete T04. Use native ARM64 Python 3.10+ on macOS with the checksum/version-verified Godot 4.7.2 engine and matching templates from tools/toolchain.lock.json. tools/README.md documents acquisition, optional --engine/--templates paths, /usr/bin/arch and /usr/bin/lipo. Use a desktop session for visible client checks.
  2. Use versioned export_presets.cfg. The build creates its own disposable project/import cache and derives an architecture-named ARM64 release template from the locked universal executable; it never changes installed templates. No scene, player, network, database or credentials are required.
  3. Make a second disposable copy including Git metadata and current implementation edits, excluding .godot, artifacts and __pycache__. Confirm .godot is absent. Preserve each build manifest/log before any --clean reuse.
  4. For runtime independence, create an empty owned directory under /private/tmp, copy server.valid.json outside the checkout, and invoke the absolute Python/launcher/artifact/config paths from that external directory with PATH set to the empty directory. Keep the desktop session available.

Actions

  1. Run the clean build command in each checkout. Retain manifest.json, logs/import.log, logs/export-client.log and logs/export-server.log. Compare source_files/source_manifest_sha256 and record each actual bundle/file hash. Confirm both import_cache_initially_absent values and Passed build statuses.
  2. Launch each exported client from the external working directory with the empty PATH. Observe Briarwake client baseline and Quit; capture the window. Activate Quit for one run (Tab then Return works), and the native macOS close button for the other. Preserve launcher output and exit statuses.
  3. Launch each exported server with the external valid fixture and --smoke. Compare baseline-build to its manifest, including build_revision, source fingerprint, package ID and dedicated_server. Confirm the server-ready rules/content labels match the external fixture.
  4. Directly run BriarwakeServer.app/Contents/MacOS/Briarwake --headless -- --config /absolute/path/server.valid.json --smoke to check its default dedicated role and absence of a Python/editor runtime requirement. Change rules_version or content_version in isolated external copies and confirm build identity remains unchanged.
  5. Run the exported server with omitted/removed/invalid configuration and with --build-revision or --role client overrides after --. Each must exit nonzero without server-ready/heartbeat/smoke success. Run the output safety unittest command and the existing --test-config source suite as regression checks.

Expected results

  1. Both clean builds exit 0 with macOS ARM64 client/server applications and complete manifests. Source inputs match; bundle hashes may differ through declared generated metadata. No cached imports, local export presets or undeclared resources are copied.
  2. Both clients visibly display the baseline using provisional Forward Plus/default macOS backend and exit 0 through the two close paths. Artifact launches do not invoke installed Godot or use source --path resources.
  3. Each headless server reports its embedded build/package identity and separate external rules/content versions, headless/Dummy drivers, exactly ServerRoot and its timer, no loaded client scene, zero local players, three heartbeat iterations, then Passed server-smoke and exit 0. Smoke runtime is bounded to ten seconds.
  4. Rejected startup arguments/configurations exit 2 before readiness. Source configuration regression and seven cleanup safety tests pass. --clean refuses modified/unknown/unowned/symlinked outputs; it replaces only unchanged inventoried output. Logs preserve any failed build instead of reporting a runtime pass.
  5. Only local native macOS ARM64 execution is established. Release signing/notarization, other platforms, T06 credential inspection, T07 failure-case automation and gameplay remain outside this ticket.

Reset

  1. Close only test clients and stop owned server processes. PATH changes apply only to test subprocesses; preserve the shell environment.
  2. Retain evidence under mmo_docs/validation/tickets/BW-001-T05, then remove only disposable checkout/runtime/config directories created for the test. Keep source artifacts/baseline for review, or use --clean only after preserving evidence. Preserve installed toolchain, original .godot state, canonical fixtures and user files.
