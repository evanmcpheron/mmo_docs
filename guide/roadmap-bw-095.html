Objective and scope

Make documented content producible and reviewable through the same contracts used by runtime admission.

Scope: Versioned editors or importers for abilities, statuses, talents, items, recipes, NPC kits, loot tables and encounter triggers, with world/tutorial relationships. A bounded import/export route is sufficient; full content authoring and gameplay handlers remain with feature epics. Render-source asset conventions and production validation extend this route in BW-098.

Acceptance criteria

  1. AC 1

    Representative records from each declared authoring family round-trip from reviewed source through validation/export to package admission with stable IDs, versions and traceable findings; later enabled families extend the same route.

  2. AC 2

    Invalid references, target/resource fields, caps, exclusive choices, progression relationships and required binding/presentation references produce actionable record-level findings and cannot partially publish an enabled package.

  3. AC 3

    The same reviewed source produces a reproducible package and fixture manifest for client/server use; unbound records remain disabled and authoring or schema validation never promotes runtime-test evidence to passed.

  4. AC 4

    An accepted content edit and a rejected edit demonstrate reviewable differences, retained prior valid output and compatibility with the canonical schema bundle; no parallel authoritative contract is introduced.

Verification and blockers

Completion evidence required: Executed author/import/validate/export/admit examples, invalid-content diagnostics, reproducible package identifiers and a reviewable fixture manifest; this proves tooling, not completed gameplay content.

Recorded evidence: None. Required evidence above describes future verification.

Blockers: None recorded; see hard prerequisites.
