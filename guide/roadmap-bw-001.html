Phase: 1. Executable boundaries and risk probes · Completion milestone: Executable ownership proof

Objective and scope

Prepare and create the first native C++ Unreal Engine 5 project with reproducible client and dedicated-server execution from zero.

Scope: Install and verify the required Unreal Engine 5 editor, native C++ compiler/toolchain and build prerequisites; select a tested engine revision; create a new C++ project and its separate game repository; configure client and dedicated-server build targets, versioned settings and foundational smoke tests. No existing project, servers or plugins are assumed. The owner selected evanmcpheron/BriarwakeUnreal for the implementation and requested inclusion of its supplied engineering docs and MultiplayerSessions Steam plugin. Bootstrap uses the canonical ServerConfiguration contract; Steam account/session behavior and gameplay remain outside this baseline.

Acceptance criteria

  1. AC 1

    On a documented clean machine, the developer can install the required engine and native C++ toolchain, create a fresh C++ Unreal project in an explicitly chosen separate repository, pin the tested engine revision, and produce launchable client and dedicated-server targets using recorded build, cook and package steps.

  2. AC 2

    The compiled dedicated server starts without rendering or a local player and reports its executable, engine, rules and content revisions; the client can be launched separately.

  3. AC 3

    Missing required configuration fails with an actionable diagnostic; credentials are absent from distributed client artifacts.

  4. AC 4

    A clean automated run distinguishes build failure from an executed passing or failing runtime check.

Verification and blockers

Completion evidence required: Versioned native project/repository, pinned engine and toolchain identities, clean C++ client/server build and package logs, exact artifact hashes, actual client launch and headless-server smoke, configuration rejection, credential inspection and distinct automated failure controls.

Recorded evidence:

  • Historical AC4 execution at the initial native revision: fresh C++ snapshot builds and two registered Unreal tests distinguish a pass, real compilation failure with runtime Not Executed, executed assertion failure, bounded timeout with no assertion pass, and independent recovery. Nine Python regressions passed at that revision.
