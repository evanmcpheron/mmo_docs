BW-001-T04 · Reject missing or invalid bootstrap configuration

Not Started · Parent epic: BW-001 · Reproducible client and headless project

Epic acceptance criteria: BW-001-AC-3

Implementation scope

  • Load server configuration from an explicit external --config path and validate it before reporting ready. Reuse canonical ServerConfiguration field names, requiredness and types; apply documented bootstrap semantic checks and identify missing/empty revision values explicitly.
  • Add fixtures/config/server.missing-rules.json and server.invalid-rate.json derived from the valid fixture, plus instructions for a nonexistent path and malformed JSON. Keep test-only parameter choices labeled as fixtures, rather than gameplay policy defaults.
  • Return nonzero on missing files, malformed JSON, missing required keys or invalid bootstrap values. Diagnostics identify the path/key, expected correction and startup stage while avoiding full configuration dumps or secret values.
  • Extend the launcher with an isolated configuration test path so negative cases cannot accidentally fall back to a developer-local configuration. Only valid configuration can reach the server-ready state.

Out of scope

  • Authentication-provider, database, economy or SecurityPolicy configuration for endpoints that do not exist yet.
  • Hot reload, remote config services, gameplay defaults, content admission or client-artifact inspection.

Dependencies

Hard prerequisites: BW-001-T03

Acceptance criteria

  1. AC 1

    The valid committed fixture reaches readiness and completes the existing headless smoke check.

  2. AC 2

    A nonexistent file, malformed JSON, absent rules_version and invalid simulation_hz each produce a nonzero exit, an actionable path/key diagnostic and no server-ready record.

  3. AC 3

    Removing required external configuration cannot silently substitute a developer file or packaged default.

  4. AC 4

    An unexpected field containing a synthetic secret marker is rejected without printing its value or a full configuration dump.

Manual verification

Run from the Briarwake implementation repository. The commands, scenes and fixtures below are deliverables of this ticket and its prerequisites; these are unexecuted test instructions.

Launch command or scene

python3 tools/run_baseline.py --role server --headless --config fixtures/config/server.valid.json --smoke
python3 tools/run_baseline.py --role server --headless --config fixtures/config/server.missing-rules.json --smoke
python3 tools/run_baseline.py --role server --headless --config fixtures/config/server.invalid-rate.json --smoke

Setup

  1. Complete T03. Use the supplied valid/missing-rules/invalid-rate fixtures.
  2. In an owned temporary directory, create a malformed JSON file and a valid-fixture copy with an unexpected secret_marker field containing a harmless unique sentinel. Also choose a file path that does not exist.

Actions

  1. Run each supplied fixture, then repeat the command against the malformed file, nonexistent file and secret-marker copy.
  2. Record exit statuses and search stdout/stderr for server-ready and the synthetic marker value.

Expected results

  1. Only the valid fixture reaches ready and exits zero.
  2. Every invalid case fails with its stage and correction; no ready record appears, and the synthetic secret value is absent from output.

Reset

  1. Delete temporary fixture files and logs containing test inputs; keep the committed fixtures intact. Stop any process that exceeded the documented timeout.

Completion evidence and blockers

Required evidence: Captured valid/negative startup results with exit statuses, redacted diagnostics and proof that invalid configuration never reaches readiness.

Blockers: None recorded; see dependencies.

Recorded evidence: None. Planning does not establish an executed pass.
