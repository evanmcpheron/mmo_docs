BW-001-T04 · Reject missing or invalid bootstrap configuration

Complete · Parent epic: BW-001 · Reproducible client and headless project

Epic acceptance criteria: BW-001-AC-3

Implementation scope

  • Load server configuration from an explicit external --config path and validate it before reporting ready. Reuse canonical ServerConfiguration field names, requiredness and types; apply documented bootstrap semantic checks and identify missing/empty revision values explicitly.
  • Add fixtures/config/server.missing-rules.json and server.invalid-rate.json derived from the valid fixture, plus instructions for a nonexistent path and malformed JSON. Keep test-only parameter choices labeled as fixtures, rather than gameplay policy defaults.
  • Return nonzero on missing files, malformed JSON, missing required keys or invalid bootstrap values. Diagnostics identify the path/key, expected correction and startup stage while avoiding full configuration dumps or secret values.
  • Extend the launcher with an isolated configuration test path so negative cases cannot accidentally fall back to a developer-local configuration. Only valid configuration can reach the server-ready state.

Out of scope

  • Authentication-provider, database, economy or SecurityPolicy configuration for endpoints that do not exist yet.
  • Hot reload, remote config services, gameplay defaults, content admission or client-artifact inspection.

Dependencies

Hard prerequisites: BW-001-T03

Acceptance criteria

  1. AC 1

    The valid committed fixture reaches readiness and completes the existing headless smoke check.

  2. AC 2

    A nonexistent file, malformed JSON, absent rules_version and invalid simulation_hz each produce a nonzero exit, an actionable path/key diagnostic and no server-ready record.

  3. AC 3

    Removing required external configuration cannot silently substitute a developer file or packaged default.

  4. AC 4

    An unexpected field containing a synthetic secret marker is rejected without printing its value or a full configuration dump.

Manual verification

Run from the Briarwake implementation repository. The commands, scenes and fixtures below are deliverables of this ticket and its prerequisites; these are unexecuted test instructions.

Launch command or scene

python3 tools/run_baseline.py --role server --headless --test-config
python3 tools/run_baseline.py --role server --headless --config fixtures/config/server.valid.json --smoke
python3 tools/run_baseline.py --role server --headless --config fixtures/config/server.missing-rules.json --smoke
python3 tools/run_baseline.py --role server --headless --config fixtures/config/server.invalid-rate.json --smoke
python3 tools/run_baseline.py --role server --headless --smoke

Setup

  1. Working directory: the briarwake repository root beside mmo_docs. Complete BW-001-T03 and use the locked official Godot 4.7.2 engine, native macOS ARM64 and Python 3.10+ in a normal local session with Godot settings/certificate access. No network listener, credentials, database or client is required.
  2. The three committed fixtures contain test-only values, not gameplay defaults. The --test-config mode creates isolated temporary copies and negative cases; it cannot be combined with --config or --smoke. Append --engine /absolute/path/to/Godot when using an isolated locked installation.
  3. Optionally append --test-report /absolute/path/in/an/owned/temporary/directory/configuration-checks.json to the suite command. Capture terminal stdout/stderr separately to retain engine verification and editor import diagnostics. Preserve existing evidence files.
  4. For individually inspected malformed/nonexistent/secret cases, run the exact temporary-file Python procedure under tools/README.md, Validate external server configuration (BW-001-T04). It creates malformed JSON containing a synthetic marker, a valid-fixture copy with an unexpected secret_marker field and a nonexistent path.

Actions

  1. Run the suite command. It launches the actual server for valid smoke checks, missing/removed files, malformed JSON, absent/null/wrong-type/empty fields, nonpositive or nonfinite rates, invalid durations, unknown fields and synthetic-secret redaction. It also invokes the bootstrap with no configuration and with res:// and user:// paths.
  2. Run the three individual fixture commands and the final command without --config. Record exit statuses and inspect stdout/stderr for the startup stage, path, known key, correction and server-ready.
  3. Run the manual temporary-file procedure and confirm each output reports exit 2, ready: False and secret leaked: False. Synthetic markers must be absent from captured stdout/stderr. The suite report records exact runtime commands, exit statuses, logs, assertions, environment and source identity.

Expected results

  1. The suite exits 0 only after all expected outcomes pass; valid fixtures reach server-ready, execute exactly three heartbeats and emit a Passed server-smoke record. The fractional-rate/zero-duration boundary fixture is accepted.
  2. Individual valid configuration exits 0. Missing rules_version and zero simulation_hz exit 2 at configuration validation with an actionable absolute path/key diagnostic. Missing files identify the read stage; malformed JSON identifies the parse stage and line without echoing input. Unknown fields list allowed keys without printing untrusted names or values.
  3. Every rejected runtime case exits 2 before any server-ready, heartbeat or smoke record. No external configuration is substituted. Omitted --config exits 2 at launcher argument validation before Godot runs. No full configuration dump or synthetic secret value appears.
  4. The launcher bounds each smoke runtime to 10 seconds; import is bounded to 120 seconds. Failed import/toolchain checks do not count as executed runtime passes. Suite failures exit 1 and identify the failing case.

Reset

  1. Temporary suite/manual configuration files are removed automatically. Remove only owned optional report/log files when no longer needed; keep committed fixtures and retained ticket evidence intact.
  2. No gameplay state is written. Stop only owned test processes if an outer runner is interrupted; preserve installed engine/templates, the project cache and existing checkout changes.

Completion evidence and blockers

Required evidence: Captured valid/negative startup results with exit statuses, redacted diagnostics and proof that invalid configuration never reaches readiness.

Blockers: None recorded; see dependencies.

  • Executed 60 isolated configuration runtime cases on pinned Godot 4.7.2/native macOS ARM64: valid smoke readiness; missing/malformed/removed configuration, required-field/type/range rejection, no implicit default and synthetic-secret redaction. Individual launcher, argument-gate, GDScript parse, schema and reload-state checks passed. Previous source admitted the zero-rate regression control. Companion logs retain engine/import evidence; one auxiliary test-generation failure is retained and superseded by a passing corrected probe.
