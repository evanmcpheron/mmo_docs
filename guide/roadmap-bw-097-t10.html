Implementation scope

  • Add --case profile and a documented isolated prototype export/replay path to the existing rendering launcher. Reuse tools/build_baseline.py staging/provenance helpers where applicable, but supply a dedicated disposable prototype export preset/staging layout because normal exports intentionally exclude tests. Do not weaken normal client/server content or credential exclusions to package the probe.
  • Package the same source scene, fixtures, shaders and versioned settings with pinned export templates. Reproduce the accepted cases from a fresh source snapshot and the graphical package, recording source/asset/settings hashes, engine/export revision, actual renderer/backend, hardware/OS and commands. Preserve existing source client/headless smoke behavior and test-input exclusion.
  • Collect attributable raw CPU/GPU frame times and memory at declared resolutions/settings for stationary/motion and incremental outline, lighting, foliage/transparency, water, contact and combined workloads. Declare warm-up/sample counts, repeats, timing source/units and percentile method; record draw calls/overdraw when measurable. GPU timing unavailability is an evidence gap, never inferred from FPS or CPU samples.
  • Review results against T03-approved prototype budgets and the completed visual matrix. Record chosen defaults, tested fallback support, platform exclusions and all remaining findings. An unmet stock-engine requirement requires a documented implementation/maintenance decision with measured evidence before a fork is adopted; no engine patch or platform exclusion is silently assumed.
  • Perform explicit epic review mapping retained evidence to all nine exact criteria and hard prerequisites. FixtureRunEvidence/TestCheck remain automated execution records, not substitutes for human appearance approval. Keep canonical records compatible through the existing extraction; record reproducibility and measurement envelopes as tool-local data, without creating a new gameplay schema. Update relevant tracking/generated views only when real evidence supports their status.

Out of scope

  • A completed production renderer, full art roster/environment pipeline, connected-client/load/capacity certification, new platform support, automatic engine upgrades or automatic approval of visual deviations.

Dependencies

Hard prerequisites: BW-097-T09

Acceptance criteria

  1. AC 1

    A fresh source snapshot and independently launched packaged prototype reproduce the accepted scene/settings and relevant still/motion/fallback matrix with matching attributable identities. Packaging does not expose server/test data through the ordinary client or break the existing headless baseline.

  2. AC 2

    Raw CPU/GPU frame-time and memory reports identify settings/hardware, warm-up, sample count, repeats, units, percentile calculation and incremental/combined costs. Approved budgets are met or revised through explicit review; missing measurements or failed budgets cannot be labeled a pass.

  3. AC 3

    The implementation decision records selected renderer/backend/camera/material/pass defaults, tested fallbacks, visual acceptance and platform limits, plus any justified custom-engine maintenance decision. Every blocking finding is resolved before epic acceptance.

  4. AC 4

    The final review maps all nine epic criteria to actual package/capture/measurement/review artifacts, confirms BW-001/BW-003 evidence still applies, preserves historical failures and makes no gameplay or production-capacity claim.

Setup

  1. Use pinned engine/templates, approved T03 budgets and all T09 accepted settings/captures. This ticket supplies prototype export/replay commands and staging assets; start from a fresh snapshot without relying on an existing import cache.
  2. Use the same declared graphics hardware for comparable profiling and available engine/platform GPU profiling support. Record unavailable measurements as gaps requiring resolution, not successful verification.

Actions

  1. Run profile through the documented warm-up/sample/repeat procedure for baseline, individual effects, combined motion and fallbacks. Inspect raw samples and independently recompute reported percentiles.
  2. Follow the supplied isolated export instructions, launch the produced graphical package, and replay the accepted cases. Run the existing baseline/content/runtime and normal-client exclusion checks appropriate to any shared tooling changed; retain the commands/results.
  3. Review package reproducibility, visual findings, budgets, platform/fork choices and each epic criterion with the user. Recheck prerequisite evidence applicability and regenerate tracking only for behavior actually accepted.

Expected results

  1. The package reproduces the approved source scene/settings; normal exports/headless behavior remain valid and their exclusions remain enforced.
  2. Measured costs and approved decisions support each chosen default/fallback with no missing GPU/memory evidence or unresolved visual blockers. The explicit epic review alone determines readiness for BW-098, without claiming production rendering or gameplay completion.

Reset

  1. Use the probe Reset control to restore the checked-in case settings, camera, actor path and effect toggles; quit the graphical process normally. No persistent gameplay state is created.
  2. Keep prior captures, failed results and reports intact. Repeat into a fresh launcher-owned artifacts directory; restore only deliberately modified disposable inputs, leaving source assets, canonical registries and existing user files intact.

Completion evidence and blockers

Required evidence: Retain reproducible source/export manifests and commands, package hashes, source-versus-package captures, raw CPU/GPU/memory samples and percentiles, fallback/capability matrix, prerequisite/regression evidence and dated defaults/visual/maintenance decisions with exact nine-criterion epic review.

Blockers: None recorded; see dependencies.

Recorded evidence: None. Planning does not establish an executed pass.
