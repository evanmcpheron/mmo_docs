In Progress · Parent epic: BW-097 · 3D pixel-art renderer and camera feasibility proof

Epic acceptance criteria: BW-097-AC-3

Implementation scope

  • Add --case camera to the same viewport/camera owner, with visual camera-grid alignment plus residual screen correction or a measured equivalent. Keep unrounded fixture foot-anchor motion separate from presentation transforms; do not modify physics, collision, aim, WorldPoint scope or simulation state.
  • Supply repeatable stationary, slow axis-aligned, diagonal, pixel-boundary-crossing and moving-actor paths with restart, pause, single-frame stepping, unsnapped comparison and capture controls. Log source anchor samples, visual camera transform, correction and frame/time indices so a reviewer can attribute shimmer/jitter rather than inspecting a single still.
  • Review continuous frame sequences against T03 bounds at every approved zoom/window preset. Include actor-only motion, stationary scenery, tracking reversals and resize transitions; apply the same screen correction consistently to the world image. Pointer-to-world gameplay picking remains a later feature, with the mapping boundary documented for reuse.

Out of scope

  • Authoritative movement, network prediction/reconciliation, production camera control or ground-cast picking. No duplicate WorldPoint or eight-direction movement implementation.

Dependencies

Hard prerequisites: BW-097-T03

Acceptance criteria

  1. AC 1

    Repeatable still and motion sequences show the chosen alignment/correction method preserves tracking continuity and accepted pixel stability for stationary, slow and diagonal cases at the declared settings.

  2. AC 2

    Recorded finite continuous WorldPoint-compatible fixture anchors are identical with visual correction enabled/disabled; correction neither quantizes actor simulation nor changes floor/zone/instance identity.

  3. AC 3

    Frame stepping and time-indexed diagnostics reproduce boundary crossings and reversals. Crawl, shimmer, jitter or resize discontinuities beyond T03 bounds remain blocking findings with retained failing sequences.

Manual verification

Run from the Briarwake implementation repository. The commands, scenes and fixtures below are deliverables of this ticket and its prerequisites; these are unexecuted test instructions.

Launch command or scene

Working directory: GAME_ROOT (briarwake/). The pinned macOS graphical desktop and matching local Titan exports are required.
python3 tools/verify_toolchain.py
python3 tools/run_rendering_probe.py --case camera
For interactive inspection after the automatic first-window/zoom smoke run:
python3 tools/run_rendering_probe.py --case camera --camera-profile smoke --interactive

Setup

  1. Use the approved T03 Titan courtyard, 9m normal / 4.5m diagnostic view, focus height 1m and T02 five window presets with actual native display scale. Missing/changed exports fail; tools/export_titan_reference.py recreates the existing bounded local exports without modifying the source sample.
  2. The default full profile runs all 140 paired sequences (8,960 consecutive source samples). Smoke covers one window/zoom and cannot establish full acceptance. Capture filenames, source hashes, engine/device/backend, exact scope/anchors and actual projection/time indices are in run.json.

Actions

  1. Open the launcher output review.html offline. Play and step every corrected/unsnapped pair for stationary, slow-axis, diagonal, boundary, reversal, actor-only and resize. Review frames 0–63; 63 to 0 is a restart and carries no continuity claim.
  2. In the interactive window select a path/window/zoom, toggle Grid + residual, Play/Pause, Step, Restart and Capture. Step pauses and advances exactly one 1/30s source sample. Capture pauses and writes internal/native output images plus a JSON observation. Resize the real window, including below/at the 640x480 logical minimum.
  3. Compare the whole-world residual with logged camera transforms and projected origin/actor. Every sample must retain identical finite WorldPoint-compatible source anchors with correction enabled/disabled. The upper-floor fixture identity remains unchanged; only the first local fixture actor moves.
  4. Exercise invalid-settings, missing-report and check-failure controls using --camera-profile smoke for runtime controls; expect nonzero exit and retained diagnostics. Follow with a fresh full run.

Expected results

  1. The guarded 386x218 render crops to the approved visible 384x216 field with unchanged units per pixel; nearest integer blocks, residual correction and native HUD remain consistent through resize/zoom. Every actual framebuffer world pixel equals the expected guarded presentation.
  2. Actual source anchor logs remain continuous and fully scoped while visual camera/actor alignment stays in presentation. Seeking/reversal repeats the same frame/time/anchor/camera/residual; no physics, collision, aim or network state is created.
  3. Stationary pixels remain identical outside the two approved normal-view scenery regions. The T04-only prototype deviation permits at most 2 RGB8 levels on at most 32 pixels inside those rectangles; compare both first-frame and adjacent samples. Close zoom retains exact identity. Any excess, outside-region change, silhouette shift, disappearance or timing/presentation failure blocks acceptance. See validation/tickets/BW-097-T04/deviation-approval.json.

Reset

  1. Reset restores frame zero, stationary/corrected, the first window and normal zoom. Quit normally. No persistent gameplay state is created.
  2. Repeat in a new launcher-owned output directory. Preserve prior logs and all failing sequences; original assets and canonical contracts remain unchanged.
