Complete · Parent epic: BW-002 · Authority boundaries and content admission

Epic acceptance criteria: BW-002-AC-5

Implementation scope

  • Extend the same staged admission path for VendorOfferDefinition, VendorPricingConfiguration, RecipeDefinition/RecipeIngredient, MaterialDefinition, ItemDefinition and SalvageRule with only their required canonical reference closure. Resolve item versus material namespaces explicitly; do not invent a mapping from display names.
  • Build a process-local view of the complete declared enabled vendor/crafting/conversion route set, including already admitted routes and the proposed additions. Include input/output quantities, explicit integer minor-unit NPC prices/sellback, eligible common-material salvage returns, and binding/access constraints relevant to guaranteed repeatability. This derived graph is not a second editable economy schema.
  • Reject unknown or missing required prices/quantities/relationships and unsupported route behavior with route/field findings before graph certification. A missing value is not zero; an explicit zero price remains a real value to analyze. Enforce SalvageRule limits: destroy original, at most 25% eligible original common materials, no rare/bound cores, gold or skill XP. Starter assistance cannot become tradable/exportable input.
  • Add --suite economy-data with fully authored synthetic canonical records and missing-value/bad-reference/bad-salvage cases. Fixture values exist only to prove admission and are not proposed production balance. Partial/unknown graph inputs keep affected routes disabled; later T07 proves the loop rule.
  • Approved canonical extension: content 2.2.1-design adds optional MaterialDefinition.item_definition_id/salvage_class and ItemDefinition.starter_assistance, preserving legacy records/IDs while economic staging requires explicit values. Fixtures and semantic checks include nonexportable starter crafting without cross-owner commissions.

Out of scope

  • Production price/recipe catalogs, live vendors/crafting/salvage, profession advancement handlers, wallets/transactions, player market prices or a general economic simulation.
  • Treating a complete graph as a loop pass, inventing undocumented conversion mechanics or enabling routes whose operational dependencies do not exist.

Dependencies

Hard prerequisites: BW-002-T04

Acceptance criteria

  1. AC 1

    The valid fixture produces a complete derived route view with every reference, quantity, price and salvage limit attributable to its canonical source record.

  2. AC 2

    A missing sellback/purchase input, unknown material/item relation, malformed quantity or unsupported route produces an explicit finding and cannot expose the route as admitted. Explicit zero-priced inputs remain distinguishable from missing values.

  3. AC 3

    Excess common-material return, rare/bound-core return and starter-assistance export examples fail their documented constraints. Prior admitted route state is unchanged on every rejection.

Manual verification

Run from the Briarwake implementation repository. The commands, scenes and fixtures below are deliverables of this ticket and its prerequisites; these are unexecuted test instructions.

Launch command or scene

Working directory: GAME_ROOT (briarwake/ repository root). No game scene or database is required; the checker executes the production RefCounted staging boundary in an isolated headless project.
python3 tools/verify_toolchain.py
python3 tools/extract_content_contracts.py --check
python3 tools/check_content_admission.py --suite economy-data --output /absolute/new/evidence-directory
python3 -m unittest discover -s tools -p 'test_*.py' -v

Setup

  1. Use the pinned native ARM64 macOS Godot 4.7.2 and Python environment in tools/toolchain.lock.json. Both game and mmo_docs PRs are required: the snapshot is extracted from the sibling canonical registry.
  2. Use fixtures/content_admission/economy-data.json unchanged. It includes complete synthetic item/material identity, explicit prices and repair fields, recipe/profession/faction/cooldown closure, salvage origins and a retained route context. All numerical inputs are test values, not balance proposals.

Actions

  1. Run the 57-case suite. Inspect run.json: the valid combined view has seven routes, including retained purchase/sellback and new purchase, two sellbacks, crafting and salvage, with canonical source paths and integer minor-unit prices.
  2. Compare explicit-zero-purchase and explicit-zero-sellback with missing price cases. Inspect namespace, malformed quantity, unsupported recraft/random/prose conversion, fractional/excess/rare/bound salvage, duplicate identity/return and starter export/commission diagnostics.
  3. Check every rejection has no candidate routes and prior_candidate_unchanged is true. The positive bound-starter case preserves the restriction without sellback, salvage or cross-owner commission.
  4. In fresh output paths, run --control import-failure, startup-failure, missing-report, assertion-failure and unsupported-schema; each must exit nonzero. False expectations execute and fail; startup/import failure is not execution. Run a clean suite again.

Expected results

  1. All 57 authored expectations execute successfully in the normal suite; candidate data and returned snapshots remain isolated and reversing catalog order preserves findings/routes.
  2. A missing value never becomes zero. Unknown references, unsupported routes, ineligible/excess salvage and starter export reject the whole proposed set without modifying retained state.
  3. Completeness alone supplies no loop certificate or active content. T07 graph certification, T08 actual startup publication and live economy/gameplay remain unimplemented.

Reset

  1. Let the bounded checker exit and remove its owned temporary project automatically. Use a fresh output directory for each run; no database/account/peers or bootstrap configuration is touched.
  2. Keep attributable run.json and logs under mmo_docs/validation/tickets/BW-002-T06/ for review. Do not overwrite fixture/canonical sources or earlier evidence.

Completion evidence and blockers

Required evidence: Executed complete/incomplete economic-input and salvage-constraint results, canonical fixture provenance and unchanged-active-route assertions.

Blockers: None recorded; see dependencies.

  • Executed 57-case pinned-engine economic input suite: complete attributable combined routes, explicit zero versus missing prices, reference/quantity/unsupported-route rejections, salvage and starter/commission constraints, snapshot isolation and unchanged prior routes. Full tooling/contract regressions are retained separately. Completeness does not claim loop freedom, activation or live economic execution. — AC 1, 2, 3; Passed; revision Exact initial/final game Git revisions, per-source/input SHA-256 manifests and final fetched main SHAs are retained in the verification report and linked run.json files.
