Epic acceptance criteria: BW-097-AC-1

Implementation scope

  • Reuse assessment: Implemented and verified — BW-001 native Editor/Game/source-Server bootstrap and BW-003 attributable test evidence, at the matching source identity recorded in manual setup. Extend those owners for this feature; do not rerun unchanged native prerequisites merely to author tickets.
  • Reuse assessment: Provided by Unreal or a plugin — UE 5.8.3 UCameraComponent, USpringArmComponent, APlayerCameraManager and Enhanced Input 1.0 are available. Config/DefaultInput.ini names EnhancedPlayerInput/EnhancedInputComponent and the engine plugin is enabled by default, but at decomposition the game module depended only on Core/CoreUObject/Engine plus private Json; T01 added private InputCore for fixture keys. Add only the camera/input/UI dependencies actually consumed. MultiplayerSessions 1.0 supplies session/menu code, not a gameplay camera or scene.
  • Reuse assessment: Missing — at decomposition, the project lacked a pawn/controller/camera owner, reference map, input actions and visual fixtures. T01 now supplies ReferenceCameraPawn, ReferenceCameraRig, ReferenceCameraConfiguration, ReferenceCameraGameMode/HUD and L_BW097_Reference; subsequent tickets reuse those owners. Create the smallest native presentation component wired explicitly to a controlled reference pawn/controller, a versioned reference level and scene-only stationary/axial/diagonal routes. Reinspect before implementation and reuse any owner introduced by intervening work. Fixture routes are not production movement and camera input cannot mutate their position, facing or aim.
  • Supply one validated editor-visible camera configuration with documented Unreal UI locations and units for every fine-tuning control: overview/close framing and focus offsets, orthographic width and perspective FOV, projection-transition policy/timing, follow smoothing, wheel step/rate, orbit sensitivity/inversion/pitch limits and collision behavior. Provide live PIE preview and save/reload of authored defaults through Details or an appropriate asset editor; preserve authored settings across restart. Reject invalid/nonfinite/inverted limits observably rather than silently fixing saved settings. Do not require C++ edits or hand-edited ini files for tuning.
  • Start with documented adjustable reference defaults: overview pitch -55 degrees and orthographic width 2400 Unreal centimeters; close pitch -15 degrees, distance 350 centimeters and FOV 70 degrees; orbit pitch bounds -80 to -10 degrees, normalized wheel step 0.1, transition duration 0.35 seconds and yaw/pitch sensitivity 0.15 degrees per mouse input unit. Complete remaining focus, follow and collision defaults from the scene proportions, state their units, and expose them in the same UI. These are proposed presentation defaults, not new world-unit or gameplay rules. T02 verifies the actual projection transition before its policy is accepted.
  • Record host CPU/GPU/OS/display, engine/compiler, asset/configuration hashes, input mappings and a proposed reference matrix covering 1280x720, 1920x1080, a non-16:9 window and native high-DPI backing scale where available. Record minimum-window/letterbox policy, independent UI scale controls and proposed CPU/GPU/memory budgets before final measurements; unavailable configurations stay unverified. This scope introduces no canonical camera wire/schema type. Preserve MovementState continuous planar/floor semantics and InputBindingConfiguration/InputBinding meanings without building a production binding editor.
  • Execution clarification 2026-10-22, owner delegated scope judgment: T01 provides live overview/close framing, follow, collision and independent HUD-scale previews. Transition/wheel/orbit values are editable, validated and persisted in that same configuration; their active input behavior and continuity/capture acceptance stay in T02/T03. This avoids duplicating their implementation and evidence gates.

Out of scope

  • Production movement/aim, combat, networking/admission, new gameplay enums/schemas, art production tools, other-platform certification and custom settings menus.

Dependencies

Hard prerequisites: BW-001, BW-003

Acceptance criteria

  1. AC 1

    A fresh run opens the versioned native reference level with an explicitly controlled pawn, default elevated orthographic camera, recognizable floor/target anchors and resettable stationary/axial/diagonal routes. Record the real launch and all settings; no missing-asset or implicit external-Actor dependency remains.

  2. AC 2

    A developer can change every camera fine-tuning parameter using Unreal UI, preview T01 endpoint framing/follow/collision/UI scale live, save a preset/default and recover it after closing/reopening the level/editor. Transition/wheel/orbit settings are validated and persisted for behavior verification in T02/T03. Record the UI path, units and validation behavior. Invalid ranges/nonfinite values fail observably without corrupting the last valid configuration.

  3. AC 3

    The environment/display/input record distinguishes tested configurations from proposed/unavailable ones and records baseline budgets before T06. Baseline Entry map, existing native tests and server behavior remain compatible; reference routes do not establish authoritative gameplay.
