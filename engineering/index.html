Engineering

C++ and Blueprint engineering standard

Implement one authoritative rule once; expose bounded authoring and observation to Blueprint.

Native scope

C++ owns reusable movement/action components, server validation, IDs, transaction routing, authoritative combat integration, replication conditions, lifecycle and cancellation. Blueprint selects approved definitions and composes presentation. The guide proposes APIs; none of the custom types or methods is supplied by the engine.

Blueprint exposure

Use EditDefaultsOnly for immutable authoring inputs, BlueprintReadOnly for views and BlueprintCallable for narrow validated command entry points. Cosmetic BlueprintImplementableEvent hooks may react to committed state; they cannot award currency, skill points or catches. Editable properties do not authorize client mutation.

Lifecycle contract

  1. Create only current-phase types and compile the native project before selecting them as Blueprint parents.
  2. Assign required definitions in the actual consumer. Validate null and unsupported version cases during initialization.
  3. Bind the observer once, then pull the current snapshot. Make teardown remove the same binding and invalidate pending presentation callbacks.
  4. On possession/zone changes, replace the body view without duplicating durable character records. Reject stale generation/lease callbacks.
  5. Keep error codes stable and log request/receipt/revision IDs without tokens or private message contents.

Maintainability

Prefer descriptive names, shallow inheritance and composition for shared gathering/crafting behavior. Five vocations are data and permission policies, not five duplicated resource systems. Avoid a universal manager or global event bus. Do not implement a second cooldown/attribute framework alongside GAS.

Review checklist

  • One authoritative writer per fact; immutable definition distinct from owned instance and view.
  • Server-side permissions and lease fencing at commit, not only at command arrival.
  • Failure leaves no unexplained debit; duplicates return the same committed result.
  • Actual existing consumers assign and invoke the feature; no disconnected shells.
  • Missing art, plugin API assumptions and unrun tests are explicitly recorded.
