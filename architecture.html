Original game, existing project

Briarwake is an original 2D pixel-art fantasy MMORPG being developed from the ground up in Unreal Engine 5.8.3. The existing Briarwake Unreal repository is the development starting point. No previous game implementation, port or conversion is required. Earlier game_docs material is optional historical and engineering reference. Each phase introduces or extends Briarwake’s own systems; planned contracts are not runtime evidence.

Briarwake is the public game name; RPG is the verified physical project and runtime module identifier. Open RPG.uproject and use Source/RPG/RPG.Build.cs, Source/RPG.Target.cs and Source/RPGEditor.Target.cs. Keep Content/Game/, existing classes, targets and configured assets intact. Do not create a second project or require a rename.

Current source baseline: 13 October 2026 read-only project inspection. Read ADR-011; the historical guide is not a prerequisite.

Recommended initial topology

CLIENT
 input / permitted prediction / UI / 2D appearance
          │ authenticated connection
          ▼
DEDICATED ZONE SERVER
 movement / abilities / AI / action permission / relevant replication
          │ validated durable commands + lease epoch
          ▼
ONE PERSISTENCE / DIRECTORY BOUNDARY
 identity / character value / regions / receipts / leases / transfer
          │ transactional writes + outbox
          ▼
VERSIONED STORE + RESTRICTED BACKUPS

Optional shared chat/guild routing remains a responsibility here initially,
not a requirement to deploy another service for every feature.

Scale only after measurement

The 1–30 population is a test target for a zone/realm configuration, not a benchmark result. Start with separate zone processes when individual biome travel needs independence. Add allocation/interest-management sophistication only when actual profiling shows a need.

Critical boundaries

  • Every fact’s writer and viewer
  • Durable mutations and receipts
  • Fenced transfer
  • Optional historical documentation comparison
  • Roadmap corrections
  • Supplied-plugin gap audit
  • Deployment and test plan

Planned game behavior is not runtime evidence. Read sources and limitations.
