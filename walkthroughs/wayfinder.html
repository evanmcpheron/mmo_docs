Fixture and readiness

First integrated checkpoint: Phase 19. Stable fixture identifiers: char-bw-way / discovery.bellroot-trail / threat.road-ambush / zone.elderwood.

discovery.elderwood.willow-cut connects the road camp to the ruined watchtower. Three clues provide a safe-route choice; a direct skirmish route remains available.

All sample quantities and timings are controlled fixtures. Actual authored definitions must match the scenario before running it.

Configure and connect

Open the normal character-selection and Thornmere route. Assign the relevant definitions from DA_GameCatalog and place the station/NPC/site/encounter named by this scenario. Initialize durable records once through the controlled fixture setup; never manufacture rewards in the UI.

Ownership and user journey

AZoneGate validates departures. The zone evaluates proximity, clues and route eligibility; the Wayfinder specializes in investigation but all characters retain a viable discovery route.

CharacterDiscoveryRecord stores personal knowledge. Record_Region stores shared discoveries and unlocked routes with distinct receipts; first-arrival recognition is not a monopoly on progression.

WBP_WorldMap and WBP_Minimap distinguish unexplored, personally discovered and publicly opened locations. Shared map notes are permissioned and redact undiscovered private facts.

Worked execution

  1. Inspect an authored track at the road edge and select the safer clue route or the exposed overlook.
  2. Solve the route clue, complete the skirmish or authorized scouting alternative, and discover the Bellroot trail personally.
  3. Report at the mentor; validate the shared discovery condition and show the authored shortcut when the realm milestone is met.

Command and projection sequence

Player input / UMG
  → owned Controller command (custom project API)
  → authoritative validation: identity, lease, action, range
  → durable boundary: revision + idempotency + domain uniqueness
  → atomic state/receipt commit
  → current snapshot / notification
  → UI observer and cosmetic PaperZD/audio response

Expected successful outcome

Inspect the specific record IDs above and compare before/after balances, revisions and receipt identities. An on-screen success toast is not sufficient evidence.

Rejected command

Reporting without valid clue evidence returns ObjectiveIncomplete; a client map reveal cannot satisfy it.

Concurrent case

Two eligible reporters may receive personal credit, but shared stage transition occurs once.

Reconnect and server restart
