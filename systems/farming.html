Player mechanic and scope

Personal or leased plots have explicit permissions. Crops progress through authored states without dying merely because the owner logged out. Farming supplies expedition cooking rather than becoming a mandatory daily maintenance schedule.

Committed requirement: one-human core progression remains available. Recommended initial choices below are design work, not compiled engine behavior.

Editor and configuration recipe

  1. Assign plot.thornmere.001 to char-bw-hearth in the fixture. Set private harvest permission by default and show it visibly on the interaction panel.
  2. Create DA_Crop_Goldenroot with three authored visual stages and a non-punitive mature state. Growth timing is a tuning value, not a daily-login obligation.
  3. Connect Goldenroot and Reedfin to DA_Recipe_FieldLoaf and the oven service so farm output has an immediate expedition purpose.

Native ownership and Blueprint boundary

All Briarwake class and command names are proposed custom project APIs. They are not installed Blueprint nodes. C++ validates durable/gameplay invariants; Blueprint configures reviewed content and presentation.

AFarmPlot projects the current crop state. The zone validates planting, tending and harvesting permissions; only the durable boundary commits seed debit and harvest grants.

Reject an invalid or expired lease, an unknown content ID, a stale revision, insufficient capacity or permission before mutating state. Return a stable error code and refresh the current projection; do not ask the player to repeat an unknown-outcome transaction with a new request ID.

Wire the actual player flow

  1. Plant requests plot/crop IDs and expected plot/inventory revisions. Validate lease, owner, empty plot, soil compatibility and seed count.
  2. Commit seed debit and planted state together. Derive future growth from the authoritative clock and the saved authored choices.
  3. Tending makes one meaningful recipe/yield tradeoff; repeated clicking cannot become the main XP source.
  4. Harvest validates mature state and current generation, then commits output, mastery and harvested state exactly once.
  5. Rejoin after absence; the crop remains in a valid saved stage with no offline deletion.

Configured route fixture

plot.thornmere.001 starts empty with two Goldenroot seeds. A mature fixture yields two ingredients; growth-duration tests use a controllable realm clock, not waiting days.

Use L_ThornmereVillage and L_ElderwoodRoad as the repeated route. The isolated L_BriarwakePreview exists only to prove imported visuals. Field values below are fixtures, not production balance.

Rejected commands, disconnect and restart

Not owner → PlotPermissionDenied. Duplicate harvest → original receipt/no new yield. Inventory full → preserve mature crop. Invalid migration → quarantine with recovery rather than deleting crops.

Persist the operation receipt in the same transaction as its effects. On a lost response, query or retry the same request identity. A successful receipt returns the original result; a changed payload under that identity is rejected. A UI timeout is not proof of a database rollback.

UI, animation and accessibility

WBP_FarmPlot shows plot ownership, next authored action and accessible progress. Tile overlays select seedling/growing/mature states; loading a mature visual grants nothing.

Bind observers, pull the current snapshot, and unbind on teardown. Preserve controller focus, localized error text and an accessible alternative to timing-only or sound-only cues. A widget’s disappearance is not a gameplay commit.

Art, maturity and stop condition

Seedling, mature plant, soil, water and oven stages are not proven in the character archive. Each requires an environment art reference or a labeled placeholder.

Shared town gardens are optional permissioned content. Expiration/spoilage is not part of the initial food baseline; introducing it requires a separate non-punitive policy.

Stop when the linked fixture cannot be run end-to-end, required source compatibility is unknown, or a command lacks an observable rejection/recovery path. This is an initial implementation contract; exhaustive properties, graphs and every content instance are not yet authored.
