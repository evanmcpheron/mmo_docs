Player mechanic and scope

The server chooses among authored eligible sites rather than inventing arbitrary coordinates. All vocations have basic gathering access. Specialists gain evaluation, route and outcome choices without monopolizing essential raw materials.

Committed requirement: one-human core progression remains available. Recommended initial choices below are design work, not compiled engine behavior.

Editor and configuration recipe

  1. Place eligible site markers away from doors, water exits and required paths. Assign permanent SiteIds; do not generate an ID anew each time a map loads.
  2. In DA_Resource_ThornmereOre set an initial active-site cap and minimum spacing. Validate candidate cells against collision before selecting sites.
  3. Choose an explicit contention policy: the first prototype vein uses an exclusive short claim with expiry; common plants may use bounded per-character quotas. Never mix policies silently.

Native ownership and Blueprint boundary

All Briarwake class and command names are proposed custom project APIs. They are not installed Blueprint nodes. C++ validates durable/gameplay invariants; Blueprint configures reviewed content and presentation.

AResourceSite exposes a replicated state projection and the zone service validates claims. UActionExecutionComponent controls the timed gathering action and cancellation.

Reject an invalid or expired lease, an unknown content ID, a stale revision, insufficient capacity or permission before mutating state. Return a stable error code and refresh the current projection; do not ask the player to repeat an unknown-outcome transaction with a new request ID.

Wire the actual player flow

  1. Request BeginHarvest(SiteId, Generation, ToolInstanceId). Validate range, line of sight, tool, state and current session lease.
  2. Acquire the exclusive claim with expiry and server action ID. A second claimant receives SiteBusy, not a second animation-based entitlement.
  3. On valid completion, check the claim and generation again, then debit wear and grant material/mastery once in the shared transaction.
  4. Apply depleted state and the committed respawn timestamp to the loaded actor. A cosmetic disappearing animation cannot deplete or grant.
  5. After reload/restart, hydrate the same SiteId and generation from durable state. Allocate a new generation only for the authorized respawn.

Rejected commands, disconnect and restart

Missing tool, full inventory, expired claim, movement cancellation and stale generation cause explicit rejection. Once a grant commits, a disconnect cannot refund wear while retaining material.

Persist the operation receipt in the same transaction as its effects. On a lost response, query or retry the same request identity. A successful receipt returns the original result; a changed payload under that identity is rejected. A UI timeout is not proof of a database rollback.

UI, animation and accessibility

The node shows a readable resource type, contested/busy state and depletion. The gathering widget displays progress and errors only.

Bind observers, pull the current snapshot, and unbind on teardown. Preserve controller focus, localized error text and an accessible alternative to timing-only or sound-only cues. A widget’s disappearance is not a gameplay commit.

Art, maturity and stop condition

Mining, woodcutting and action pages are source-reported; ore/tree/plant world sprites remain unverified and likely need a separate environment-content audit.

No unrestricted terrain destruction. Replanting and sustainability operate through authored grove states, not a simulated global ecosystem.

Stop when the linked fixture cannot be run end-to-end, required source compatibility is unknown, or a command lacks an observable rejection/recovery path. This is an initial implementation contract; exhaustive properties, graphs and every content instance are not yet authored.

Neutral materials and faction contribution sources

Server-randomized resource sites retain their existing ownership/generation/claim rules. Structural timber uses DA_Resource_ElderwoodTimber in neutral Willow Cut cells; contested groves are optional. Every faction may use basic gathering and essential material alternatives.

A faction contribution consumes a verified owned source once. Selecting a faction never grants arbitrary resource yields or a second claim on a depleted generation.
