Player mechanic and scope

Exploration rewards interpreting clues, finding safe routes and discovering useful world facts. Personal discoveries remain available to later players even after a shared route has been opened by someone else.

Committed requirement: one-human core progression remains available. Recommended initial choices below are design work, not compiled engine behavior.

Editor and configuration recipe

  1. Connect Thornmere Basin → Elderwood Frontier → Siltfen Reach, with a second branch to Cairnstep Heights → Hollowpeak Depths → Galehaven Coast.
  2. Give every connection an explicit destination ZoneId and safe SpawnId. Validate both outward and return routes before decorating.
  3. Place a track sequence on Elderwood Road that reveals an optional safe path. Non-Wayfinders can learn the route through an NPC investigation contract.

Native ownership and Blueprint boundary

All Briarwake class and command names are proposed custom project APIs. They are not installed Blueprint nodes. C++ validates durable/gameplay invariants; Blueprint configures reviewed content and presentation.

AZoneGate validates departures. The zone evaluates proximity, clues and route eligibility; the Wayfinder specializes in investigation but all characters retain a viable discovery route.

Reject an invalid or expired lease, an unknown content ID, a stale revision, insufficient capacity or permission before mutating state. Return a stable error code and refresh the current projection; do not ask the player to repeat an unknown-outcome transaction with a new request ID.

Wire the actual player flow

  1. Inspect an authored clue or enter an eligible landmark trigger; the server validates state and position.
  2. Advance a personal clue sequence and commit its once-only discovery reward.
  3. When a shared route milestone is met, commit the realm discovery revision separately from each participant’s journal.
  4. Update map/minimap and gate presentation from that revision; later arrivals can still complete their personal clue journey.
  5. At a zone boundary, use the fenced transfer protocol rather than whole-server travel. Preserve personal fog and route state across reconnect.

Rejected commands, disconnect and restart

Unknown destination → RouteUnavailable. Invalid clue sequence → PrerequisiteMissing. Client-forged discovered cells are ignored. Return travel must never depend on an online party member.

Persist the operation receipt in the same transaction as its effects. On a lost response, query or retry the same request identity. A successful receipt returns the original result; a changed payload under that identity is rejected. A UI timeout is not proof of a database rollback.

UI, animation and accessibility

WBP_WorldMap and WBP_Minimap distinguish unexplored, personally discovered and publicly opened locations. Shared map notes are permissioned and redact undiscovered private facts.

Bind observers, pull the current snapshot, and unbind on teardown. Preserve controller focus, localized error text and an accessible alternative to timing-only or sound-only cues. A widget’s disappearance is not a gameplay commit.

Art, maturity and stop condition

All six biome families are original design targets, not existing maps or acquired environment packs. Terrain, interiors, creatures, VFX and UI remain in the art backlog.

No endless procedural TileMap. Ordinary expansion is authored data and content validation, with code changes only for genuinely new mechanics.

Stop when the linked fixture cannot be run end-to-end, required source compatibility is unknown, or a command lacks an observable rejection/recovery path. This is an initial implementation contract; exhaustive properties, graphs and every content instance are not yet authored.
