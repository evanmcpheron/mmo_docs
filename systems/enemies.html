Player mechanic and scope

Enemies patrol authored routes, detect eligible targets, leash to safe encounter bounds and reset under explicit rules. Death is a server state transition. Reward eligibility includes declared healing/support contribution and must not depend on the last hit.

Committed requirement: one-human core progression remains available. Recommended initial choices below are design work, not compiled engine behavior.

Editor and configuration recipe

  1. Author a short patrol and a leash polygon on L_ElderwoodRoad, using the same 2D walkability grid as movement validation.
  2. Assign DA_Encounter_RoadAmbush to a spawn marker and give it one clear wind-up, one avoidable attack and one reset path.
  3. Configure the reward eligibility window and support contribution rules explicitly. Start with personal loot; do not infer party rights from proximity alone.

Native ownership and Blueprint boundary

All Briarwake class and command names are proposed custom project APIs. They are not installed Blueprint nodes. C++ validates durable/gameplay invariants; Blueprint configures reviewed content and presentation.

ABriarwakeEnemy and ABriarwakeAIController execute behavior on the zone server. An encounter coordinator within the zone owns the current EncounterInstanceId and reward-eligible participants.

Reject an invalid or expired lease, an unknown content ID, a stale revision, insufficient capacity or permission before mutating state. Return a stable error code and refresh the current projection; do not ask the player to repeat an unknown-outcome transaction with a new request ID.

Wire the actual player flow

  1. Create a server-owned encounter ID at spawn; route perception decisions through eligible cell and line-of-sight checks.
  2. Engage targets and accumulate bounded participation facts. Damage and support events are attributed to validated character IDs.
  3. On health reaching zero, atomically transition the encounter from Alive to RewardPending; repeated death callbacks see the existing transition.
  4. Commit each eligible character reward under (EncounterInstanceId, CharacterId, RewardVersion). Reconcile pending grants after a lost response.
  5. Present death/loot and schedule authored respawn. A respawn uses a new encounter identity; reopening an old corpse cannot create a new one.

Configured route fixture

encounter.elderwood.road-ambush.01 spawns two briar-struck sentries, with an accessible solo alternative to simultaneous switches. Reward fixture is 25 combat XP and one eligible loot roll.

Rejected commands, disconnect and restart

Leash reset removes temporary combat state but not already committed rewards. Disconnection is not an instant invulnerability exploit; use a short published server-controlled retreat policy with a safe recovery checkpoint.

Persist the operation receipt in the same transaction as its effects. On a lost response, query or retry the same request identity. A successful receipt returns the original result; a changed payload under that identity is rejected. A UI timeout is not proof of a database rollback.

UI, animation and accessibility

Remote enemies replicate position, action/telegraph and health presentation. WBP_Loot shows each character’s authorized results; the corpse is not the inventory owner.

Bind observers, pull the current snapshot, and unbind on teardown. Preserve controller focus, localized error text and an accessible alternative to timing-only or sound-only cues. A widget’s disappearance is not a gameplay commit.

Art, maturity and stop condition

Enemy families, hit, telegraph and death sprites are not proven present. Use labeled development silhouettes only until original licensed art is supplied.

Mechanics variants must be authored; multiplying health is not a substitute for solo-compatible encounter mechanics.

Stop when the linked fixture cannot be run end-to-end, required source compatibility is unknown, or a command lacks an observable rejection/recovery path. This is an initial implementation contract; exhaustive properties, graphs and every content instance are not yet authored.
