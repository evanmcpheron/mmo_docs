Player mechanic and scope

Human cooperation adds tactical variety, convenience and community recognition. Social actions naturally need other humans, but required story, profession mastery, essential recipes and critical region stages do not.

Committed requirement: one-human core progression remains available. Recommended initial choices below are design work, not compiled engine behavior.

Definition, runtime, durable state and view

Editor and configuration recipe

  1. Create local, party and guild channels with explicit recipients. Global chat remains separately rate-limited and permissioned.
  2. Expose invite, leave, block, report and guild-rank actions in controller-accessible menus. Require confirmation for permission-changing operations.
  3. Connect party participation to the existing encounter reward rule. Party membership alone does not authorize remote idle reward farming.

Native ownership and Blueprint boundary

All Briarwake class and command names are proposed custom project APIs. They are not installed Blueprint nodes. C++ validates durable/gameplay invariants; Blueprint configures reviewed content and presentation.

The zone owns local proximity membership; a shared social responsibility inside the same initial service handles durable membership and cross-zone routing. Do not duplicate character identity records.

Reject an invalid or expired lease, an unknown content ID, a stale revision, insufficient capacity or permission before mutating state. Return a stable error code and refresh the current projection; do not ask the player to repeat an unknown-outcome transaction with a new request ID.

Wire the actual player flow

  1. Submit a scoped social command from the authenticated character/session context.
  2. Validate membership, invite state, block rules and current permission revision.
  3. Commit durable membership or moderation changes where applicable; transient chat routes through rate-limited delivery without granting gameplay items.
  4. Publish only to authorized recipients. Reconnect resolves current membership instead of replaying expired invitations.
  5. Revalidate ranks/permissions at the action boundary; an old guild UI cannot spend or edit shared resources after demotion.

Rejected commands, disconnect and restart

Not authorized → PermissionDenied. Blocked invitation → NotAvailable without disclosing unnecessary account details. Flooding is rate-limited and auditable; moderation access is not available to ordinary clients.

Persist the operation receipt in the same transaction as its effects. On a lost response, query or retry the same request identity. A successful receipt returns the original result; a changed payload under that identity is rejected. A UI timeout is not proof of a database rollback.

UI, animation and accessibility

WBP_Social, WBP_Chat and WBP_Party display scoped information. Blocking affects permitted chat/invites; inventory and private journal facts do not leak into presence.

Bind observers, pull the current snapshot, and unbind on teardown. Preserve controller focus, localized error text and an accessible alternative to timing-only or sound-only cues. A widget’s disappearance is not a gameplay commit.

Art, maturity and stop condition

Guild crests, emotes and chat icons need separate approved assets. Text-first UI is a valid development fallback.

PvP, taxation, political elections, conquest, player housing and massive mandatory raids remain deferred optional extensions.

Stop when the linked fixture cannot be run end-to-end, required source compatibility is unknown, or a command lacks an observable rejection/recovery path. This is an initial implementation contract; exhaustive properties, graphs and every content instance are not yet authored.

Opposing allegiances and neutral cooperation

Cross-faction friends, guilds, chat and consenting parties are allowed. Shared-threat/neutral settings use per-character access and reward checks; party membership grants no private faction quest or headquarters access. Existing consent, moderation, trade escrow and anti-spam requirements remain.

Party/guild mechanics are still Phase27; the Phase26 campaign does not require them. Faction rivalry does not create irreversible social partitioning or authorize player damage.
