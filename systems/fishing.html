Player mechanic and scope

Fishing combines site selection, cast placement, bite recognition and a catch decision. The player can use a forgiving accessible mode without letting the client declare a successful catch. Short varied sessions replace compulsory idle waiting.

Committed requirement: one-human core progression remains available. Recommended initial choices below are design work, not compiled engine behavior.

Editor and configuration recipe

  1. Add water.safe.01 with an explicit cast polygon and safe bank cells on L_ThornmereVillage. A painted water tile is not sufficient.
  2. Assign DA_Fish_Reedfin and a bait requirement to the water definition. Set small bounded wait/timing fixtures and expose the accessible mode in settings.
  3. Provide the same cast/cancel/reel actions for keyboard and controller. A text cue must duplicate each sound cue; timing color is not the only signal.

Native ownership and Blueprint boundary

All Briarwake class and command names are proposed custom project APIs. They are not installed Blueprint nodes. C++ validates durable/gameplay invariants; Blueprint configures reviewed content and presentation.

AFishingWater validates cast intersections. UActionExecutionComponent owns the one active CastId, server timing and cancellation state.

Reject an invalid or expired lease, an unknown content ID, a stale revision, insufficient capacity or permission before mutating state. Return a stable error code and refresh the current projection; do not ask the player to repeat an unknown-outcome transaction with a new request ID.

Wire the actual player flow

  1. BeginCast validates character, water polygon, range, equipment and action eligibility; the server allocates CastId.
  2. The server schedules bite state and sends a window to the owning client. The client sends a reaction/reel choice, not a rolled species or catch quantity.
  3. Validate the command against server timing with a declared bounded latency policy and the selected accessibility mode.
  4. Commit one authorized species/quantity and vocation XP under the cast receipt. If capacity is unavailable, keep or reject the pending catch under the published policy; never silently discard it.
  5. Movement, combat, death or zone departure cancels pre-commit casting. Late bite messages cannot revive a cancelled CastId.

Configured route fixture

pool.thornmere.reedbank.01 permits Reedfin; cast fixture requests a 2-second bite cue and 3-second response window. These numbers are accessibility/playtest inputs, not measured pacing.

Use L_ThornmereVillage and L_ElderwoodRoad as the repeated route. The isolated L_BriarwakePreview exists only to prove imported visuals. Field values below are fixtures, not production balance.

Rejected commands, disconnect and restart

No eligible water → InvalidCast. Old bite → CastExpired. Busy character → ActionBusy. InventoryFull must not also debit a consumed catch item or emit vocation XP.

Persist the operation receipt in the same transaction as its effects. On a lost response, query or retry the same request identity. A successful receipt returns the original result; a changed payload under that identity is rejected. A UI timeout is not proof of a database rollback.

UI, animation and accessibility

WBP_Fishing displays visual and audio bite cues, reel choices and remaining timing window. UCharacterAppearanceComponent shows audited rod and p3 poses when available.

Bind observers, pull the current snapshot, and unbind on teardown. Preserve controller focus, localized error text and an accessible alternative to timing-only or sound-only cues. A widget’s disappearance is not a gameplay commit.

Art, maturity and stop condition

p3 fishing and rod layers are reported in the brief only. Bobber, water animation and cast/reel/catch frames require actual archive paths before visual acceptance.

No real-world-time story lock. Seasonal fish needed for mandatory progression receive an authored substitute or predictable in-game window.

Stop when the linked fixture cannot be run end-to-end, required source compatibility is unknown, or a command lacks an observable rejection/recovery path. This is an initial implementation contract; exhaustive properties, graphs and every content instance are not yet authored.

Faction-neutral essential fishing

Fishing remains server-randomized and independent of allegiance. Neither crossing policy nor a hostile optional border removes the neutral Reedbank fishing route, cooking inputs or vocation progress. Existing accessible timing and CastId uniqueness apply unchanged.
