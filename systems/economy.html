Player mechanic and scope

Currency uses signed-range-checked integer smallest units. Basic NPC supplies and commissions exist even with one player online. Secure direct trade adds choice but never becomes a main-story prerequisite.

Committed requirement: one-human core progression remains available. Recommended initial choices below are design work, not compiled engine behavior.

Editor and configuration recipe

  1. Introduce a limited basic-supplies merchant at Phase 13 for Slice B; full stock, bank and trade security become active at Phase 25.
  2. Assign fixed fixture prices and a non-specialist repair/commission option to the Thornmere quartermaster. Protect essential stock from server-wide depletion by using a baseline personal purchase entitlement.
  3. In trade UI separate Offer, Review and Confirm. Show the exact item instance properties and both balances; never auto-confirm after a revision refresh.

Native ownership and Blueprint boundary

All Briarwake class and command names are proposed custom project APIs. They are not installed Blueprint nodes. C++ validates durable/gameplay invariants; Blueprint configures reviewed content and presentation.

ANpcServiceActor validates local service access. The persistence boundary owns balances, stock, escrow, bank transfers and final trade commits.

Reject an invalid or expired lease, an unknown content ID, a stale revision, insufficient capacity or permission before mutating state. Return a stable error code and refresh the current projection; do not ask the player to repeat an unknown-outcome transaction with a new request ID.

Wire the actual player flow

  1. Request a service operation with item IDs, quantity, expected price/stock/offer revision and stable RequestId.
  2. Validate permissions, ownership, bind restrictions, balances, capacity, stock and integer overflow before mutation.
  3. For trade, hold offered assets in escrow and require both parties to confirm the identical immutable offer revision.
  4. Commit both item/currency transfers together, or commit none. A disconnect before commit releases valid escrow through a receipt-backed cancellation.
  5. After unknown outcome, query TradeId/RequestId and display its terminal state. Reconfirming cannot commit a completed trade again.

Rejected commands, disconnect and restart

Negative/overflow amount → InvalidAmount. Stale quote → PriceChanged. Escrowed item cannot be equipped/sold. Full recipient inventory aborts the whole final trade without partial loss.

Persist the operation receipt in the same transaction as its effects. On a lost response, query or retry the same request identity. A successful receipt returns the original result; a changed payload under that identity is rejected. A UI timeout is not proof of a database rollback.

UI, animation and accessibility

WBP_Merchant, WBP_Bank and WBP_Trade show current revisions, all offered items/currency and explicit two-sided confirmation. Any offer change invalidates both confirmations.

Bind observers, pull the current snapshot, and unbind on teardown. Preserve controller focus, localized error text and an accessible alternative to timing-only or sound-only cues. A widget’s disappearance is not a gameplay commit.

Art, maturity and stop condition

Merchant icons and bank/trade UI assets are not included by implication. Use text labels and accessible placeholder icons during implementation.

Auction house and player storefronts are deferred. Taxes, conquest and player political governance are outside the committed scope.

Stop when the linked fixture cannot be run end-to-end, required source compatibility is unknown, or a command lacks an observable rejection/recovery path. This is an initial implementation contract; exhaustive properties, graphs and every content instance are not yet authored.

Faction commerce without essential lockout

NPC offers, trainer access and prices use one server-derived faction decision, revalidated at transaction commit. Restricted commissions and cosmetic rewards may be faction flavored; neutral repair, food, basic trade, essential recipes and vocation resources remain viable. No faction monopolizes mandatory raw materials.

Q5 branch rewards provide equivalent essential advancement and cosmetic-only differentiation. Repeating a quest, donation source, alternate faction character or new request ID cannot bypass per-character source-generation guards; public consultation additionally allows one ballot per account per round.
