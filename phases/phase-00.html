Baseline outcome and why this is first

Briarwake is an original 2D pixel-art fantasy MMORPG being developed from the ground up in Unreal Engine 5.8.3. The existing Briarwake Unreal repository is the development starting point. No previous game implementation, port or conversion is required. Earlier game_docs material is optional historical and engineering reference. Each phase introduces or extends Briarwake’s own systems; planned contracts are not runtime evidence.

Prerequisites and hard blockers

Access to the existing Briarwake checkout and its local engineering instructions is required. No earlier game or game_docs checkout is required.

Installed Unreal 5.8.3, a compatible C++ toolchain, licensed enabled plugins and resolved configured assets are required for actual Editor/build checks, not for reading this guide. Do not create a second project to bypass a missing prerequisite.

Editor and configuration sequence

Obtain or open the existing evanmcpheron/Briarwake repository, not a blank replacement project. Read its AGENTS.md, Docs/GIT_WORKFLOW.md and applicable local engineering guidance. Inspect status and preserve local work. Verify RPG.uproject, Source/RPG/RPG.Build.cs, RPG.Target.cs and RPGEditor.Target.cs; inspect Content/Game/ and configured startup assets. Confirm installed Unreal 5.8.3 using About / Build.version; EngineAssociation 5.8 alone is insufficient. Inspect enabled plugin descriptors, required licenses and the platform C++ toolchain. Verify Paper2D/PaperZD compatibility before Phase 01 imports. Hash and audit licensed art/plugin archives when available; missing art blocks its imports, not the existing-project baseline.

Document observations before changing project settings. There is no new native class or Blueprint parent to select in Phase 00.

Native ownership contract

Briarwake is the public game name; RPG is the verified physical project and runtime module identifier. Open RPG.uproject and use Source/RPG/RPG.Build.cs, Source/RPG.Target.cs and Source/RPGEditor.Target.cs. Keep Content/Game/, existing classes, targets and configured assets intact. Do not create a second project or require a rename. The stable documentation asset ID Briarwake refers to the existing RPG module, not a native class or new module. No gameplay classes are created in Phase 00. Preserve ARPGGameMode and URPGGameInstance; later feature tasks must inspect actual Blueprint parents before choosing integration.

Run the existing-project baseline

On a development machine with verified prerequisites, generate/refresh IDE files for the existing RPG.uproject as needed, build its RPGEditor target and open that project. Check the configured Test_Level and BP_GameInstance/BP_GameMode references, Editor logs and plugin loading without replacing them. Record commit, platform, exact engine/toolchain/plugin versions, command, exit result and log location. If Unreal or a dependency is unavailable, record Not run and the blocker; never infer successful compilation from repository files.

Reject incompatible or invented setup

Stop on a missing descriptor/module/target, unsupported engine/toolchain/plugin version, unresolved content pointer or failed build. Resolve the actual prerequisite; do not create a replacement project, rename RPG identifiers, assume a pending rename merged, or require an earlier game.

Regression and historical evidence

Confirm no game file, configured asset or class was renamed/recreated and that Phase 01 still targets RPG. Baseline source inspection is not Blueprint compile, multiplayer or gameplay acceptance. Preserve previous evidence and add dated results.
