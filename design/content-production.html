Guide / Design

Design

Data-driven content production

Add ordinary content through reviewed definitions and existing systems.

Design contract

On this page

  2. A new quest is an objective graph
  3. A new biome is a checked content bundle
  4. Clock and weather

  6. Definition of content completion

A new item is not a new manager

Create an item definition with a stable ID, reviewed stack/bind/slot/affix rules and an audited appearance key or explicit nonvisual fallback. Register it once. Assign its actual consumers: recipe, loot table, merchant, quest or project. A definition with no use is not implemented content.

A new quest is an objective graph

Choose existing objective types: kill, gather, fish, plant/harvest, craft, deliver, talk, interact, research, scout/map, rescue, defend, dungeon and region contribution. Author prerequisites, localized text and success/rejection/reward rules. The quest evaluator consumes validated receipts; do not add one Blueprint class for each ordinary quest.

A new biome is a checked content bundle

  1. Declare geography, outward and return gates, hub/service set and a complete solo route.
  2. Audit/acquire the actual art and define import/pivot/tile/collision requirements. Missing art blocks visual acceptance but does not justify claiming a nonexistent pack.
  3. Author tile layers, walkability, eligible resource sites, fishing polygons, plots, enemies and NPC services.
  4. Create quest/discovery/project definitions with stable IDs and content versions; register every concrete asset before use.
  5. Run validator checks for references, duplicate IDs, unreachable objectives, invalid cells, unsupported appearance/action combinations and graph cycles.
  6. Test one-human completion, two-client shared-state/travel, crowded contention, restart, content migration and rollback policy before release.

Clock and weather

Recommended initial choice: persist a realm epoch, game-time rate, weather seed/schedule version and authored transitions. Zone servers derive coherent local effects from the same authoritative source. Do not let a client clock or tint authorize a rare catch. Use controlled server-clock fixtures to test transitions, and provide alternate accessible windows for essential objectives.

Do not silently expand scope

A new ordinary recipe, item, NPC service or quest should normally fit existing schemas. A genuinely new mechanic needs a reviewed system/owner/transaction/UI/art/test contract and registry update first. Housing, PvP and freeform simulation are not ordinary data entries in this committed version.

Definition of content completion

A registered page is not enough. The content is assigned, loaded, reachable through the player route, tested for valid and rejected paths, recovered after restart and proven compatible with its actual art. This package supplies the pipeline and initial fixtures, not a finished six-biome content database.

Planned game behavior is not runtime evidence. Read sources and limitations.
