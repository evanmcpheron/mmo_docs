D. CONVENTIONS AND ARCHITECTURE DECISIONS
Canonical definitions live only in this registry. The generated schema bundle and HTML are read-only projections. Existing feature HTML and shipped data remain evidence, not alternate contract editors.
snake_case properties follow existing JSON and ability_command_v2. Existing mixed-case keys such as weapon_DPS are preserved for compatibility. Stable inventory IDs and anchors never change when classification changes.
Required means present; nullable permits explicit null. Optional fields may be absent. No implicit default exists. Empty collections mean a known empty set; null means no current selection or applicability as described per field.
Id is an opaque stable string, with a field-level x-reference naming its content definition or instance contract. Content references do not embed live entities. Entity IDs, account IDs, character IDs, item instance IDs and content IDs occupy different namespaces.
Numbers are finite. CombatAmount is measured in domain units with fixed-point thousandths, with final health rounding at resolution. Seconds are durations; Instant is an absolute authoritative timestamp in RFC 3339 UTC (explicit boundary representation; no existing epoch encoding is changed). WorldPoint includes zone, instance, floor and foot-anchor coordinates in authored tile widths.
Currency is integer minor units. No currency name, exchange rate, cap or new currency is introduced. Fractions are 0..1; fields explicitly named percent use 0..100. Existing formula coefficients retain their documented scale.
Arrays preserve order unless uniqueItems and set semantics are declared. Maps are keyed by the referenced stable ID. Runtime collections with unique entities use keyed maps or unique ID sets. No derived display owns a second mutable copy.
Enum encodings are explicit case-sensitive strings. Previously symbolic members serialize as their documented snake_case IDs; existing serialized labels and operation tokens retain their encodings. Never infer numeric ordinals. Unknown enum values or discriminators are rejected. Breaking changes require a new message discriminator and migration; compatible additions require a new package version and negotiated capability.
Static content is versioned by the package content version. Runtime state belongs to the owning world process; durable economic ownership belongs to the transactional service. Client requests carry intent and expected versions, never authoritative results.
A Fully Defined shape is supported at documentation level, not runtime-ready or balanced. Needs Decision schemas validate only their supported portion and cannot certify an unresolved mechanic. Text invariants require future semantic/runtime validation beyond structural JSON Schema.
Reviewed contracts and changed prototype descriptions ship as content package 2.1.0-design; registry format remains 2. ID namespaces are determined by the referenced contract, not a required text prefix, and IDs never authorize access. Session epochs and sequences must never wrap or be reused; acquire a fresh epoch before exhaustion.
A missing concrete map, art asset, deployed provider or executed gameplay test is future implementation/content work. It does not reopen a completed parameterized schema. All required configuration remains explicit; absent bindings/configuration keep future content disabled.
