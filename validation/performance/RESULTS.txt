PROFILING AND CHANGES
Original slowest tests: unmanaged entry fields 20.138s; feature associations 5.345s;
page review drift 5.307s; malformed ticket lists 4.774s. The passing baseline's
complete durations are in baseline-current-05.log.
cProfile (instrumented timings, not wall-clock benchmarks) identified sample
instance validation (851,972 recursive calls), repeated HTML parsing and repeated
registry checks. See profile-inventory.txt and profile-roadmap.txt.

Sample validation reuses results only inside one process, bounded to two entries.
Keys contain serialized definitions and bindings plus every freshly read bound
source's contents. Cached errors are immutable; callers receive fresh lists.
HTML caches hold immutable metadata keyed by actual source text, bounded to 256
entries. No filesystem timestamp, mutable registry identity or persistent cache
can certify stale content. Regression tests mutate schemas, bindings, catalogs,
same-path records and returned errors. All existing mutation tests remain.
Type checks no longer compute every candidate type eagerly; identity checks no
longer allocate a union for every field. No schema constraint changed.

COVERAGE BEFORE -> AFTER
Roadmap builder --check + roadmap validator + aggregate roadmap call -> one
aggregate roadmap call with the same source/freshness checks and stronger anchor
checks than builder --check. Inventory builder --check + inventory validator +
aggregate inventory call -> one aggregate inventory call using the same registry
validator and expected-output/stale-output comparison. No separate check-only
command regenerates output. Positive regression tests remain independent.
76 Python regressions -> all original tests plus 16 selection/cache regressions
(14 at the initial FULL measurement, two more for allocation/search selection).
All gameplay/allocation checks, links, stable anchors, search destinations, browser
assertions/screenshots and four JS cleanup tests -> retained in FULL. Read-only
aggregate validation additionally rejects stale allocation examples instead of
overwriting them before inspection. Aggregate check-call preservation is verified
in source-equivalence.json. Browser report matches the original passing report.

FULL defaults to comprehensive validation; no Git classification can bypass CI.
FAST always runs aggregate documentation checks and the engine audit, with relevant
regression modules and browser checks. Allocation cases/routes/example freshness
are explicitly deferred only when shipped data inputs are unchanged. Roadmap
changes select roadmap/inventory tests and browser;
contracts/schema outputs select model/reviewed-contract/inventory tests and browser;
standalone shared search/manifest changes union both, while regenerated search
alongside a known source uses its domain tests and inventory navigation tests;
shipped data-only changes omit browser.
Other HTML, CSS, JS, templates, instructions, generators, validators, helpers and
unknown paths fall back to FULL. Scope detection includes branch commits, index,
worktree, untracked files, deletes and both rename paths; unavailable scope or
dependency data also falls back to FULL. Reports explicitly list deferred checks.
