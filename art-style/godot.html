    Version evidence

    The read-only game project at commit 923c52d6959348b42b4fa8744878afd5f3d8c40c declares config/features 4.7 and canvas_items stretch with expand aspect. The installed Godot binary reports 4.7.2.stable.official.ed1daf0bf. The project does not pin a patch version or final viewport dimensions. This chapter uses the official 4.7 documentation; adopting 4.7.2 as the team patch is still a technical decision.

    No gameplay scene or asset was modified or integrated. Editor import, terrain painting, collision, animation and lighting workflows are documented preparation steps requiring a separate runtime review. Existing Unreal art integration pages are historical and superseded for new artwork.

    Texture settings and verification

    Keep PNG as a lossless runtime source and preserve editable Aseprite files separately. In Godot 4.7, filtering is a CanvasItem/project setting rather than the older per-image filter workflow. Set the project default under rendering/textures/canvas_textures/default_texture_filter to Nearest, or use a reviewed CanvasItem texture_filter override. Inspect inherited values on actual Sprite2D and TileMapLayer nodes.

    For ordinary native-resolution sprites, use lossless compression and disable generated mipmaps as the initial recommendation. Mipmaps can help deliberate minification but are not a cure for noninteger scaling; approve them only with the camera policy. Keep alpha, avoid matte edges and examine transparent borders against both light and dark backgrounds. Texture import options are resource-specific; default filter, render size and stretch are project-wide unless overridden.

    Atlas bleeding is addressed by correct regions, no unintended filtering and appropriate padding. TileSetAtlasSource supports use_texture_padding; retain and review it for its generated padding behavior rather than adding unexplained gaps to a zero-spacing atlas. Packed atlases need explicit rectangles and separation. Never apply a lossy compression setting that alters palette edges.

    Pixel-perfect presentation and Camera2D

    Choose logical resolution only after gameplay and UI tests. Use the pixel-scale chapter’s 320×180, 384×216 and 480×270 candidates as comparisons, not approved settings. Godot viewport stretch can render at a fixed logical size; canvas_items stretch renders CanvasItem content at target resolution. The inspected project currently uses canvas_items/expand; this guide does not silently change it to a fixed viewport.

    Use Camera2D for 2D view control. Integer zoom and presentation scaling keep consistent screen sample sizes. Pixel snapping options can affect transforms and vertices, but enabling every snap option without testing can create animation or camera jitter. Compare static camera, moving character, moving camera and camera smoothing separately. A smooth subpixel camera may make sprites shimmer; decide the presentation policy through runtime captures. Letterbox, expand or crop behavior must be documented for supported aspect ratios.

    TileSet and TileMapLayer setup

    1. Create a TileSet resource with tile_size (16,16), then add a TileSetAtlasSource referencing the native atlas PNG.
    2. Set texture_region_size (16,16), margins (0,0) and separation (0,0) for this study. Create only the named occupied regions; leave intentional empty slots unused.
    3. Define alternative tiles for compatible visual variants. Set reviewed TileData probability values if using weighted alternatives; keep terrain geometry and metadata compatible.
    4. Create terrain sets and terrain modes suitable for the chosen kit. Map center and peering bits explicitly. Test all 47 binary patterns, empty boundaries and unsupported multi-material junctions.
    5. Add TileSet physics layers and draw collision polygons only after gameplay review. Navigation layers and polygons require a separate navigation plan; occlusion layers require light testing. Custom data can carry reviewed art/integration metadata, not duplicate authoritative world state.
    6. Configure animated atlas tiles for the water strip using animation columns and frame durations. Confirm the selected cells and full loop in-engine; four adjacent PNG cells do not animate themselves.
    7. Use multiple TileMapLayer nodes for base ground, decoration and foreground as appropriate. Godot 4.7 TileMap is deprecated; use TileMapLayer for new work. Scene tiles through TileSetScenesCollectionSource are useful for actual reusable scene content, not required for every static prop.

    Origins, character nodes and shared timelines

    With a centered 64×64 Sprite2D, the texture’s geometric center is (32,32). To place source contact (32,48) at the parent root, a visual offset of (0,-16) is the starting mapping. Verify it visually with the exported source: do not confuse texture center, node position and collision origin. AnimatedSprite2D supports centered sprites and offset too; record equivalent registration.

    A flattened sprite can use AnimatedSprite2D and SpriteFrames. A layered character can use Sprite2D children and AnimationPlayer tracks, or a project-owned shared frame selector. All equipped layers share action, facing, frame and timeline. Exported Aseprite JSON needs an explicit importer or reviewed manual mapping; Godot does not preserve every Aseprite feature automatically. Retain original offsets if a packed sheet is later approved.

    Technical approval requires engine evidence

    An integrator must verify filter inheritance, alpha, camera motion, aspect ratios, atlas coordinates, terrain painting, origin offsets, alternative tiles, water playback, collision, navigation where used, occlusion and paper-doll synchronization. Record exact Godot version, project commit and scene path for every pass. This edition does not claim those tests passed.

    Artists supply clear source and visual contracts. Gameplay owns collision decisions, interaction logic, world state and networking. Do not introduce a plugin or a new mutable-state owner solely to explain an art export.
