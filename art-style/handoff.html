    New-art naming convention

    Use lower_snake_case names with stable asset identity and explicit qualifiers. Recommended shape: bw_category_region_object_race_equipment_action_facing_variant_rNN. Omit fields that do not apply; do not fill them with arbitrary placeholders. Individual frames add _f000 before .png. The revision belongs in delivery/source history; a stable runtime alias may be retained by the integrator.

    Keep existing purchased and game filenames unchanged. Their creator conventions are not verified in this edition. New original art uses the new convention without renaming assets that could have live references.

    Source and export association

    Recommended delivery folders are source/, export/, preview/ and metadata/. These are asset delivery conventions, not a request to restructure the game. Keep an asset manifest beside the source or in the team catalog. It identifies stable asset ID, source path and hash, source revision, artist, palette ID, export settings, exports, tags, frame durations, origin and approval.

    The original reference catalog records SHA-256 for every PNG and its source. The character study associates its PNG sheet with the actual .aseprite source. Procedural reference sources remain reproducible drawing code; the artist-facing workflow still requires future edits to be saved as native Aseprite sources. Keep provenance if an artist refines a study.

    Assignment form and completed handoff

    The downloadable JSON assignment template includes all mandatory fields. The completed example describes the real character study, with 48 frames, eight directions, 100 ms timing, 64×64 cells and (32,48) registration. Its source is structurally checked; Aseprite application-open and engine tests remain pending. This is an honest completed documentation handoff, not production approval.

    Minimum delivery by family

    FamilyRequired files and evidence
    All assetsEditable .aseprite/.ase, native PNG, palette reference, source attribution, rights information, version and approval record
    Terrain / atlasCell dictionary, full transition list, seam repeat, mixed map, source/export grid settings
    Character / equipmentUntrimmed cells, origin, layer order by facing, frame identity and action compatibility matrix
    AnimationSheet or individual frames, tag ranges, duration metadata, loop/terminal behavior and playback preview
    Living Region statesAligned exports, shared connection points and intentional footprint/collision differences
    UI / iconsNative cell sizes, transparency, all interaction states and light/dark slot preview

    Submission and revision steps

    1. Artist completes the assignment fields and attaches source, export, metadata and previews. Rights questions block publication of third-party pixels.
    2. Run the static asset validator and include its actual report. Review silhouette, density, palette, seams and frame registration.
    3. Request art review. Record specific revisions or a named art-approval decision for the exact revision.
    4. The technical artist imports into the selected Godot version and tests the documented integration criteria. Record remaining failures separately.
    5. Owner grants production approval only after both visual and technical requirements pass. Archive superseded revisions and list affected runtime aliases.
