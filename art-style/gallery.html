    Local visual reference library

    Inspect original study assets, native dimensions, palette relationships and source metadata.

    On this page
    1. Reference status is visible
    2. Source and reconstruction
    3. How to cite a reference

    Reference status is visible

    All essential examples are local. Proposed reference means new artwork awaiting owner review. Technical demonstration means a coordinate, modularity or comparison study. Approved creative direction applies to the owner’s verbal direction, not automatically to these pixels. No new image is marked Approved production reference.

    The viewer supports 1×, 2×, 4× and 8× nearest-neighbor zoom, pixel grid, 16-pixel tile grid and checkerboard. Large images scroll inside their own viewport. Metadata stays available as text. Animation inspection has a dedicated player with local frames.

    Source and reconstruction

    The reference catalog records native dimensions, palette, status, source file, attribution and hashes. The scene-map source lists every placed cell, object and actor. The complete atlas and second village prove reuse. The palette JSON and GPL specify the proposed ramps.

    Some technical previews intentionally contain lighting-derived or incorrect colors. Their metadata classifies that exception. They must not contaminate source palette validation or become approved references through a copied screenshot.

    How to cite a reference

    Name the exact reference ID and revision in an assignment. Include the relevant rule, such as 64×64 untrimmed source contact at (32,48), instead of writing only “match this image.” If a study is replaced, record its successor and owner approval; do not silently change the meaning of a production assignment.

    The rights audit excludes paid sprite sheets. A private artist may consult licensed originals only after checking the applicable license; those pixels do not belong in this public gallery without explicit redistribution authorization.
