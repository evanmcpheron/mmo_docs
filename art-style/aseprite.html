    Installed version and verification boundary

    The installed Aseprite bundle reports 1.3.18.6 in its application metadata. Its executable aborts with exit 134 even for --version and --batch --noinapp --version in this environment. Therefore no command is labeled verified against a running installed Aseprite build. The supplied .aseprite documents are generated to the documented RGBA file structure and checked structurally; application opening, editing and export remain pending.

    Aseprite 1.3 documentation supports tilemap layers and tilesets. Confirm the artist’s installed version before following version-sensitive menus. Aseprite remains the primary authoring application even though these original documentation studies are reproducible from integer drawing recipes.

    Set up the working file

    1. Create a new RGB document with transparent background and exact native dimensions. Save immediately as .aseprite in the source directory.
    2. Set grid width and height to 16, with origin at (0,0). Turn on the grid when checking atlas alignment; toggle it off for silhouette review.
    3. Load the named project palette. Record the palette ID and revision in the asset handoff.
    4. Name visual layers by responsibility. Use body, hair, outfit, cloak_back, headwear, equipment_front, shadow and effects only where needed.
    5. Keep guides and collision_ref hidden and explicitly excluded from exports. Reference layers explain integration but do not define authoritative collision.
    6. Save an incremental revision before changing canvas size, palette, frame order or tags. Preserve the previous approved source until migration is reviewed.

    Frames, onion skin and tags

    Use the timeline to add or duplicate frames. Duplicate registered layers together; avoid copying a garment into a different-size document. Set frame duration explicitly, then use onion skinning to check motion arcs and contact. Tags use action_facing such as walk_s and cast_ne, with inclusive endpoints. Source tags and runtime identifiers are mapped in metadata rather than assumed identical.

    Inspect the first and last frames together for loops. For nonlooping death or impact, record terminal hold behavior. Play each direction at 1× before exporting. A six-frame source is not automatically a 6 fps animation: six 100 ms frames make a 600 ms cycle.

    Tilemap editing and atlas maintenance

    In Aseprite 1.3+, create a tilemap layer with a 16×16 tileset when that editing mode helps reuse. Understand whether edits update a shared tile or create a new tile; test on a duplicate source first. Keep intentional alternative tiles separate and preserve stable atlas IDs.

    An Aseprite editing tilemap is not a Godot TileSet resource. Export a documented PNG atlas and map its cells in Godot separately. Do not claim terrain peering, collisions, navigation or tile IDs transfer automatically. The supplied atlas studies use normal image layers and are not falsely labeled native tilemap documents.

    Export without changing pixel identity

    1. Save the editable source. Hide guide layers and select the intended tag or state.
    2. Use sprite-sheet export with a fixed grid layout at 100% scale. Keep trim, packing, rotation, border and shape padding disabled for shared paper-doll cells.
    3. Export PNG with alpha. Export JSON array metadata including frame rectangles, durations and tags when required.
    4. For individual frames, use a zero-padded action/facing/frame naming pattern. Export related layers with identical cells and frame order.
    5. Reopen the PNG and compare native dimensions, transparent margins, colors, loop duration and source contact. Keep a preview separate from runtime exports.
