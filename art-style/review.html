    Visual QA, readability and approval

    Reject structural problems early and record the evidence behind every approval.

    Approval states

    Use Draft → Ready for review → Revisions requested or Art approved → Technical validation pending → Production approved. Superseded records remain traceable. Art approval accepts appearance; technical approval accepts tested integration. Neither is inferred from a valid PNG or a passing documentation build.

    A proposed reference can remain useful without production approval. A technical demonstration proves a specific construction or coordinate rule; it does not approve its art. An incorrect example must say what fails. Review records name the reviewer, date, asset ID, revision and evidence.

    Sixteen-point review

    Check style compatibility, native density, dimensions, palette, silhouette, detail level, perspective, reusability, tile continuity, animation quality, frame registration, source structure, PNG export, Godot requirements, rights and gameplay readability. The printable checklist supplies explicit checkboxes and space for failure notes.

    Review native-size and enlarged views. Zoom explains clusters, but 1× decides whether a silhouette reads. Compare exports to source hashes and registration. A sheet with correct dimensions can still contain the wrong action or missing diagonal direction.

    Pass and fail comparisons

    The first tree column uses connected clusters; the noisy, enlarged-density and continuous-gradient columns fail specific drawing rules. The registered character grips its weapon; the shifted example does not. Treat a complete terrain family as a set: a beautiful base tile fails if an inside corner is missing.

    Crowded visual scenarios

    The local static scenes cover one exploring character, two actors, a five-actor party, twelve actors near settlement space and thirty around a shared area. They are visual stress inputs rather than runtime measurements. Playable combat still needs engine tests with enemies, UI and real animation.

    For every density, inspect character identity, enemy silhouette, effect overlap, environmental contrast, interaction markers, item visibility, canopy occlusion and action legibility. Log failures with asset IDs and pixel locations. Static actor placement alone cannot pass animation or occlusion behavior.

    Review output

    A review ends with Pass, Revisions requested or a documented test limitation, not an ambiguous aesthetic score. Block approval for unresolved rights, incomplete transition geometry or broken registration. Record minor polish separately so teams can prioritize structural fixes. Preserve screenshots and command results as evidence; never replace a failed check by weakening its rule.
