Prerequisites

Official Paper2D documentation describes enabling the plugin through Edit → Plugins and restarting the Editor. The following is a version-sensitive workflow to check in the actual target installation, not a completed import.

One audited character

  1. Read the creator guide and identify one complete body/outfit/action/facing set. Record exact archive paths, dimensions and frame spacing; do not infer frame size from the filename.
  2. Enable Paper2D, restart and import the selected textures into Content/Game/Art. Open each Texture asset and verify nearest filtering/pixel-art settings, no unwanted mip blur and consistent color handling. Inspect actual option names in the installed Editor.
  3. Extract sprites using the documented grid or transparent regions. Verify the first and last frames manually; automatic extraction can incorrectly split tools or transparent gaps.
  4. Set a consistent pixels-per-unit value and shared foot anchor. Build the four idle and four walk flipbooks using only audited frames and creator timing.
  5. Render each layer on the same animation clock. Test a full cycle with large tools, hat and cloak; a layer cannot select its own independent pose frame.
  6. Open L_BriarwakePreview, switch all four facings, zoom within bounds and compare foot placement. Repeat from a remote client after the network phase.

Tiles and collision

Create a TileSet from an acquired atlas, assign correct tile dimensions/margins and inspect collision shapes per blocked tile. Place ground, obstacle and overhead layers separately. Test a fixed orthographic camera with sprites and tiles aligned to the flat gameplay plane. An invisible collision floor is implementation support, not a 3D visual environment.

Occlusion test

Walk in front of and behind a tree trunk, roof edge, doorway and bridge support. Use ground-contact position for Y sorting; canopy/roof overlays use separate intentional layers. Cosmetic hop lift must not change the contact coordinate used for sort/collision. Test adjacent feet positions for flicker and long tool clipping.

Stop condition

Do not accept visual quality until actual source sheets, pivots, sorting and packaged rendering are checked. Missing jump/swim/weapon actions remain listed in the art backlog.
