Multiplayer

Population scaling: model and measurement

Keep essential work stable; evaluate optional capacity through a frozen activation policy.

Design contract

On this page
  1. Model contract
  2. What the included simulation proves
  3. Required runtime extension
  4. Acceptance boundary

Model contract

The proposed essential target is 12 credited units, independent of online population. Optional reinforcement target is 8 + 2 × ceil(log2(n + 1)) with engaged accounts n clamped to 1–30. Persist n, targets and policy version at activation; subsequent login/logout does not retune that project.

What the included simulation proves

The arithmetic script checks 1/2/5/10/30 values, monotonic optional effort, a fixed essential target and frozen goals under changing population. It does not simulate real players, encounter AI, network load, fun, completion time or a production economy.

Required runtime extension

Exercise alternate solo contribution categories and per-character repeatable maintenance after a shared project is already complete. Measure personal time-to-value and stalls for all five vocations. Test alts, inactive logins, bots, rushed engagement windows and 30 people at the same last objective.

Acceptance boundary

Do not select final balance based only on the arithmetic passing. A game test must establish ingredient availability, accessible encounters, fair contention and understandable remaining effort.
