Purpose and ownership

Owned request route and local widget lifetime; request ownership is not permission to change balances.

Owner: ABriarwakeGameMode admits a verified character-session lease. ABriarwakePlayerController routes owned commands. A newly spawned ABriarwakeCharacter is only the current body.. Lifetime: Current actor/component/widget instance; reconstruct on teardown.

Replication: Explicit per-field public/owner-only projection; see system contract. Persistence: No Actor/UObject pointer in durable storage.

Authored values describe rules; runtime projections and persistent instances remain separate. A view/definition cannot become an additional authoritative writer.

How to create and configure

Prepare the future native type ABriarwakePlayerController using the stated base and required module dependencies. Compile the real project before any Blueprint selects this type. Expose only current-phase properties and validated APIs. This page does not create a header, implementation or compiled class.

Create the three widgets under Content/Game/UI/Frontend. Put the appearance preview, vocation comparison and validation errors in separate panels. Set an explicit controller focus order: name, appearance, vocation, confirm, back.

Lifecycle, failure and recovery

Reject an invalid or expired lease, an unknown content ID, a stale revision, insufficient capacity or permission before mutating state. Return a stable error code and refresh the current projection; do not ask the player to repeat an unknown-outcome transaction with a new request ID.

Persist the operation receipt in the same transaction as its effects. On a lost response, query or retry the same request identity. A successful receipt returns the original result; a changed payload under that identity is rejected. A UI timeout is not proof of a database rollback.

For a definition, do not attach a transaction/RPC to the Data Asset itself: its owning runtime service implements this lifecycle. For presentation, bind once, pull the snapshot and unbind on teardown; ignore stale callbacks.

Concrete wiring and fixture

Account fixture acct-bw-001 has two permitted slots; char-bw-hearth starts at zone.thornmere / spawn.square with VocationId vocation.hearthkeeper. Names and slot counts here are tuning fixtures.

Submit CreateCharacter(RequestId, Name, AppearanceIds, VocationId) from the authenticated account context. The service derives AccountId; it is not trusted from the form.

Acceptance and remaining depth

Create the Hearthkeeper, enter Thornmere, log out, restart the zone and reconnect. One durable character, one starter kit and one active lease must exist.

Race two requests for the same normalized name, then race two logins for the same character. Exactly one name reservation and one current lease win; the losing session cannot spend inventory.
