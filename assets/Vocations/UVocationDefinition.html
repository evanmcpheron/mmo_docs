Purpose and ownership

One active primary vocation, independent from permanent combat class; immutable rules rebuild permissions from that vocation’s retained progression.

Owner: Content author; immutable during play. Lifetime: Loaded content; no player state.

Replication: None for authored definitions/assets. Persistence: Save stable IDs only; not this object.

Authored values describe rules; runtime projections and persistent instances remain separate. A view/definition cannot become an additional authoritative writer.

How to create and configure

Prepare the future native type UVocationDefinition using the stated base and required module dependencies. Compile the real project before any Blueprint selects this type. Expose only current-phase properties and validated APIs. This page does not create a header, implementation or compiled class.

Create the three widgets under Content/Game/UI/Frontend. Keep appearance, faction, combat discipline and vocation selections separate. Focus order: name, appearance, faction, combat discipline, vocation, confirm, back. Explain the permanent faction/class choices before confirmation; UI validation does not replace server validation.

Commands and notifications

No executable command is supplied on this definition/view contract. The owning system chapter specifies the future validated operation and observable result.

Custom project functions and backend endpoints are proposed. Engine creation actions, plugin APIs and these custom commands are not interchangeable. Emit a completed-change notification only after the owning rule/transaction succeeds.

Lifecycle, failure and recovery

Reject an invalid or expired lease, an unknown content ID, a stale revision, insufficient capacity or permission before mutating state. Return a stable error code and refresh the current projection; do not ask the player to repeat an unknown-outcome transaction with a new request ID.

Persist the operation receipt in the same transaction as its effects. On a lost response, query or retry the same request identity. A successful receipt returns the original result; a changed payload under that identity is rejected. A UI timeout is not proof of a database rollback.

For a definition, do not attach a transaction/RPC to the Data Asset itself: its owning runtime service implements this lifecycle. For presentation, bind once, pull the snapshot and unbind on teardown; ignore stale callbacks.

Concrete wiring and fixture

Account fixture acct-bw-001 has two permitted slots; char-bw-hearth uses discipline.vanguard and vocation.hearthkeeper at zone.thornmere / spawn.square. Resolve FactionId from the approved faction fixture; no real faction ID is authored on the audited main baseline. Slot counts and locations remain test values, not a replacement faction starting-region policy.

Submit CreateCharacter(RequestId, Name, AppearanceIds, FactionId, CombatDisciplineId, VocationId) from the authenticated account context. The service derives AccountId; it is not trusted from the form. Include every semantic selection in the existing request digest.

Reconnect from another client after logging out. Display the same permanent faction/class, active vocation, saved vocation histories and appearance without granting another kit or replaying progression rewards.

See Fixture_identity for trainer-switch and migration acceptance.

Race two requests for the same normalized name, then race two logins for the same character. Exactly one name reservation and one current lease win; the losing session cannot spend inventory.

Retained history and active-only permissions

VocationId identifies a stable key in Record_Character.Progression.Vocations. This immutable definition owns no player XP. Validate ContentVersion, InitialXP and LevelThresholds before activation; initial XP must yield Level 1 and the curve cannot depend on combat level.

The character may have many retained history entries but exactly one active VocationId. Apply only its saved eligible abilities/recipes/techniques, retaining inactive learned information. Returning to a trained vocation restores XP/mastery/purchases and never reapplies starter items or earned milestone grants.
