Purpose and ownership

Ironfang Warbands: Orc-like martial clans seek political recognition and ancestral territory. Korra advocates witnessed agreements; aggressive captains favor reprisals. Neither ancestry nor species determines moral worth. Definition registration is active, NOT playable selection. Map, NPC, dialogue, quest and solo/cooked production content remain unauthored/unverified.

Only owner: Validated content author. Immutable retained content version; no character/realm state. No runtime Tick, RPC or mutation delegate belongs on this immutable definition. Blueprint exposes defaults/read-only queries only. Server RPC authorization remains on the existing owned command route.

Create, initialize and configure

After the existing parent schema compiles in the authorized game project, create a Data Asset of UFactionDefinition in Content/Game/Factions, name it DA_Faction_Ironfang. Do not create fake .uasset files in this manual. Assign the exact source record and resolve all required enabled dependencies through UGameCatalog.

Register at Phase 05; activate the defined contract at Phase 05. Registration of Briarbound/Ironfang/Tidebound never enables character selection. Historical definitions are retained for existing characters; setup errors do not create default faction identities.

Callable API, events and authority

Validate definition and resolve through UGameCatalog; no mutation API on this immutable authored content. Accepted actions use the existing quest/transaction boundary described in architecture/faction-contracts.html.

No runtime Tick, RPC or mutation delegate belongs on this immutable definition. Blueprint exposes defaults/read-only queries only. Server RPC authorization remains on the existing owned command route.

Proposed shared operation results are Committed(ReceiptId, revisions), Rejected(ReasonId) or unresolved transport outcome requiring receipt lookup. UDurableStateClient observers receive committed results; content validation reports precise missing ID/path. None of these custom APIs is claimed to exist in Unreal.

Dependencies and consumer assignments

Creation prerequisites: UFactionDefinition

Direct registered reverse users: None in the current creation graph.

Runtime consumers/assignments: DA_GameCatalog faction registration Phase05, Character creation and continuation policy, Quest/NPC assignments only when content ready.

Later assignments are stamped in faction phase recipes. Do not add a future quest/map as an early native creation dependency merely because the catalog eventually references it.

Replication, persistence and migrations

Definitions are not replicated; public views carry approved IDs and content revisions only

Stable IDs/content version only; owner records store mutable values

Retain stable definition IDs/version and preserve historical branch/reward generations. Client views are never a writer. Definitions cannot carry UObject pointers into durable records; actor/service adapters carry IDs and values. Schema3 migration requires explicit missing-faction confirmation or review, never inferred political identity.

Failures, teardown and diagnostics

Unknown/duplicate IDs, invalid ranges, missing enabled references, mismatched versions or unsafe spawn fail validation before activation. Locked future records may reserve non-runtime content references, but must retain neutral recovery references for existing characters. No fake fallback quests are shipped.

At zone/character teardown cancel outstanding local observers by generation; bind before snapshot on rejoin. Log path/ID/version and stable reason; exclude account secrets, raw tickets and unrestricted character history. Storage errors freeze pending value mutations until receipt reconciliation.

One-human, two-client and thirty-client acceptance

One human: create Hearthward, complete all six quests via the noncombat/free contract route, choose either Q5 branch, persist, travel and reconnect. Both branches have equal essential advancement.

Two clients: validate opposed NPC services/neutral cooperation, race duplicate contributions/choices, check one receipt and immutable historical branches. Thirty clients: measure actual server admission/update/transaction behavior only in authorized runtime tests; the SQLite test jobs are not connected clients.

Source tests: tools/tests/test_factions.py; schema validator: tools/validate_factions.py; acceptance cases and known fixture gaps: faction verification.

UI, four-facing art and definition of done

Use localized text keys and a shared four-facing appearance. Faction-specific portraits/outfits and eight-direction sprites are not prerequisites. Scene/tablet/signage alternatives work with text and authored map props; cook/placement/collision must be verified in Unreal.
