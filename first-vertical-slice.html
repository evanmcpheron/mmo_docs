Roadmap

Four vertical-slice acceptance checkpoints

Each checkpoint must work from the normal player flow.

Design contract

On this page

Slice A · after Phase 10

Create or select a valid starting character, enter Thornmere, move with correct facing, transfer to Elderwood while another player stays, attack an enemy, receive combat XP and reconnect. Inventory loot is not claimed before Phase 11. Account/provider, plugin and art integrations must have real evidence.

Slice B · after Phase 19, adjusted

Play Forgekeeper, Hearthkeeper and Wayfinder separately through their complete starter outings: mine/salvage/forge, fish/farm/bake and track/map/report. Early NPC supplies and the small durable project board make the solo route self-sufficient. The source’s Phase 18 checkpoint precedes cartography; ADR-002 corrects that dependency.

Slice C · after Phase 26

All five vocations contribute through different activities. One human can complete the core repair/danger milestone; newcomers see current region state. Run 1/2/5/10/30 contention and parity cases where the actual environment supports them. Arithmetic simulation is not this acceptance test.

Slice D · after Phase 31

Complete the six-region content route, solo/group dungeons, trade/social flows, all major UI and real deployment/recovery tests. Verify packaging, migrations, restore, bad-data/replay and performance. This manual currently supplies initial contracts, not a passing Slice D.

Evidence to retain

For each slice record build/content SHA, source/provider versions, fixture IDs, environment, commands, expected/actual states, screenshots where licensed, failing cases and unrun cases. Do not mark a slice complete from a generated HTML report.

  • Worked system interactions
  • Documentation evidence

Planned game behavior is not runtime evidence. Read sources and limitations.
